# skyaxis — decision 0026：核验信息归一（退役报告详情核验表）与评审节排版（状态条置顶）

> 日期：2026-10-22
> 背景：0025 核验矩阵升级后，用户指出矩阵与报告详情弹窗的核验表重复，「只能留一个」之争。经两轮中立分析（含用户以「实时性」角度反证——该论据推到底反而支持矩阵：矩阵结构上保证最新态，详情表点开旧报告即见过时结论且无推翻标记），用户采纳留矩阵。第二问：排版是否优化、矩阵是否置顶——三向拍板选 **A 摘要条置顶**（状态置顶，整表留底）。

## 一、拍板记录

1. **留矩阵、退役详情表**：矩阵是「验收面当前状态」唯一真源（跨报告最新聚合＋空洞＋覆盖 chips＋完成口径摘要），详情表是同屏第三份拷贝（0023 输出契约规定报告正文第二节就是完整核验节，弹窗本就全文渲染正文）。
2. **排版 A 档**：节顶加状态条（完成/未完成 Tag＋已处置 n/m · 空洞 k＋核验四段计数），报告区与动作按钮不动，矩阵整表留底——状态一眼见、长矩阵不压首屏（矩阵行将带证据 meta 行变高，整表置顶代价更大）。

## 二、实现要点

- **状态条**：criteria 在场时渲染于节顶；Tag 复用 matrixDone/Undone（与底表头双在场）；计数 `review.stripChecks` 四段全列（满足/不满足/无法核验/未核验——未核验也是状态，诚实计数）。完成 Tag 语义零改动（完成口径不动）。
- **矩阵行证据 meta 行**：最新核验的 evidence 直接可读（详情表退役后证据不落空；报告正文仍有全文）。
- **详情表退役**：ReportDetailModal 回到「正文＋复制＋篡改警示」；`review.checksTitle` 键随之退役（-1 键），`review.stripChecks` 新增（+1），净零。
- **标题正名**：`review.matrixTitle`「PRD 覆盖矩阵」→「验收核验矩阵」（en：Acceptance verification matrix）——名实相符 0025 后的主列语义。

## 三、不动清单

完成口径与摘要行语义（仅位置/复用）；coveredBy 投影；报告卡与核验计数 Tag；裁决区；导入/生成按钮位置；报告正文渲染与复制；VerdictFormModal 证据只读面（checkEvidence 键仍用）；空洞操作臂（仍留待另立项）。

## 四、验收门

1. 节顶状态条：完成 Tag＋已处置/空洞＋核验四段计数，先于报告区出现；完成态翻转正确。
2. 矩阵行：三值 Tag＋证据 meta 行（最新核验）。
3. 报告详情弹窗：无核验表，正文/复制/篡改警示照旧。
4. 回归：标题新名、双 Tag 并存、tsc＋全量绿。
