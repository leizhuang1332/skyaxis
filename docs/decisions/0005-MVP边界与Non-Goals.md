## 背景

按 CLAUDE.md 第 4.4 节阶段切换条件第 3 条，**MVP 范围与 Non-Goals 必须经用户确认**。

MVP 范围（做什么）已由 ADR 0003 锁定 6 个场景 + ADR 0004 锁定核心画像 A。但**边界（不做什么）**此前散落在多个 ADR 与对话中，本 ADR 集中锁定全部 Non-Goals。

Non-Goals 由两个维度构成：

1. **场景反向清单**（来自 ADR 0003 暂缓项 + ADR 0004 反向画像）
2. **运行环境 / 商业模式边界**（本轮用户决策）

## 后果

### 正面

- **范围极其清晰**：MVP 只服务画像 A、只做 6 个场景、只本地、只开源免费——没有任何模糊地带。
- **护城河起点强化**：纯本地 + 单端 + 开源，与 DSH 内置多 session 列表的差异化进一步加大。
- **DSH 生态友好**：MIT 与 DSH 宿主完全一致，避免社区抵触。

### 负面 / 风险

1. **画像 A 群体规模有限 + 商业模式受限**：画像 A 是小细分市场，MIT 免费又限制了变现路径。
   - **风险**：MVP 完成后如何扩展？扩展方向是什么？
   - **缓解**：MVP 验证后再讨论扩展路径（云同步、增值服务、企业版等），避免立项阶段过度承诺商业模式。
2. **纯本地 + 单端可能成为扩展瓶颈**：用户后期想用手机 / 平板看 session 状态，需要重新设计。
   - **缓解**：从一开始就把数据层抽象出来（虽然 MVP 只本地实现），为未来云同步留口子。
3. **MIT 免费意味着 skyaxis 必须靠"足够好用"取胜**：没有付费用户承担亏损缓冲。
   - **缓解**：MVP 阶段聚焦"让画像 A 离不开 skyaxis"——这是开源个人开发者工具的成功路径（参考 Raycast 免费版、tmux、fzf 等）。

## 备选项（已考虑，未选）

| 维度 | 备选 | 未选原因 |
| --- | --- | --- |
| 运行环境 | 本地优先 + 可选云备份 | MVP 阶段复杂度上升，与"薄壳"定位冲突。 |
| 运行环境 | 本地优先 + 自动云同步 | MVP 阶段最重，需架构层抽象。 |
| 分发 | 开源核心 + 增值服务 | MVP 阶段会引入"开源 / 闭源边界"问题。 |
| 分发 | 闭源免费 | DSH 是 MIT，闭源插件可能不被接受。 |
| 分发 | 暂不决定 | MVP 之后再决定会推迟社区互动。 |
