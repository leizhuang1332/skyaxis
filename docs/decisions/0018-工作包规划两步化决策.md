> 状态：**已拍板**——D1-D8 均用户 2026-10-20 全采推荐档。延续 [决策 0007](0007-分析报告工作区交付决策-点目录通道与单写者纪律.md)（文件=契约面）、[决策 0013](0013-拆分结果文件通道与探索规划两步化决策.md)（两步化+单文件交付+采纳门族）与 [决策 0006](0006-AI工作台治理决策-产物独立文件存储与分级级联清理.md) P2（四权）三条既定路线。

## 背景

S3 的「待计划/计划已批准」状态链结构性空转（research 0018 §1 五证据）：dev 任务书无约束段投递即写码、`plans[]` 唯一写入通道是人手 textarea（0006 权责表设计的「AI 起草计划」通道从未实现）、「批准计划」沦为自批自稿、0016 两轮实机验收记录在案的用户行为=跳过直投。本轮补齐：新增「工作包规划任务书」（只读探索+写 WP 计划文件）→ 收取为 `plans[]` 草稿 → 人批准（硬门②语义零变化，从此批的是 AI 提议）→ 再生成开发任务书（嵌已批准计划）投递。决定性论证：业界敢让 todo 无门，前提是 todo 不进账本；skyaxis 的 `plans[]` 是账本治理对象（版本链+硬门②+contentHash），给它配「AI 起草→人批准」是对齐 0006 原设计（权责表「起草计划：AI ✓」行），且 0016 刀〇侦察证实 dev 会话本就自制 todo/write——本设计只是把会话内不可见的自制计划提升为可审可批可版本化的账本对象。

## D1 两会话（已拍板，全采推荐档）

WP 两步化=**两会话**：规划会话（purpose=`wp-plan`，只读探索+单写者写计划文件，完即死）→ 人批准 → 开发会话（purpose=`dev`）新起。理由：投递=0017 直启、会话中途暂停求批准物理上不可能（0011 同款物理限制）；规划/执行上下文隔离是官方设计（Claude Code showClearContextOnPlanAccept 同型）；已批准计划全文嵌入 dev 任务书即规划探索的蒸馏物，重建成本被抵消。**不做一会话两产物**（0011 §5 红线同款——中间门蒸发，伪两步）。

## D2 计划文件通道（已拍板，全采推荐档）

`.skyaxis/wps/<workPackageId>/plan.md`——工作区家族第五目录（requirements/analysis/planning/split 之后；`declares/<rid>/<wpId>-*.md` 已开 WP 子目录先例，命名不撞需求级 `.skyaxis/planning/`）。AI 单写者，一次成文覆盖写；无工作区 ⇒ 通道 unarmed（人工 textarea 保留为诚实回退——与 split 无工作区回退同口径）。路径单源 `workbench-shared/protocol.ts`（`WP_PLAN_DIR`/`wpPlanRelPath`，isWorkPackageId 守卫），host join 在 artifact-path.ts 双层防御。

## D3 收取→账本写入（已拍板，全采推荐档）

watcher（view 层，analysis/split watcher 家族复制精简版——0013「复制不抽」先例）→ seed 端点：读文件 sha256 幂等锚 → `plans[]` **追加新版本 v=max+1**（AI 每次投递=全新会话完整重写，版本链记演进史；contentHash 入 PlanEntry）→ `planned→plan-draft` 与首条目**同一账本 save 原子落账**（writePlan 路径同款）。**两语义并陈**：人工 textarea 维持尾草稿覆盖写（tail-draft 锁零改动）；AI seed 追加后，原未批准尾草稿自然降为「归档」（versionTag 已有该标签），approvePlan 的 last-unapproved 守卫天然兼容。**收取门**：`!running` + WP 非 dropped（0016 修订 #93 口径——收取是信息收集，不受生命周期限制；返工期 re-plan 合法）。**四权**：AI 写入的是未批准草稿行，approvePlan 仍只走用户按钮（0005 细化纪律同源：AI 永远递交草稿而非批准）。

## D4 dev 任务书门=状态驱动分层（已拍板，全采推荐档）

**非硬门**（P3「阶段是指示器不是闸门」+ 业界「小任务跳过规划」模式）：`待计划`（planned/plan-draft）态的主动作=「生成工作包规划任务书」——看板卡动作区按状态分层（0016 P1b 状态驱动先例：built 卡带验收按钮的同款手法）、WP 详情、inbox 条目三面一致；「生成工作包任务书」（dev）入口保留但**无已批准计划时带 ack 确认**（「本包尚无已批准计划，直接投递开发任务书？」——0013 采纳 ack 形制，警示不阻断）；`计划已批准` 态主动作=「生成开发任务书」。跳过路径显式化：走 ack 而非隐藏。

## D5 边界纪律（红线，无分叉）

WP 规划**不改边界、不增删 covers、不改依赖**——这些是拆分批准的契约（硬门① 锁定）；细粒度任务分解必须在边界内。发现边界本身有问题（缺关键依赖/边界错切）⇒ 停下来向用户报告/走发现通道/S2 重拆分，不许静默扩界。此纪律明文写入 wp-plan 任务书约束段。

## D6 人工通道保留（已拍板，全采推荐档）

textarea/writePlan 零语义改动（尾草稿覆盖）；**人机共作同版本**：AI seed v3 后人工微调=覆盖 v3 同 version 重哈希（现有 planWriteFlow 语义自然支持，零新代码）。批准权不受作者身份影响。

## D7 wp-plan 任务书形态（已拍板，全采推荐档）

**九节家族形**（目标/需求快照/输入/参考知识/约束/工作流/输出——plan purpose 0012 同构，WP 粒度版）：头行判别前缀 `# skyaxis 工作包规划任务书 WP<n> · <需求标题>`（家族对齐，人读辨识）；输入段=必读基线文档行（三态，0009 D2 口径）+ S2 已采纳规划文档行（三态，0013 D2 口径）+ repos/ 行 + WP 边界/依赖摘要嵌入式；约束段=严格只读唯一例外写计划文件 + 不裁决 + D5 边界纪律明文；输出段=固定节结构计划文件（**任务分解**（步骤×文件级改动面）/ **测试安排** / **风险与开放问题**），**纯文件交付无 declare 回传**（plan purpose 先例——收取靠文件哈希，不靠声明块）；**无 revision 戳**（0010 D4 AI 语境口径——快照头注「生成时快照」诚实锚）。

## D8 规划会话不绑 sessions[]（已拍板，全采推荐档；**0022 修订「不绑」子口径**）

wp-plan 投递**不进 `sessions[]` 绑定**（那是 analysis/dev/review 执行器绑定，purpose 枚举不动）；溯源走**收取回执的来源会话行**（analysis 提议 `proposal.sourcePrefix` 先例）。账本面：`WorkbenchWorkPackage` 增可选字段 `planSeed?: { session?: {sessionId, boundAt}, contentHash?, seededAt? }`（字段演进纪律：optional）——投递回传时记 `session` 指针（非绑定，仅溯源+幂等锚成员）；watcher 收取时读盘哈希 ≠ `planSeed.contentHash` 才 seed（**哈希主锚**，sessionId 为辅——人工微调改写 PlanEntry.contentHash 后 watcher 重跑不误 seed 的关键：幂等锚独立于版本链，记在 planSeed 上）。

> **0022 修订（用户 2026-10-21 拍板「投递即绑关联会话」）**：推翻本条「不进 `sessions[]` 绑定 / purpose 枚举不动」子口径——`sessions[]` 用途枚举扩 `'wp-plan'`（标签「规划」），wp-plan 投递成功（sent）在指针之外**经普通 `bindSession` 动作**追加绑定行，关联会话面与开发路径同形（投递即可见可点入）。指针语义（同会话 unchanged / 异会话替换+清戳重臂）与收取 watcher 布防**零改动**——`recordWpPlanSession` 动作仍不触 `sessions[]`。`planSeed`/哈希主锚/幂等语义全部原样。详见 [决策 0022](0022-规划会话投递即绑决策.md)。

## 连带记档

- **SowPurpose 扩 `'wp-plan'`**：sow.ts 的 purpose union（SowContext/sow-modal/view 状态）+ 入口穿线（work-package-dialog 计划节/board 卡分层动作/inbox 条目）。命名与 stage key、artifact kind 'plan'（WP 实施计划，0013 D3 已审议的撞名格局）三分立——'wp-plan' 语义自洽。
- **protocol.ts**：`WP_PLAN_DIR='.skyaxis/wps'` + `wpPlanRelPath(wpId)`（isWorkPackageId 守卫，requirementDocRelPath 同款）；`WorkbenchWorkPackage.planSeed?` 可选字段（zod 双侧镜像）；`PlanEntry` 零改动（contentHash 已有）。新 action：`seedWpPlan`（host，watcher 调）。
- **endpoint**：`wpPlanSeedFlow`（读工作区文件→哈希→幂等门→plans[] 追加 v=max+1+contentHash+`planSeed` 盖章→`planned→plan-draft` 同 save 原子→返回新 record+seed 回执）；文件>2 MiB ⇒ 413（analysis 口径）；GET artifacts 面增 kind=`wp-plan-doc`（收取前文件先行可读，404 诚实缺失——0013 GET 面口径）。
- **watcher**：view 层为 wp-plan 复制精简版（无 shell repair、无内容寻址——文件单通道）；收取门 `!running`+非 dropped。
- **投递回传**：onDelivered 增 wp-plan 臂（`controller.recordWpPlanSession(rid, wpId, sessionId)`——只写 planSeed.session，不触 sessions[]/SESSION_PURPOSE_VALUES）；0017 直启+投递即绑机器对新 purpose 直接可用。
- **词典**：`sow.wpPlanButton` + `wpPlan.*`（来源会话行/收取 miss 理由族：文件缺失/无声明块不适用——纯文件通道只有缺失/超限/哈希不变三态）+ dev 直投 ack 键 + 分层主动作键；zh/en 双版+register 类型同步。
- **UI**：WP 详情计划节版本链回显零结构改动（AI 草稿走现有 MarkdownText+版本 chip）；来源会话行小字（proposal.sourcePrefix 形制）；dev SOW 生成前的 ack 弹窗（无已批准计划时）。
- **测试基线 1152**（0017 收口后），预计净增 30-45（实施期落定）；README 双版同步。

## 不动清单

四权模型（批准拆分/批准计划/验收/阶段推进永不在 AI 手里）；硬门①②语义（approvePlan 尾草稿锁/批准盖章/重基线路径原样）；dev/review 五段形态与 revision 戳逐字冻结；declare 家族**不加 plan 键**（纯文件交付）；`sessions[]` 三 purpose 绑定与 SESSION_PURPOSE_VALUES；投递通道；`advanceStage` 零改动；S5 导入面零改动；**失效链不接**（0006 §7.6 挂账继续挂——上游基线/规划变更不自动标 WP 计划 stale）；不自动化「批准后自动投递开发任务书」（两次投递两个人握动作）。
