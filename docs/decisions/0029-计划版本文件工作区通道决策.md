## 一、通道规则（同 0028）

| 场景 | 写入位置 |
| --- | --- |
| 绑定工作区 | `<workspace>/.skyaxis/plans/<rid>/<wpId>-v<version>.md`（`workspacePlanPath`，reviews/<rid>/ 同形） |
| 未绑定 | `<workbenchRoot>/<rid>/plans/<wpId>-v<n>.md`（legacy） |

收敛臂通道感知（armed 修复/顺迁工作区正本、legacy 永不删除；unarmed 修 legacy）；详情 planFileExists 双 stat；scan missing 双查；级联零改动；协议/客户端/UI/词典零改动。

## 二、plans 独有险与对策（本档核心记档）

**草稿可合法重写**（reviews 正文按 id 不可变、通道切换后两副本恒同内容，故 0028 读面「先到先得」安全；plans 的尾草稿同版本号反复重写换锚）——通道切换（armed 写过→unbound 重写，或反向）会在另一通道遗留**陈旧副本**，其内容与账本 contentHash 不符。若读面沿用先到先得，陈旧副本会以「篡改」姿态压过真身正文。

**对策：读哈希优先**——计划读面双路径读取后按「sha256===账本 contentHash 命中者优先」选定；双方皆不命中（真篡改/真漂移）才以当前通道副本出面并如实报 contentTampered。

## 三、实现面

artifact-path.ts +`workspacePlanPath`＋模板注 v2 增补；endpoint `planBodyLocations`＋写臂（新版本/草稿重写/收敛三处）＋读臂哈希优先＋存在行双 stat；orphan-scan plans missing 双查（resolver 与 reviews 共用一次解析）。

测试 +4：armed 草稿落工作区（插件库零文件）＋GET 读回＋exists／收敛顺迁（草稿态 v1 同文本重导→同版本、工作区副本、legacy 保留）／**读哈希优先两态**（陈旧工作区副本在场仍读出真身不误报篡改；双方皆不命中才报篡改）／scan 双查。实现中修一钉：收敛臂只认未批准尾草稿（已批准版本同内容重导按既有语义走新版本号），测试种子改草稿态。

## 四、不动清单
