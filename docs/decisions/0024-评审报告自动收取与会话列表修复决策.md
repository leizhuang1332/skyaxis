# skyaxis — decision 0024：评审报告自动收取（投递即绑＋双 watcher）与会话列表修复

> 日期：2026-10-22
> 背景：0023 评审任务书方法论轮实机验收三问题——① 评审报告不自动落盘；② 不自动回显到页面；③ 导入报告的选择会话下拉不可滚动（目标会话选不到）。根因取证（file:line 见会话记录）：①② 同一根因链——评审投递不绑会话（view.tsx onDelivered review 落 undefined 臂）＋四条收取通道唯独评审报告零 watcher（dev=register 级 dev-watcher、analysis/split/wp-plan=view 级收取 watcher）；回显不是独立缺口（controller.importReview 本就 patch slot＋重拉），自动收取发生则落盘（reviews/\<id\>.md）与回显自动跟随。③ ReviewImportModal 用原生 select，弹层由宿主 webview 渲染、超可视高度不滚——项目自有先例（SessionPicker 自定义滚动列表）早弃原生 select。
> 拍板：用户 2026-10-22 三问三答——D1 需求级槽＋投递即绑（推荐档）／D2 register 级＋view 兜底（推荐档）／D3 **连带报告下拉同修**（超出默认钉名范围一档，用户点名连带）。

## 一·修订

- **修订#1（2026-10-22，用户验收追加）**：导入报告的抓取候选**放开为工作区全体会话**，不再限定绑定会话——抓取是纯读，任何会话的日志都可能携带报告（含用户手动开、未经工作台投递的会话）；空壳会话（从未运行）过滤；`reviewSession` 绑定仅用于**置顶**（自动收取源=人工修复路径首选），WP 绑定不再特殊。词条改义：`review.sessionLabel`「从会话抓取」、`review.noBoundSessions` 退役 → `review.noSessions`（空态=工作区零可抓取会话）。declare 导入弹窗的绑定候选语义不在本轮（未点名，钉名纪律）。
- **修订#2（2026-10-22，用户验收追加）**：修订#1 的「工作区全体」实为**全机器全体**——sessions 面的宿主列表 RPC 不分工作区（`SessionSummary.blank` 文档自证："Filtering stays with the consumer: the store carries every row"，过滤责任在消费方），弹窗因此列出其他项目的会话。候选**再收窄到本需求工作区**：按会话行 `cwd` 对 `requirement.workspacePath` 比较（复用 delivery.ts `sameHostPath`——Win11 大小写/分隔符/尾斜杠折叠先例，导出共用）；无 `cwd` 的行放行（宿主列表行恒带 cwd——冷行无 cwd 直接不入列表、create 恒写 cwd，undefined 只会是 create 回声占位竞态，刚投递的会话不该闪没）；空壳过滤、置顶语义、修订#1 的「手动开自由会话可抓」全部不动（作用域内保留）。WorkbenchSessionSummary/register 窄化面连带 +`cwd?`；词典零改动（`review.noSessions`「当前工作区没有可抓取的会话」文案本就按工作区口径书写，修复后名实相符）；`reviewSession` 绑定不豁免——置顶行也须通过 cwd 匹配，跨工作区绑定是台账异常不该暗中重开全机器列表。测试：候选测试改写（外工作区缺席负钉 + '/WS/' 折叠命中钉 + 无 cwd 占位行在场钉）+ 全外来会话走 noSessions 空态新用例。

## 二、连带口径

1. **不设 sent 门（有意与 dev/wp-plan 口径不同）**：v2 降级尾巴落在同一 id，用户手发后 idle 边沿照样布防收取；shell 绑定零害——评审是读路径（reviewFetch miss 只是咨询位不落盘），dev 设门防的是「从 shell 播种」的写路径危害，无此险。
2. **autoImportReview 安全面纪律**：从不 banner、从不 busy-toggle（dev-watcher「健康时不可见」纪律）；回显=写入成功且 slot 在场时 open() 重拉，**绝不伪造 slot**（detached 纪律，seedDevDeclareDetached 的 store-peek 形）；写走既有 writeReview 幂等锚——重复零写、删行不复活（0023 已钉），双引擎（register+view）竞争由 revision 门串行化，409 输家静默等下次边沿。
3. **抓取候选连带**：ReviewImportModal 候选=reviewSession 绑定居首＋WP 绑定（dev/wp-plan）随后——自动收取失败时的人工修复路径首选自动收取源。
4. **watcher 无标题寻址 pass**：dev 的 title-pass 是补绑定前历史的修复件；评审从第一天生效投递即绑，不需要。无启动首扫（dev 同形：首次翻转绕过节流窗补收；投递→报告完成必然产生 idle 边沿）。
5. **attempted 一次性语义**：miss（no-review-block——报告未产出/块未闭合）也占 attempted，只有绑定会话的 running 边沿重臂（续话轮语义）；重启后 attempted 清零重试，幂等锚吸收。
6. **存储 schema 第五处登记位**（0023 连带11 教训前置执行）：WorkbenchRecordSchema 登记 reviewSession（sessionId/boundAt/anchor≤512）——endpoint 测试钉 load 往返在案。
7. **auto-import 不带 title**：报告卡标题回退日期（既有形制）；带 title 的收敛键差异留给手动导入通道。

## 三、不动清单

手动导入/粘贴通道与导入弹窗结构；`# skyaxis-review` 解析/播种/幂等锚（0023 全套）；评审完成口径；sessions[] purpose 'review' 手动绑语义（P2 存量，与需求级槽并存互不影响）；其余三 watcher（analysis/split/dev/wp-plan）；裁决表单 disposition 下拉（≤4 选项无滚动问题，未点名）；词典零新增（pickerList 复用既有样式，sessionPlaceholder 转提示行）；其余六种任务书用途；declare 收取链。

## 四、验收门（实机脚本）

1. **投递绑定**：投递评审任务书（v3 或降级手发均可）→ 该会话自动成为评审收取源。
2. **自动落盘＋回显**：评审会话产出带 `# skyaxis-review` 块的报告、运行结束 → 打开中的需求评审节自动出现报告卡（含核验行/发现行），reviews/\<id\>.md 落盘；未打开的需求在下次打开/翻转后可见。
3. **下拉修复**：导入报告弹窗会话列表可滚动、长列表可达目标会话；裁决表单多报告切换正常。
4. **回归**：手动导入/粘贴照旧；dev/analysis/split/wp-plan 收取零变化；tsc 干净＋全量绿。
