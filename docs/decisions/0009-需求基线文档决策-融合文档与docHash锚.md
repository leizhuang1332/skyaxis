# 决策 0009：需求基线文档（融合文档与 docHash 锚）

> 状态：**已拍板**——四拍板全量落定；**修订 [决策 0008](0008-需求理解定稿决策-软门收口与理解基线.md) D2**（「不落盘理解文档」→「落盘但单写者+哈希锚定」），0008 其余裁决不变。

## 背景

0007 把定稿实现为账本状态后，用户明确最终形态：定稿是**一份融合文档**——原始 PRD 去冗余 + 采纳发现补细节 + 采纳标准给判定 + 澄清消歧 + 背景补充，标准结构、适合 AI 阅读、下游以其为唯一需求真源。业界（research 0010）同构：Spec Kit 的 clarify 答案回写 spec 正文、Kiro 的 requirements.md 即基线、BMAD「下游不得自行解释 PRD」。

## D1 落点与单写者：`.skyaxis/requirements/<rid>.md`（已拍板）

决策 0007 同族的点目录通道（`.skyaxis/analysis/` 姊妹）：整理会话是**唯一写者**（任务书规定绝对路径 + 覆盖写）；插件不写用户区（0005 边界不破）；gitignore 由用户自定。布局 frozen at v1，变更先修订本 ADR。**与 0005 细化①的关系沿用 0007 D2 论证**：会话写的交付面、账本状态不依赖文件存活（换绑最坏 = 可见孤儿）。

## D2 修订 0008-D2：落盘，但账本与文档的真源分治（已拍板）

0008-D2 否决落盘的两条理由在新形态下消解：**双真源** → 分治——账本仍是**裁决状态**真源（采纳了什么/答了什么/何时定稿），文档是**需求表达**真源（下游唯一读它）；文档的权威性不来自自身而来自**定稿盖章锚定的哈希**。**单写者** → 整理会话单写；手改文档 = 对照 `understandBaseline.docHash` 的篡改披露（警告不阻断，细化④同款）；改内容走重新整理（同入口重跑）→ 重新定稿换锚。

摘要导出（0007）**保留**：基线文档 = 需求表达（下游读），摘要 = 裁决审计（评审会看处置与未答）——两种读者两种产物。

## D3 验收标准 C 编号与账本 criteria 对齐（已拍板）

文档验收标准节的 C1..N **与账本 criteria 一一对应、不增不删不改号**——增删先走账本（采纳提议/手动录入）再重新整理。这是业界没有的「文档↔账本结构对齐」：覆盖矩阵、stale、拆分任务书全部可机读，文档与账本永不各说各话。FR 编号是文档内生的（PRD 素材重组产生），纪律为发布后不回收不重排（重新整理保持稳定，账本 id 不回收惯例同源）。

## D4 approveUnderstand 专属 flow 与软门延续（已拍板）

**docHash 是 IO 读盘派生值不能走 wire** ⇒ approveUnderstand 从主 union 拆为 endpoint 专属 flow（seedAnalysis 先例：zod parse 后分流，读 `.skyaxis/requirements/<rid>.md` 算 sha256 作派生参数进纯函数 `approveUnderstandWith`；wire 面零改动，隐式建账语义保留）。**软门延续**：unarmed/缺失 ⇒ 无锚但定稿照旧成立（ack Modal 开时现探文件并披露「尚无基线文档——不阻断」；docHash 定稿时才铸造，不能查 baseline——首定稿必空的诚实性要点）；too-large ⇒ 413（文件在但读不了，锚「无文档」是伪证——直披不回落先例）。

## 连带记档

- **拆分任务书基线行**：定稿带锚 ⇒ 输入段首行「必读 `.skyaxis/requirements/<rid>.md`——本拆分的唯一需求真源（验收标准以账本为准，其余表达以文档为权威；与快照冲突时列出不要自行取舍）」——**依据账本不依据盘**（未定稿/无锚 ⇒ 无行）。
- **stale 第五臂 'requirementDoc'**：`record.understandBaseline?.docHash !== baseline.requirementDocHash` ⇒ 成因「需求基线文档已变更」。语义锚定**定稿态**（纯函数零读盘）：重定稿换锚才报；重整理未重定稿/手改文档由 S1 卡片 contentTampered 读时对照兜。[确认仍有效] 全臂重锚（含本臂）。
- **整理任务书（purpose 'consolidate'，第五个 purpose）**：九节骨架第三次复用；快照嵌**全量裁决素材**（发现 detail+方案全文、澄清全文——整理需要完整原料，与 analysis/split 行级摘要分工）；输入段全部 PRD 必读（无重点章节指针）；输出节给十节文档结构模板；约束含 Spec Kit 回填铁律与 BMAD 索引收口。**无 declare 提议回传**——文档本身即产物，投递是普通投递（不绑 watcher）。
- **S1 第三张文件卡片**：requirement-doc-section（report-section 同构复制，每文档面一份的仓库先例；三面已齐，第四面出现再抽通用组件）。
