# 工作包与评审任务书 PRD 勾选退役决策（[输入] 块与基线必读行）

> 日期：2026-10-16
> 背景：用户要求「生成工作包任务书」modal 同其他任务书一样去掉左侧 PRD 目录勾选（例：生成规划任务书、生成拆分任务书）；范围拍板时用户选定**工作包 + 评审一起**收口。
> 定位：纯客户端轮——宿主零改动、wire 协议零改动、store 零改动；六个 purpose 全部无 PRD 勾选面。

## D1 文档面替代物：[输入] 块 + 基线必读行（不是 prds 清单、不是全量嵌入）

去掉勾选组后，dev/review 会话的需求依据必须仍有载体。三个候选：

| 候选 | 判定 | 理由 |
|---|---|---|
| 全章节自动嵌入（勾选默认全选） | 弃 | 体量无上限、与「同规划/拆分一样处理」的用户意图相反——0008/0009 的既定方向就是路径引用替代嵌入（业界共识：spec-kit "REQUIRED: Read \<path\>"） |
| prds/ 目录全文档必读清单（analysis/consolidate 形） | 弃 | dev/review 处于定稿下游：0009 D2 已立「基线文档是唯一需求真源」教义，拆分/规划两轮相继只引基线文档、不引 prds/；开发/评审再回头引原始 PRD 是教义倒退 |
| **账本决定的基线必读行 + repos 行（split/plan 形）** | **采纳** | 与用户所举两例（规划/拆分）逐字同构：`- 必读 .skyaxis/requirements/<rid>.md——需求基线文档，{目的}的唯一需求真源（…）`，三态诚实行（anchored / 定稿无锚 / 未定稿）由账本判定不探盘 |

引用-嵌入的分界线沿用 P1 物理位置规则不动：**工作区内的文件（基线文档、克隆仓库）路径引用；台账本数据（需求快照、WP 边界/覆盖标准、已批准计划、criteria 清单）照旧嵌入**。五段形态保留（[需求]/[输入]/[工作包]/[知识注入]/[输出约定] + revision 戳），只是 [PRD 节选] 段退役、新增 [输入] 段。

## D2 评审同轮收编（用户拍板）与评审的保留嵌入面

改完工作包后，评审会是唯一还带章节勾选的任务书——用户选定一起收口，六个 purpose 全部无 PRD 勾选面，一次到位。

review 的**审计对照面不动**：[需求] 段的 criteria 清单照旧逐条嵌入（账本数据，P1），输出约定的 `# skyaxis-review` findings 块逐字不动——本轮只动「需求原文怎么给」（嵌入→路径引用），不动「裁决数据怎么给」（账本嵌入）与「回传契约怎么定」（declare/findings 骨架冻结）。

## D3 退役清单与诚实降级

**退役（六处）**：

1. 左侧 PRD 勾选组 UI（文档 select + 章节 checkbox + 组内加载/空/失败提示）——`sow.prd*` 5 词典键 × 五点登记三处（interface/zh+en/LocaleNamespaceMap+哨兵）整体删除；
2. `fetchPrdText` prop 与文档正文链（焦点文档加载/切换/失效守卫）——无任何 purpose 消费；
3. `SowContext.prdSections`/`prdDocumentName` 与 `prdBlock()`（[PRD 节选] 组装）；
4. `splitPrdSections()` + `PrdSection` 导出（唯一生产消费者是 ②，随之退役）；
5. dev/review 的 PRD 列表拉取——开面 effect 的无 PRD 面臂从 `split || plan` 扩为「非 analysis/consolidate」；
6. 对应测试锚（多文档 select 切换用例、dev 组内提示用例、splitPrdSections 单测 3 例）。

**保留**：analysis/consolidate 照拉 PRD 列表（他们是必读清单行的唯一消费者）；knowledge 勾选组与 dev「工作包范围」勾选组（边界+计划/依赖摘要）不动——它们勾的是账本数据不是文件。

**诚实降级（无新状态机）**：dev/review 输入段的三态诚实行与 split/plan 逐字同构（定稿带锚⇒必读行；定稿无锚/未定稿⇒诚实行）；工作区未绑定⇒「无可引用的文档与仓库，{目的}只能基于需求描述」——dev 在无工作区需求上仍可生成任务书（五段形态从未要求绑定工作区，不因本轮收紧）。

## D4 措辞分目的：noun 表参数化

`analysisInputBlock` 泛化为 `inputBlock(ctx, header)`：头字符串参数化（九节 `## 输入（…）` / 五段 `[输入]（…)`，阅读纪律括注逐字同款）；两个 Partial noun 表驱动基线行（`本拆分`/`本次规划`/**`本工作包`**/`本次评审`）与诚实行（`本次拆分`/`本次规划`/**`本次开发`**/`本次评审`）。dev 用「本工作包」——该任务书服务单个工作包，必读行的受益者是它；repos 行与结尾「路径不存在或不可读」指令全 purpose 复用（dev/review 走「向用户报告」臂）。

## D5 范围与不动项

- **dev 已批准计划正文照嵌不动**：计划文件存宿主工件目录（工作区外，decisions/0005），会话无法路径引用——与基线文档（工作区内）的处置不同是位置规则的自然结果，不是不一致。
- **revision 戳保留**（0009 D4 口径：dev/review 五段路径专属）——本轮未动戳语义。
- **declare 骨架逐字不动**：dev 的 `workPackage:`/claims/artifacts 与 review 的 findings 块是回传契约（回传轮/回传锚冻结），任务书精简不碰契约面。
- view.tsx/board-section/review-section 零改动（开 modal 的按钮与 purpose 流转原样）；fetchPlanText（dev 计划链）原样。
