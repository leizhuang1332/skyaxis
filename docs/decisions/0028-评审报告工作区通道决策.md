# skyaxis — decision 0028：评审报告改道工作区通道（双通道分流＋双路径读＋顺迁）

> 日期：2026-10-22
> 背景：用户要求评审报告的落盘位置改到 `<工作区>/.skyaxis/` 下，与其他阶段（①需求理解 ②探索规划 ③执行实施）的产出文档同族——用户项目树内可见。经源码影响面分析（写入/收敛/读/存在行/孤儿扫描/级联/协议七消费面）后两问拍板。
> 拍板：用户 2026-10-22 两问两答——**D1-A 双通道分流**（绑定工作区→工作区路径；未绑定→维持插件库老路径，能力零缩水）／**D2-A 读双路径＋写时顺迁**（存量零迁移照常读；armed 重导同内容时顺手复制工作区，legacy 永不删除）。

## 一、通道规则（D1-A）

| 场景 | 写入位置 |
| --- | --- |
| 绑定工作区 | `<workspace>/.skyaxis/reviews/<rid>/<reviewId>.md`（`workspaceReviewPath`，declares/<rid>/ 每需求一目录先例；文件名保持宿主铸 id——机读一致、幂等锚稳定） |
| 未绑定/无 resolver | `<workbenchRoot>/<rid>/reviews/<reviewId>.md`（legacy `reviewDocPath`，即 0005 v1 原路径） |

## 二、定位与迁移语义（D2-A）

- **读/存在性**：双路径——工作区优先、legacy 兜底，contentHash 判篡改以实际命中文件为准；**读路径零写**（GET never creates 纪律不破——迁移只走写臂）。
- **收敛（同内容同题重导/自动收取重放）**：armed ⇒ 工作区副本为正本，缺失/过期即修复，legacy-only 存量在此顺迁出工作区副本（legacy 副本永不删除——合法副本，扫描豁免）；unarmed ⇒ legacy 仍为唯一家（反向复制保 unarmed 自洽）。
- **孤儿扫描**：missing 判定改「两处皆无」；孤儿面维持插件库域（工作区文件是用户域——家族通例不扫）；legacy 路径上 id 在账本的文件永远合法。
- **级联删除（D6）**：零改动——插件库 `<rid>/` 整目录进 .trash（legacy 副本随之）；工作区文件本就不随需求删除（与 analysis/baseline/declares 家族一致）。

## 三、实现面

- artifact-path.ts：+`workspaceReviewPath`（uuid/reviewId 域守卫复用），布局模板注升 v2（0005 冻结条款按其自身规定先修 ADR 修订表）。
- endpoint.ts：闭包 helper `reviewBodyLocations`（workspace?/legacy 双位）；新报告写当前通道；收敛臂通道感知修复＋顺迁；读面与详情 existsSync 双路径；scan 接线传入 resolver。
- orphan-scan.ts：可选第三参 resolver，review missing 双查。
- **协议/客户端/UI/词典零改动**——路径从不跨线（0005 细化②），0024 自动收取与手动导入同路无感。
- 测试 +5（armed 落盘+插件库零文件+读回+exists／unarmed legacy 钉／收敛顺迁〔同 id、工作区副本出现、legacy 保留〕／读双路径且 GET 零写／scan 双查）。

## 四、不动清单

plans 版本文件（仍插件库——同为台账伴随文件未点名，另立项）；其余五个工作区通道（analysis/requirements/planning/split/wps/declares）；删除报告留孤儿文件语义；幂等锚/收取链/review-watcher；0005 其余条款（级联/对象化/短文本语义）。

## 五、验收门

1. 绑定工作区的需求导入/自动收取评审报告 → `<workspace>/.skyaxis/reviews/<需求ID>/<报告ID>.md` 落盘，项目树可见。
2. 未绑定工作区需求照常导入（老路径，行为不变）。
3. 旧报告（插件库正文）详情照常打开（双路径读，不迁移不报缺失）；重导同内容后工作区出现副本。
4. 对账扫描：仅工作区正文的报告不报 missing；两处皆无才报。
