## 二、连带口径（拍板的自然推论，随轮记档）

1. **修订戳退役（review 专属）**：九块族纪律＝AI 语境诚实锚在快照头「生成时快照」措辞，不带修订戳（0009 三用途先例、0010 D4 wp-plan 先例）。review 随族；**dev 保留修订戳不变**（五块原形不动）。
2. **[需求] 块 review 臂退役**：`requirementBlock` 的 criteria 追加臂随五块 review 路径一并消失（criteria 进新快照节）；dev 的 [需求] 块字节不变。
3. **[输入]/知识头随族**：review 的输入节头从 `[输入]` 变 `## 输入`（analysisInputBlock 既有参数化，行内容不变）；知识节头从 `[知识注入]` 变 `## 参考知识（工作台注入，已审定）`。
4. **outputBlock 的 review 臂退役**：五块 outputBlock 回到 dev/plain 两形；review 输出约定进自己的九块输出节（散文三节模板＋yaml 骨架＋完成自检）。
5. **criteriaChecks 播种过滤**：解析层纯文本校验（ref 非空≤64、result 闭枚举、evidence≤2000 可缺席）；宿主播种时以 `record.criteria` 的 id 集为宇宙过滤未知 ref（账本不收无锚核验行）——过滤在 endpoint 层非 parse 层（parse 不识账本）。
6. **skip 原因闭枚举扩位**：`ReviewSkipReason` 增 `bad-check-shape`/`bad-check-result`/`check-over-cap`（host 分类＋测试钉，不跨线成行——落法 A 既有纪律）；findings 的 detail 超 2000 复用 `over-cap`（截断是静默数据编辑，跳过是诚实拒绝——nextReleaseItemId 教训）。
7. **detail 的全行替换**：`SaveReviewVerdictRequest.verdict` 增可选 `detail`（≤2000）——裁决表单只读展示、保存时原样回传，编辑 proposed 行不丢证据；播种行 detail 由宿主铸入，表单不提供编辑（AI 证据不是用户输入面）。
8. **响应面**：review 写入响应增 `seededChecks` 计数（导入弹窗状态行连带展示）；幂等收敛分支同样不重播核验行（重导入不复活已删行的既有纪律推广到 checks）。
9. **`criteriaChecks` 字段可选**（field-evolution 纪律）：0023 前的报告无此字段，UI 渲染缺席即不显示。
10. **报告抓取候选/完成口径零改动**：核验行是信息面，不建新裁决环、不动「发现全处置＋无空洞＋空集守卫」完成口径——核验结论喂给用户的 accept/fail 裁决（既有闭环），不自己成为裁决对象。
11. **（实施中实证）存储侧 zod schema 是第五处登记位**：`ReviewVerdictSchema`/`ReviewReportEntrySchema`（types.ts）不登新键时，load 时的 schema 解析按 zod strip 模式**静默剥掉** detail/criteriaChecks——保存→读取往返丢字段（endpoint 测试当场抓获）。连带登记：存储 schema（types.ts）＋守卫（protocol.ts isReview*）＋输入 schema（ReviewVerdictInputSchema）三面同键。
12. **（实施中修正）ref 超长的 skip 归类**：解析层初版把 ref 超 64 误归 bad-check-shape，按闭枚举语义修正为 `check-over-cap`（测试钉住）。

## 三、不动清单

`# skyaxis-review` 标记与 fence 纪律（column-0/闭围栏/last-wins）；proposed 三态与宿主专属播种纪律（saveReviewVerdict 输入 verdict 两值不变）；幂等锚（contentHash＋title 收敛、修复落盘、不重播种）；评审完成口径；报告抓取候选集（绑定会话）；verdict 表单两值单选；报告正文文件通道（reviews/<id>.md，账本只存引用＋哈希）；dev/analysis/split/consolidate/plan/wp-plan 六种任务书用途；投递/绑定面（评审会话投递不绑不变）；评审节入口与导入弹窗结构；dev-watcher/declare 收取链。

## 四、验收门

实机验收脚本（待实施完成后走）：
1. 生成面：评审节生成任务书——九节在场、快照含验收标准与 commits 锚、六维判据在场、yaml 骨架含 criteriaChecks 与 detail、无修订戳、dev 任务书回归不变。
2. 回传面：粘贴带 criteriaChecks＋detail 的报告导入——核验计数与状态行、报告详情核验表、播种行带证据。
3. 裁决面：打开 proposed 行——证据只读在场、保存后 detail 存活。
4. 回归面：旧形报告（无 checks/detail）导入渲染如常；幂等重导入不复活；tsc 干净＋全量测试绿。
