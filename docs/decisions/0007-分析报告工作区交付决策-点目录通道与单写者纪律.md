# 决策 0007：分析报告工作区交付（点目录通道与单写者纪律）

> 日期：2026-10-14
> 依据：[决策 0005](0005-AI工作台治理决策-产物独立文件存储与分级级联清理.md)（D4 细化①否决工作区邻接的三死因）+ 里程碑 0006 回传轮五次诊断记档（会话自由文本提取的故障族）+ [research 0008](../research/0008-分析任务书业界调研与重设计.md) 分析任务书九节骨架 + 用户 2026-10-13/14 三项拍板（文件形态 / 目录名 / 答案不回写）
> 状态：**已拍板**——用户 2026-10-13 ①同意 md+内嵌机器块；②目录名定为 `.skyaxis/analysis/`；③答案进账本不回写文件。

## 背景与问题

回传轮把分析报告的收取建在「从会话日志提取 declare 围栏」上，五次实机诊断（裸尾兜底 / 零写 advisory 链 / 未闭合围栏改尾体提取 / attempt 流 text-chunks / 壳会话锚寻址）全部在修同一类故障：**会话自由文本不是契约面**——有流式截断、有模板混入、有壳会话错绑、有事件形态分叉。且报告正文（F1 发现 / A1 标准 / 待澄清三节）从未落过任何存储，只停留对话中。

用户裁决换轨：**在分析任务书里规定 AI 把报告写入工作区指定文件，插件读文件渲染与收取**。文件是契约面：一次写全量、一次读、一次 zod/parse 校验，会话提取的整类故障连根消除。

## D1 交付通道：工作区报告文件（已拍板）

**选择**：单 `.md` 文件 = 报告正文（人读）+ 结尾内嵌 ` ```yaml # skyaxis-declare ` 机器块（机读）。任务书输出节给**绝对路径**；会话每轮**全量覆盖写**；插件收取以文件为主通道、会话链降为兜底（无工作区需求与存量投递）。

**为何不是整文件 JSON/YAML**：长中文 prose 塞 JSON 字符串需 `\n` 转义（AI 手写头号 syntax-error 来源，一个引号错整文件报废）；整文件 YAML 缩进陷阱多、人读体验差。md 内嵌机器块让正文零转义、机器块解析器（declare-parse）原样复用、评审报告（reviews/ 整份 md + 内嵌 marker 块）与 ADR 0005 细化⑤「独立成文落文件」的语义判据同构。

## D2 落点：`<workspacePath>/.skyaxis/analysis/<requirementId>.md`（已拍板；与 ADR 0005 细化①的关系）

**选择**：点前缀目录（工具自有状态约定，同 `.vscode/` 惯例）+ uuid 文件名（确定性——AI 照任务书写，零创造空间；多需求共用一个工作区不撞名）。**git 不自动改 ignore**——分析报告是值得进版本库的需求资产还是本地草稿由用户自定，文档说明即可；v1 覆盖写无历史（git 提交为历史出口）。

**与 0005 细化①「否决工作区邻接」的区分（本 ADR 的核心论证）**：0005 否决的是**插件写的、账本持引用的资产**放工作区，三死因——no-workspace 400 卡死写入、换绑后引用全量悬空、research §6.3 反对产物混入用户区。本文件的写作者是 **AI 会话本身**，其可达域就是工作区 cwd——这是通道约束不是偏好；且**账本状态（提议行/裁决/答案/幂等锚）不依赖文件存活**：

| 0005 三死因 | 本方案 |
| --- | --- |
| no-workspace 写入卡死 | 无工作区 ⇒ 通道 unarmed，降级会话交付（诚实缺席，非 400） |
| 换绑后引用悬空 | 种子内容已落账本；换绑最坏 = 文件成**可见孤儿**（面板缺失态披露），非数据丢失 |
| 混入用户区 | 点前缀命名空间隔离；且这是用户明确要的可读交付物（拍板②）——报告在用户自己的工作区里可读是特性 |

**布局模板 v1 冻结**（0005 同款纪律）：`.skyaxis/analysis/<requirementId>.md` 约定变更视为破坏性迁移，须先修订本 ADR。路径约定单源在 `workbench-shared/protocol.ts` 的 `analysisReportRelPath()`（浏览器渲染任务书文本用，正斜杠 display 形态）；host join 在 `artifact-path.ts` 的 `analysisReportPath()`（node:path + uuid 双层防御）。

## D3 单写者纪律：文件作者是 AI 会话，用户状态在账本（已拍板）

**选择**：报告文件只有 **AI 一个写者**（每轮全量覆盖）；用户的采纳/不采/驳回/**待澄清答案**全部是账本状态（`WorkbenchRecord.analysis`），**永不回写文件**。

**为何否决「答案写回文件」**：① 两写者必打架——用户答 Q1 → 插件注入文件 → 重新分析 → AI 重写整文件 → 答案被覆盖或半保留出四不像；② 往 md 内嵌围栏块做手术式注入，正是本轮要逃掉的「从自由文本抠结构」换地重现；③ 裁决先例本如此——采纳/不采从回传轮起就只存账本；④ 幂等锚保持干净（contentHash 只覆盖 AI 自著内容，混合作者需合并语义）。

**答案的下游**：重新分析时任务书「需求快照」块把已答 Q&A 嵌入（快照嵌待裁决提议的既有先例）——新会话从任务书读到答案，不碰旧文件。**已答行跨批替换保留**（AI 提议整批换，答案不是提议——用户自著状态权威，与「已删行不复活」同理）；忽略（dismiss）是手动出口。

## 连带记档

- **收取阶梯**（endpoint seedAnalysisFlow）：`resolveWorkspacePath?` 服务（requirements.yaml 容错读 join，缺席 ⇒ 通道 unarmed）→ 文件读（2MiB 帽）→ 命中以**整份文件磁盘字节 sha256** 作幂等锚；缺失回落会话链；双 miss 披露 file 原因（headline 交换，会话扫描指纹仍附）；too-large / 无围栏直披不回落（文件在但坏，回落会静默偏源）。
- **死锁消解**：收取门改 `!running && (fileChannel || !blank)`——文件通道在则 blank 壳不再关门（回传轮五次诊断③的挂账留案收口）；running 双通道都关门（不 mid-run 播种）。
- **报告正文读面**：artifacts 路由 query 扩 `kind=analysis-report`，不要求工作台记录存在（种子未落也先读）；`contentTampered` 对照 seed 锚（细化④警告不阻断）；S1 面板直达路径披露行（0005 产物导出承诺口径）。
- **壳会话锚修复链降级**：file 命中不再依赖会话寻址；锚修复/标题前缀改绑存活于会话兜底分支与 review 用途。
- **待澄清数据面**：`clarifications` 第三提议组（optional 字段演进，旧账本零迁移）；`answerAnalysisClarification` / `dismissAnalysisClarification` 在 split 锁外（findings 族同款——门冻结清单×coverage 契约，不管分析问答）。
- **spike 义务**：会话写域覆盖工作区绝对路径须实机实证（验收第 1 步）；dev 用途已在 repos/ 写代码为先验支撑，但投递会话 cwd 不保证是工作区根——被沙箱拦截则改相对形态指令（预留裁决）。
