# ADR 0007：长期规划与里程碑 — 从立项到 MVP 的阶段划分

| 字段 | 值 |
| --- | --- |
| **状态** | 接受 |
| **日期** | 2026-09-19 |
| **记录人** | Claude（基于用户决策） |

---

## 背景

按 CLAUDE.md 第 4.4 节阶段切换条件第 5 条 + 第 5 节议题 8，**长期规划与里程碑**是立项阶段必填项，落地在 `docs/milestones/roadmap.md`。

MVP 6 个场景（ADR 0003）+ 6 个核心对象（ADR 0006）共同决定了"宽范围 MVP"。为缓解此风险（ADR 0003 / 0006 均标注过），MVP 内部需要分**子阶段**。

CLAUDE.md 第 2.1 节硬性约束："**不排期、不估时、不绑死时间，只划阶段**"。

---

## 决策

### 总体阶段划分

skyaxis 的长期规划分为 **3 个大阶段**：

| 阶段 | 名称 | 状态 |
| --- | --- | --- |
| **阶段 1** | 立项验证 | ✅ 已完成（ADR 0001-0006） |
| **阶段 2** | MVP 实现 | ⏳ 待启动（分为 v0.1 / v0.2 / v0.3 三个子阶段） |
| **阶段 3** | MVP 后迭代 | 📋 占位（待 MVP 完成时启动新 ADR 锁定具体内容） |

### 阶段 1：立项验证（已完成）

- **目标**：把"做什么 / 不做什么 / 为谁做"说清楚，形成立项阶段产出物。
- **已完成内容**：6 个 ADR（[ADR 0001](0001-形态-dsh插件.md) ~ [ADR 0006](0006-业务对象清单.md)）+ 5 个权威文档（[vision/positioning.md](../vision/positioning.md)、[users/personas.md](../users/personas.md)、[scope/mvp-boundary.md](../scope/mvp-boundary.md)、[domain/entities.md](../domain/entities.md)、[decisions/](../decisions/)）。
- **通过条件**：✅ 满足（ADR 0007 落地即视为进入阶段 2 准备阶段）。

### 阶段 2：MVP 实现（待启动）

MVP 内部按"对象群"分 3 个子阶段。

#### v0.1：核心可视化（Session + Task）

| 维度 | 内容 |
| --- | --- |
| **目标** | 交付"单 session 内的进度可视化"核心能力。 |
| **能力范围 — 场景** | **A**（单 session 内进度可视化）必交付；**B**（跨 session 产出聚合）+ **C**（多 session 总览）**基础部分**（Session 视图层）。 |
| **能力范围 — 对象** | Session（元数据视图）+ Task（任务步骤）。 |
| **依赖前置** | DSH 插件 demo 跑通，验证 trajectory 事件流可达。 |
| **通过条件** | Session 视图层可用 · Task 自动抽取可用 · 单 session 内至少一种进度可视化（任务树 / 时间线 / 进度条）· 关键决策有 ADR。 |

#### v0.2：依赖关系（TaskDependency + SessionDependency）

| 维度 | 内容 |
| --- | --- |
| **目标** | 交付"session 内 task DAG + session 间依赖"两个增强能力。 |
| **能力范围 — 场景** | **D1**（session 内 task DAG）+ **D2**（session 间输入 / 输出依赖）必交付；**B + C** 增强部分（依赖 SessionDependency 的多 session 视图）。 |
| **能力范围 — 对象** | TaskDependency + SessionDependency。 |
| **依赖前置** | v0.1 全部场景可用；**假设验证**：DSH 原生支持 task DAG 事件（D1）；DSH 原生支持 session 间通信（D2）。 |
| **通过条件** | Task DAG 可视化可用 · Session 间依赖图可视化可用 · 关键决策有 ADR。 |

#### v0.3：归档检索（Decision + Snippet）

| 维度 | 内容 |
| --- | --- |
| **目标** | 交付"session 内决策 / 代码片段的归档检索"能力。 |
| **能力范围 — 场景** | **D**（session 决策 / 代码片段归档与检索）必交付；**B + C** 进一步增强（以 Decision / Snippet 为锚点）。 |
| **能力范围 — 对象** | Decision + Snippet。 |
| **范围限定** | 仅"只读归档 + 全文搜索"，**不含**语义级智能检索（已 Non-Goal，[ADR 0005](0005-MVP边界与Non-Goals.md)）。 |
| **依赖前置** | v0.2 全部场景可用；DSH trajectory 暴露决策 / 代码片段标记能力（待验证）。 |
| **通过条件** | 用户可主动标记 Decision / Snippet · 跨 session 全文搜索可用 · **MVP 完整 6 个场景全部可用** · 关键决策有 ADR。 |

### 阶段 3：MVP 后迭代（占位）

| 维度 | 内容 |
| --- | --- |
| **目标** | 根据 MVP 验证结果决定下一阶段方向。 |
| **能力范围** | 占位。**不在本 ADR 锁定具体内容**，避免立项阶段过度承诺。 |
| **候选方向**（仅作参考，不锁定） | 反例 3（B 画像）适配 · 云同步 / 多端 · 商业模式探索（开源 + 增值服务）· 学习者画像适配 · D3 / D4 重新评估。 |
| **依赖前置** | v0.3 完成后，启动阶段 3 时需**新开 ADR** 锁定具体内容。 |

## 后果

### 正面

- **"宽范围 MVP 风险"得到缓解**：每个子阶段都能独立交付"可用"能力，避免"什么都做一点、什么都不精"。
- **阶段切换条件清晰**：每个子阶段都有"通过条件"作为阶段切换的门。
- **依赖前置显式化**：DSH 原生能力的假设在每个子阶段都被标注，避免后期返工。

### 负面 / 风险

1. **B / C 两个场景在子阶段间跨越**：v0.1 提供基础视图层，v0.2 / v0.3 增强。
   - **风险**：v0.1 交付时 B / C 可能"看起来半成品"，用户试用体验差。
   - **缓解**：在 [docs/milestones/acceptance.md](acceptance.md) 中明确 v0.1 的 B / C 验收门槛是"基础视图可用"，增强能力不在验收范围。
2. **DSH 原生能力假设可能不成立**：v0.2 / v0.3 的依赖前置都依赖 DSH 暴露对应能力。
   - **风险**：若 DSH 不支持，对应能力降级为"skyaxis 自建抽象层"，增加工作量。
   - **缓解**：跑通最小插件 demo 后验证假设，提前重新调整子阶段。
3. **阶段 3 占位不锁定具体内容**：可能导致 MVP 完成后"不知道下一步做什么"。
   - **缓解**：MVP 完成时（v0.3 通过条件满足时）重新启动一轮"长期规划"讨论，**新开 ADR** 锁定具体内容。

| 备选方案 | 未选原因 |
| --- | --- |
| **方案 B：按"场景维度"分 4 个子阶段** | v0.3（C 多 session 总览）依赖 v0.1 / v0.2 的 Session 视图层作为底座，独立交付能力较弱。 |
| **不分子阶段，直接做整个 MVP** | 验证 [ADR 0003](0003-MVP场景清单.md) / [ADR 0006](0006-业务对象清单.md) 已标注的"宽范围 MVP 风险"。 |
