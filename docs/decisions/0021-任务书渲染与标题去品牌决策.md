# 任务书渲染与标题去品牌决策（MarkdownText 默认渲染 + 编辑切换）

> 日期：2026-10-21
> 背景：用户实机反馈——所有任务书都是 markdown 格式，但页面直接显示原文（裸 textarea），没有渲染。三条诉求：① 任务书默认渲染 markdown ＋ 编辑模式切换按钮；② 任务书标题去掉 "skyaxis"；③ 「投递并发送的文本格式也应该是渲染后的样式」。
> 拍板：用户 2026-10-21 两问两答——**发送格式=保持 markdown 源码（推荐档）；返工话=rework 弹窗一并处理（推荐档）**；实施落 [milestones 0021](../milestones/0021-任务书渲染实施计划.md)。
> 定位：client 侧为主小轮（host 侧仅 seedDevDeclare 锚兜底一处）；发送链路字节不变——渲染只是展示层。

## D1 发送格式：保持 markdown 源码（宿主约束如实告知后拍板）

宿主取证（[dsh-client-ui-primitives](../../node_modules/@deepseek-ai/dsh-client-ui-primitives/lib/types/user-text.d.ts)）：DSH 聊天面板对**用户消息**（气泡与排队行）用 `projectUserText`——inline 平文＋@chip 投影，不做 markdown 排版；`MarkdownText` 自述为「assistant 专用渲染器」。即任务书投递进会话后按宿主设计显示为平文，插件无法改变宿主渲染。两档取舍：**保持源码**＝AI 完整读到文档结构（表格/层级/输出约定 yaml 围栏示例最忠实，声明块收取链零风险）；**转纯文本**＝气泡干净但结构退化、围栏示例拍平、收取链有断链风险。用户拍板保持源码——模态内渲染保证所见即所发，宿主气泡内平文显示属宿主行为。

## D2 返工话范围：一并处理

返工话（`# 返工话 WPn` 头行的 markdown，rework 弹窗裸 textarea 预览后发送）与任务书同为「预览→编辑→发送」面，体验一致；用户拍板一并处理（渲染默认＋编辑切换＋标题去品牌）。**边界维持**：sheet-export-modal 的 `<pre>` 是「所见即所复制」纪律且非任务书——不动。

## D3 标题联动：双臂兼容

标题去品牌波及内容寻址锚（0016 拍板：任务书头行=真实会话 fallback 标题＝寻址地址）：`DEV_SOW_TITLE_WP_RE` 改 `/^# (?:skyaxis )?工作包任务书 (WP[1-9]\d*)(?!\d)/`；view.tsx 分析 shell repair 双前缀；endpoint.ts seedDevDeclare 新锚先查、miss 后 legacy 锚兜底。在途旧标题会话（`# skyaxis …`）不停摆。**机器标记不动**：`# skyaxis-declare`/`# skyaxis-review` 是 AI 输出协议（declare-parse/review-parse 消费），改动会孤儿化在途会话。自洽锚（onDelivered 的 `sowText.slice(0,200)`）存的就是所发文本——自动跟随。

## 渲染实现（复用先例）

`MarkdownText`（宿主原语包，项目内 4 处在用：dialog 计划体/doc-section/review-section/prd-section）＋ labels memo 稳定引用（work-package-dialog.tsx:160-165 先例）。词典 +2 键（`md.edit`/`md.preview`，md.* 既有 markdown-chrome 组）四处登记。测试策略受 vitest 桩约束（micromark 族被 [vitest.config.ts](../../vitest.config.ts) 打桩，work-package-dialog.spec 纪律「断言不做到 Markdown 层」）：读文本一律**幂等切编辑态读 textarea**（waitFor 轮询不翻转），渲染态新用例只钉容器在场/缺席与按钮文案。
