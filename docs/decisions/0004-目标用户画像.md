# ADR 0004：目标用户画像 — MVP 第一版核心服务"AI 重度多 session 用户"

| 字段 | 值 |
| --- | --- |
| **状态** | 接受 |
| **日期** | 2026-09-19 |
| **记录人** | Claude（基于用户决策） |

---

## 背景

按 CLAUDE.md 第 4.4 节阶段切换条件第 2 条，**目标用户画像明确并写入 `docs/users/`** 是立项阶段的硬性前置。

ADR 0001 / 0002 / 0003 共同锚定了 skyaxis 的形态、定位、MVP 场景，但尚未定义**为谁服务**。本 ADR 锁定目标用户画像的具体内容。

---

## 决策

### 核心画像：**A — AI 重度多 session 用户**

> **一句话**：每天 4 小时以上 AI 编程、同时并行 3-5 个 session、个人开发者。

**行为特征**：

- **使用强度**：每天 4h+ 在 AI 编程工具中工作。
- **session 并行度**：同时打开 3-5 个 AI session，不同 session 在不同任务上并行。
- **痛点**：
  - 单 session 内复杂任务被切成多步 AI 调用，无法看清"现在到哪一步"。
  - 多 session 并行时，"哪个 session 在等指令、哪个在执行、哪个已完成"无法一眼看清。
  - session 跑完后产出散落在聊天框里，事后想找回困难。
  - 不同 session 之间存在依赖（如 session B 的 prompt 依赖 session A 的产出），但缺乏显式表达。

### Anti-Persona（明确不服务）

| 反例 | 特征 | 不服务原因 |
| --- | --- | --- |
| **反例 1：团队协作用户** | 多人共用 session、团队任务分配、共享决策 | 与"个人开发者"定位正交；skyaxis 不做团队协作。依据：CLAUDE.md 第 3 节 + ADR 0002 定位。 |
| **反例 3：跨项目独立 session 用户**（B 画像） | 同时维护 3-5 个独立项目，每个项目 1 个 session，session 间无依赖 | MVP 优化重点是"session 间有依赖"的重度多 session 用户，B 画像痛点更弱；D2（session 间依赖）对其是过度设计。 |

### 边缘画像（非核心但允许）

- **学习者 / 探索性使用**：单 session 为主、低使用强度、上下文切换不频繁。MVP 不为这类用户做**专属优化**，但他们使用 skyaxis 不会被"劝退"——A / B / C 场景对学习者也有价值，只是 D1 / D2 的复杂度对他们是过度设计。

---

## 后果

### 正面

- **聚焦明确**：MVP 只为一个清晰的核心画像服务，所有 6 个 MVP 场景（ADR 0003）都向画像 A 的痛点对齐。
- **反例清晰**：避免 MVP 范围被"似乎有用"的其他用户群体稀释。

### 负面 / 风险

1. **画像 A 群体规模有限**：3-5 session 并行的重度 AI 编程用户是相对小的细分市场。
   - **风险**：MVP 验证的市场容量可能不足。
   - **缓解**：MVP 验证后可向画像 A 的"弱化版"扩展（如 2-3 session 的中度用户），但前提是核心场景已经验证有效。
2. **学习者未被排除**：MVP 不为学习者做专属优化，但他们使用 skyaxis 不会被劝退。
   - **风险**：如果学习者实际使用率高，可能反向要求 skyaxis 适配学习场景，导致 MVP 范围扩张。
   - **缓解**：在 `docs/scope/` 的 Non-Goals 中明确标注"不为学习者做专属优化"，避免反馈驱动的范围蔓延。
3. **反例 3（B 画像）排除过早**：D2（session 间输入/输出依赖）正是 B 画像不需要的能力，但 MVP 6 个场景里包含 D2，意味着 B 画像用户尝试 skyaxis 会觉得"D2 是过度设计"。
   - **缓解**：通过反例 3 告知 MVP 不服务 B 画像；MVP 后视情况再评估是否补回 B 画像的弱化版。

## 备选项（已考虑，未选）

| 备选核心画像 | 未选原因 |
| --- | --- |
| **B：跨项目独立 session 用户** | 与核心痛点（"session 间无依赖"特征）不匹配。 |
| **C：中度单 session 用户** | 痛点最弱，会让 D1 / D2 变成过度设计。 |
| **D：AI 重度学习探索者** | 与 A 有重叠但场景不同（学习 vs 产品开发），痛点不是"session 并行"。 |
