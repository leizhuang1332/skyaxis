- [ADR 0009 — subagent 拓扑可视化](0009-subagent拓扑可视化-MVP范围与轨迹合并策略.md)（observe-only 集成；MVP 优先形态 B 外部 patch overlay；独立 panel 架构）

## 决策

### 10.1 唯一推荐技术栈

#### A. 与 DSH 一致的强约束项（无需用户决策，自动锁定）

| 维度 | 选型 | 来源 |
| --- | --- | --- |
| **包管理器** | pnpm@11.7.0 + workspaces | DSH 仓根 package.json |
| **Node 版本** | ^22.19.0 \|\| >=24.0.0 | DSH engines |
| **模块系统** | ESM-only（`"type": "module"`） | DSH 子仓 package.json |
| **TypeScript** | 5.x（DSH 同版本） | DSH tsconfig.host.json / tsconfig.client.json |
| **构建工具** | tsdown | DSH ui-subagent package.json `"bundle": "tsdown"` |
| **测试框架** | Vitest | DSH 根 scripts: `"test": "vitest run"` |
| **Lint 工具** | oxlint（非 eslint） | DSH 根 scripts: `"lint": "tsx scripts/run-oxlint.ts ."` |
| **React** | ^18.2.0 | DSH ui-subagent peerDependencies |

#### B. skyaxis 自身设计选择（推荐）

| 维度 | 选型 | 替代方案 | 推荐理由 |
| --- | --- | --- | --- |
| **状态管理** | **Zustand** | Jotai / Redux Toolkit / 不用第三方 | hook-style、与 React 18 + TS 配合好；store 与 React 解耦；skyaxis 多 slice（session / catalog / projection / merged-trajectory）管理清晰 |
| **拓扑图库** | **React Flow** | Cytoscape.js / D3 + 自定义 SVG / 自研 | 与 React 18 + Zustand 配套；MIT；活跃节点高亮 + 1s tick 直接支持；场景 A / D1 / D2 共用一个图组件减少开发量 |
| **UI 组件库** | **复用 DSH @deepseek-ai/dsh-client-ui-primitives** | Radix UI / shadcn/ui / 自写 | skyaxis 是 DSH 插件，视觉与 DSH 一致；复用 DSH 维护好的 button / dialog / list |
| **包结构** | npm 包 `@skyaxis/plugin` | monorepo / 单仓多包 | [ADR 0009 第 9.6 节](0009-subagent拓扑可视化-MVP范围与轨迹合并策略.md) 锁定 MVP 优先形态 B（外部 patch overlay） |

### 10.2 为什么其他方案不适合当前项目

#### 不推荐：Jotai（替代 Zustand）

- skyaxis 状态是**几个大块**（session / catalog / projection / merged-trajectory），不是"很多独立原子"
- Jotai 适合细粒度状态（如表单字段、动画值），Zustand 适合"几个独立 store"
- skyaxis 拓扑图节点 1s tick 需要精细控制订阅，Zustand 的 selector 比 Jotai 的 atom 更适合这种场景

#### 不推荐：Redux Toolkit（替代 Zustand）

- 工程量过大；skyaxis MVP 状态结构 5-6 个 slice 不需要 RTK 的样板代码（createSlice / thunk / middleware）
- DSH 周边仓库社区无 RTK 使用惯例

#### 不推荐：不用第三方状态管理

- useState + Context 在跨多组件共享时触发不可控 re-render
- skyaxis 拓扑画布 + 多 panel 需要精细控制订阅粒度，Context 无法满足
- Zustand bundle size < 1KB；不引入反而增加开发难度

#### 不推荐：Cytoscape.js（替代 React Flow）

- 学术级图算法（社交网络、生物信息）skyaxis 用不上
- 与 React 集成需要 cytoscape-react 包，额外依赖
- 性能开销 > React Flow
- skyaxis MVP 子阶段 N ≤ 64（ADR 0009 9.4），不需要学术级算法

#### 不推荐：D3 + 自定义 SVG（替代 React Flow）

- 最大灵活度但工程量最大
- skyaxis 场景 A / D1 / D2 共用一个图组件（subagent tree、task DAG、session 依赖图），D3 要写 3 次
- DSH 周边仓库无 D3 + React 使用先例

#### 不推荐：自研拓扑图库

- MVP 工期爆炸
- 拖拽 / 缩放 / 折叠 / 高亮等交互需要自己实现
- 复用 DSH ui-subagent 拓扑的"dropdown + 键盘导航"等参考实现（[research/0009-dsh-subagent-reference.md 第 1.3 节](../research/0009-dsh-subagent-reference.md)）也表明自研是次优选项

#### 不推荐：Radix UI / shadcn/ui（替代 DSH ui-primitives）

- 与 DSH 视觉不一致
- 用户认知 skyaxis 是"DSH 的一部分"，视觉割裂破坏沉浸感
- DSH ui-primitives 已包含 button / dialog / list / progress 等 skyaxis 需要的组件
- 自写组件工程量大，且无法复用 DSH 已维护的样式 / a11y / 国际化

#### 不推荐：集成形态 A（DSH 主仓 PR）

- [ADR 0009 第 9.6 节](0009-subagent拓扑可视化-MVP范围与轨迹合并策略.md) 锁定 MVP 优先形态 B
- 形态 A 需 DSH 维护者接受 PR，skyaxis 独立演进被阻塞
- 形态 A 可作为长期目标，但不在 MVP 范围

### 10.3 这套技术栈适合当前项目的哪些需求

#### MVP 6 场景 + ADR 0009 扩展

| 场景 / 能力 | 满足方式 |
| --- | --- |
| **A 单 session 内进度可视化** | React Flow（任务树 / 时间线 / 进度条）+ Zustand（session / task slice）+ DSH ui-primitives（progress / list）|
| **B 跨 session 产出聚合** | Zustand（aggregated slice）+ React Flow（多 root 并列）+ DSH ui-primitives（tabs / table） |
| **C 多 session 总览** | React Flow + Zustand + DSH ui-primitives（card / filter）|
| **D 决策 / 代码片段归档** | Zustand（decision / snippet slice）+ DSH ui-primitives（dialog / form）+ Vitest（搜索功能 E2E）|
| **D1 session 内 task DAG** | React Flow（task DAG 节点 / 边）+ Zustand + Vitest |
| **D2 session 间依赖** | React Flow（session 间依赖图）+ Zustand + Vitest |
| **ADR 0009 subagent 拓扑** | React Flow（subagent tree + 多 root 并列）+ Zustand（running / settled / catalog state）+ tsdown（独立 npm 包打包） |

#### 6 项非功能 / 横切关注点（[docs/scope/mvp-features.md NF 组](../scope/mvp-features.md)）

| 非功能 / 横切 | 满足方式 |
| --- | --- |
| **NF.1 集成形态 B** | tsdown 打包产出 `lib/index.js` + `lib/client.js`（与 DSH ui-subagent 同结构）；package.json `dsh.client.inject` 声明 6 个只读服务 |
| **NF.2 observe-only** | oxlint 自定义规则扫描 `continuationBinding` / `registerProvider` / `interrupt` / `fork` 调用 |
| **NF.3 5 分钟跑起来** | pnpm + tsdown + Vitest 与 DSH 一致；用户用 DSH 现有工具链即可 |
| **NF.4 DSH 版本钉钉** | package.json 用精确版本 `0.1.5-rc.2`；CI 检查 DSH 版本漂移 |
| **NF.5 纯本地 + 单端** | pnpm + tsdown 完全本地打包；无远程依赖 |
| **NF.6 MIT 开源免费** | 全套依赖都是 MIT / Apache 2.0；React Flow / Zustand 都是 MIT |

### 10.4 后期可能遇到的风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **DSH 版本演化** | DSH 是 Developer Preview（v0.1.5-rc.2 → v0.2 / v1.0），tsdown / Vitest / oxlint / React 可能升级 | 钉钉 v0.1.5-rc.2；版本升级策略落地为新 ADR（候选 ADR 0011）|
| **DSH workspace 协议依赖** | 复用 DSH ui-primitives 用 `workspace:^` 协议；skyaxis 发到 npm 后该协议无法解析 | 发包前替换为 `npm:@deepseek-ai/dsh-client-ui-primitives@0.1.5-rc.2` 精确版本 |
| **React 18 → 19 升级** | DSH 升 React 19 时 skyaxis 必须跟随；hook 行为可能变化 | skyaxis 自写代码遵循 React 官方升级指南；React Flow / Zustand 兼容性需逐版本验证 |
| **拓扑图库性能** | React Flow 在 subagent 数 > 100 时可能卡顿 | skyaxis 边界 N ≤ 64（[ADR 0009 第 9.4 节](0009-subagent拓扑可视化-MVP范围与轨迹合并策略.md)）；边界接近时做性能回归测试 |
| **Zustand 扩展性** | skyaxis 状态 5-6 个 slice 在 MVP 范围内够用；阶段 3（MVP 后迭代）增加新场景时可能不够 | 阶段 3 是占位（[ADR 0007](0007-长期规划与里程碑.md)）；MVP 锁定范围已考虑 |
| **oxlint 规则覆盖** | 自定义 oxlint 规则写起来有学习曲线；observe-only 违规扫描可能漏掉非直接调用（如反射调用）| v0.1 实施期先用简单正则扫描；v0.2 升级为完整 oxlint 规则 |
| **pnpm-lock.yaml 体积** | 复用 DSH workspace:^ 依赖会让 pnpm-lock.yaml 较大 | CI 缓存策略设计（pnpm store cache） |
| **DSH type-only 包导出** | skyaxis 消费 DSH 类型时遇到 `import type { ... } from '@deepseek-ai/.../src/*'` 深路径导入；DSH 包结构变化时 skyaxis 必须跟着改 | v0.1 实施期验证所有 DSH 消费路径；记录在 `docs/research/dsh-consume-map.md` |

---

## 后果

### 正面

1. **强约束项与 DSH 一致**：复用 DSH 已有工具链（pnpm / tsdown / Vitest / oxlint），用户无需学新工具链（NF.3 5 分钟跑起来）
2. **observe-only 集成天然支持**：oxlint 自定义规则 + `verify-skyaxis-readonly` lint 脚本
3. **可视化核心组件统一**：React Flow 服务于场景 A / D1 / D2 + ADR 0009 subagent 拓扑；skyaxis 子阶段开发可"复用同一图组件"
4. **MVP 工程量可控**：Zustand + React Flow + DSH ui-primitives 三件套覆盖 90% skyaxis UI / 状态需求
5. **MIT 全栈**：所有依赖都是 MIT / Apache 2.0，符合 [ADR 0005](0005-MVP边界与Non-Goals.md) 分发约束

### 负面 / 风险

1. **DSH 版本钉钉代价**：skyaxis 必须等 DSH 升级才能升级 React / tsdown / Vitest
2. **DSH ui-primitives 复用是双刃剑**：复用 = 一致，但 DSH 改 UI 库时 skyaxis 必须跟随
3. **Zustand 在阶段 3 可能不够**：但 MVP 锁定范围已考虑
4. **React Flow 性能边界**：N ≤ 64 是 MVP 子阶段约束，阶段 3 可能需切换图库

## 备选项（已考虑，未选）

| 备选 | 未选原因 |
| --- | --- |
| pnpm + turbo / nx | skyaxis 是独立仓，不需要 monorepo 工具 |
| CJS 模块系统 | DSH 是 ESM-only，CJS 无法 import |
| JavaScript（无 TS）| 失去 DSH 类型保护，refactor 灾难 |
| React 17 / 19 | DSH 是 React 18.x；版本不一致破坏 hook 行为 |
| ESLint | DSH 用 oxlint（非 ESLint）；skyaxis 内部 lint 应一致 |
| 状态管理 Redux Toolkit | MVP 工程量过大 |
| 状态管理 Jotai | skyaxis 状态是"几个大块"不是"很多独立原子" |
| 状态管理不用第三方 | Context re-render 不可控 |
| 拓扑图库 Cytoscape.js | 学术级过重 |
| 拓扑图库 D3 + SVG | 工程量最大；3 个场景要写 3 次 |
| 拓扑图库自研 | MVP 工期爆炸 |
| UI 组件库 Radix | 与 DSH 视觉不一致 |
| UI 组件库 shadcn | 与 DSH 视觉不一致；需额外 Tailwind 依赖 |
| UI 组件库自写 | 工程量爆炸 |
| 集成形态 A（DSH PR）| 需 DSH 维护者接受；MVP 优先形态 B（ADR 0009 9.6） |
