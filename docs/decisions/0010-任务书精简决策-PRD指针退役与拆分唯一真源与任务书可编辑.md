# 决策 0010：任务书精简（PRD 指针退役 / 拆分唯一真源=基线文档 / 任务书可编辑）

> 日期：2026-10-15
> 依据：用户 2026-10-15 对三轮（0007/0008）堆出的任务书形态的四点反馈（去左侧「PRD 重点章节」/ prompt 只引路径 / 拆分只引基线文档 / 去冗余 + 支持编辑）+ 本轮 AskUserQuestion 两拍板（拆分无锚保持精简形态 / 精简深度取保守）。
> 状态：**已拍板**——延续 [决策 0009](0009-需求基线文档决策-融合文档与docHash锚.md) D2 的真源分治（文档=需求表达真源），把它从「衔接行」推进到「任务书主体」。

## 背景

0007/0008 之后任务书三轮加码：split 快照嵌标准/发现处置/澄清全量摘要、输入段带重点章节指针、modal 左侧 PRD 勾选组、结尾 revision 戳。用户反馈四点：modal 不需要左侧「PRD 重点章节」；prompt 只需明确 PRD 文件地址；拆分的唯一真相源是基线文档（发现/验证标准/澄清项都在文档里，不再需要）；去掉「生成于 revision N · …」等冗余并支持用户改任务书。

## D1 PRD 重点指针退役——三任务书全部路径引用（已拍板）

analysis 输入段的文档行与 consolidate 同形：**全部 `- 必读 prds/<name>`，无焦点文档、无「重点章节」指针**（modal 左侧勾选组对 analysis/split/consolidate 退役，仅 dev/review 保留——它们的五段 SOW 嵌入选中章节正文，是仅存的嵌入面）。焦点/按需分级行（`- 按需 prds/…`）随之退役。

## D2 拆分唯一真源=基线文档——快照瘦身 + 无锚两态诚实行（已拍板）

**拆分任务书的需求依据只有基线文档**（0009 D2 的彻底化）：

- **快照瘦身**：仅保留 标题/描述/当前阶段/定稿状态行/现有工作包（re-split 参考）；标准清单、发现处置三组、已答澄清、待裁决提议全部退役——这些真源内容都在基线文档里，账本副本是同一真相的第二次表达。
- **输入段**：PRD 清单整段退役（含「列表未可得」行）；基线文档行三态（依据账本不依据盘，0009 D4 口径延续）：docHash 在场 ⇒ 必读行（逐字不变）；定稿无锚（pre-0008 定稿/定稿时无文档）⇒ 诚实行「已定稿但未锚定基线文档…以需求描述为唯一需求依据」；未定稿 ⇒ 诚实行同口径。
- **拍板：无锚不回退**——精简形态在所有状态成立（不做旧快照兜底）；诚实行本身就是「先定稿再拆分」的 doctrinal 推力。
- 文案对齐：工作流第 1 步改「通读需求基线文档」、约束/输出的依据括注从 `PRD#章节/已裁决发现编号` 切到 `基线文档 FR/C 编号`。
- repos/ 行保留（代码探索仍是拆分输入）。

## D3 任务书可编辑——脏锁 + 恢复生成内容（已拍板）

预览从只读 `<pre>` 改为受控 `<textarea data-testid="sow-preview">`：用户键入即生效（`editedText` state，null=live 生成内容）；**脏锁**——已编辑时左列勾选（知识等）更新 live 生成内容但不覆盖用户文本，footer 出现 [恢复生成内容]（`sow.resetEdit`）负责同步；复制/投递/analysis 回传锚全部用最终文本。**对五个 purpose 一致生效**，但 dev/review 的默认生成文案逐字冻结不变（0007「本轮只动 analysis」的范围纪律延续——编辑是 modal 能力，不是文档形状变更）。

## D4 revision 戳退役范围——仅三 AI 语境（已拍板，保守精简）

analysis/split/consolidate 不再拼接「生成于 revision N · 日期 · 此后账本变更不自动同步」；dev/review 保留（五段路径冻结）。诚实锚由快照头的「生成时快照」措辞承担。**精简深度拍板为保守**：只去戳 + 指针相关内容；快照/约束/工作流/输出的契约文案（围栏纪律、声明块教学、六类判据）不动——它们是回传解析的承重结构，单次实例的再裁剪由 D3 编辑能力承担。
