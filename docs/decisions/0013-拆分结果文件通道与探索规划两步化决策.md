# 决策 0013：拆分结果文件通道与探索规划两步化（采纳软门 / workPackages 提议键 / stale 第六臂）

> 日期：2026-10-15
> 依据：[research 0011](../research/0011-拆分结果交付与探索规划两步化业界调研与设计.md)（三路调研 + 四正三反论证）+ 用户 2026-10-15 六拍板（方向三拍板：A+B 合并一轮 / 采纳=软门 / 四权闭环；AskUserQuestion 两拍板：落点一族一目录 / 动作命名「采纳规划」）+ [research 0009](../research/0009-需求理解定稿业界调研与设计.md) §5 挂账（「拆分提议机器回传——另轮四权论证」，本轮即该轮）。
> 状态：**已拍板**——六项均用户 2026-10-15 拍板；延续 [决策 0007](0007-分析报告工作区交付决策-点目录通道与单写者纪律.md)（文件=契约面）与 [决策 0009](0009-需求基线文档决策-融合文档与docHash锚.md) D2（真源分治）两条既定路线，把 ② 补齐到与 ① 同构。

## 背景

① 已三轮成型「AI 写文件→自动收取→页面回显→用户裁决锚定」；② 停在「会话散文+人肉抄录」（拆分任务书明令不写文件、建议不会被自动导入，[sow.ts:735/759](../../src/client/workbench/sow.ts#L735)），且一步出拆分、探索结论无产物。research 0011 的决定性论证：**拆分在 skyaxis 的权重 ≈ 业界 agent 产品里「计划」的权重**（账本持久治理对象 vs 廉价可逆 todo），故业界给「计划」的待遇（审批门+工件化）应给到拆分层，中间补方案层（业界默认 spec→plan→tasks 三层，skyaxis 缺中间层）。

## D1 拆分结果文件通道与四权闭环（已拍板）

**选择**：拆分任务书输出段从「会话内交付，不写文件」改为**文件交付**——AI 单写者把完整拆分方案（markdown 正文 + 结尾内嵌 ` ```yaml # skyaxis-declare ` 机器块）写入 `<工作区>/.skyaxis/split/<requirementId>.md`（覆盖写）；插件以文件为**唯一收取通道**收取（无会话链兜底——0007 的会话链是为存量投递兜底而设，split 无存量包袱；无工作区 ⇒ 通道 unarmed，S2 提示「无法自动收取，可手动录入」，[＋工作包] 手动路径保留为诚实回退）。

**机器块 workPackages 提议键与四权闭环**：declare 块在 plain 键（knowledge/stageReady）之外新增 `workPackages` 提议键（条目：`ref`（AI 建议序号 WP1/WP2…，提议内部交叉引用用）/ title / boundary / dependsOn（ref 列表）/ parallel / covers（C 编号列表））。**提议≠登记**：收取落 `splitProposals` 容器（analysis 容器同构的待裁决行，HOST-MINTED ONLY、不进徽章/stale/覆盖矩阵）；登记=用户在提议区勾选后 [登记选中]（`adoptSplitProposals` 动作），**WP 序号由 host 铸**（nextSequenceId，ref→铸 id 映射、dependsOn 随行重写——0005 细化③「version 由 host 分配」同款纪律，AI 永远递交建议而非 id）；**硬门①（批准拆分）语义零变化**——登记只是把提议变成 workPackages[]（planned 态），批准仍是后续独立用户动作；locked-split 后 adoptSplitProposals 400（生命周期动作家族，saveWorkPackage 同门）。坏行跳过并列出（covers 指向不存在的 C 编号 / dependsOn 悬空 ref / 坏形状→skipped，不整块拒绝）；新 seed 替换未登记提议（analysis「新报告替换未裁决」先例）；[忽略] 为逐行手动出口。

**为何不是纯 JSON/YAML 整文件、为何保留会话散文段**：0007 D1 论证原样适用（长中文 prose 零转义 + declare-parse 复用）；正文（覆盖矩阵/新发现/排序理由）保持人读 markdown，供 [批准拆分] ack 弹窗与用户审阅。

## D2 规划文档与两步化——采纳软门（已拍板）

**选择**：② 内拆两步——**2a 探索规划**：新任务书 purpose=`plan`（九节骨架，analysis 同族装配：目标=产出技术规划文档；输入=必读基线行〔三态，0009 D2 口径〕+ repos/ 路径行 + 现有工作包参考；输出=写 `.skyaxis/planning/<rid>.md`，一次成文覆盖写），**无 declare 回传、不绑 watcher**（整理任务书先例——决策 0009 连带记档明文）。文档骨架六节：现状盘点（含探察文件清单——0008「已通读须以清单为证」纪律）/ 技术方案 / 改动面（模块×文件）/ 风险与开放问题 / 实施顺序草案（依赖顺序+建议工作包轮廓——**论证材料非清单**，正式清单仍只出自 2b，不造第二真源）/ 对拆分的建议原则。**2b 拆分**：现任务书输入段增必读规划行三态——planBaseline.docHash 在场 ⇒ 必读 `.skyaxis/planning/<rid>.md`（技术方案真源；与你所见冲突时在报告中列出）；已采纳但未锚（采纳时无工作区）⇒ 诚实行；未采纳 ⇒ 诚实行「尚无锚定的技术规划文档——以基线文档与仓库现状为依据」（跳过路径保留，doctrinal 推力同 0010 D2）。

**采纳软门**：[采纳规划]（ack 弹窗统计+警示不阻断，定稿 ack 形制）→ 专属 flow 读盘 sha256 → 盖 `planAdoptedAt` + `planBaseline{at, docHash, requirementDocHash(上游基线快照)}`；**unarmed/missing ⇒ 无锚但采纳仍成立**（approveUnderstand 软门口径逐字同构：无文档可采纳——ack 披露）；too-large ⇒ 413（文件在但坏，锚定空值会伪证「无文档」）。[撤销采纳] 摘戳即摘基线；重复采纳 400（approve 家族纪律）；采纳含 implicit-create 臂（全零采纳=合法路径，全零定稿先例）。**不锁下游**——规划未采纳可直接拆分（诚实行披露）；advanceStage 语义零改动（内容事件≠注意力事件，0008 裁决延续）。

**驳回侧形态**：采纳前不满意 = 重新 [生成规划任务书] 投递（新会话覆盖写同一路径文件，无额外账本状态）；采纳后 = [撤销采纳] 再重投。**不做一会话两产物**（research 0011 §5——中间门蒸发，伪两步）。

## D3 落点与命名（已拍板，AskUserQuestion 两项）

- **一族一目录**：`.skyaxis/planning/<requirementId>.md` + `.skyaxis/split/<requirementId>.md`——与 `analysis/`、`requirements/` 并列，uuid 定名零创造空间（0007 D2 纪律）；点前缀命名空间隔离；布局模板 v1 冻结（变更=破坏性迁移，先修订本 ADR）；路径单源 `workbench-shared/protocol.ts`（`PLANNING_DOC_DIR`/`planningDocRelPath`、`SPLIT_RESULT_DIR`/`splitResultRelPath`，requirementDocRelPath 同款 uuid 守卫），host join 在 artifact-path.ts（`planningDocPath`/`splitResultPath`，双层防御）。
- **动作命名**：按钮「采纳规划」/「撤销采纳」，字段 `planAdoptedAt`/`planBaseline`——裁决动词与 ① 提议行家族（采纳/不采）一致，规划文档本质是 AI 递交的待裁决主张；不复用「定稿」（① 定稿=整阶段收口，此处是阶段内子步骤门，动词复用混淆收口语义）；GET kind：`planning-doc` / `split-result`（与 analysis-report/requirement-doc 命名形制一致；**不复用 `plan`**——该 kind 已被 WP 实施计划占用，[protocol.ts:1370](../../src/workbench-shared/protocol.ts#L1370)）。

## D4 用户介入点与不动清单（已拍板）

**介入点三处**（权限全部落在既有模型内）：① 规划采纳/撤销（软门，新）；② 拆包提议逐条勾选+[登记选中]/[忽略]（提议裁决，analysis 提议行同构，新）；③ 批准拆分（硬门①，语义零变化——从审人肉转写升级为审系统收取+用户校对过的清单）。

**不动清单**：dev/review 五段形态与 revision 戳逐字冻结；declare 家族解析原则（坏行跳过、整块语法错误信封化、fence 定位器）；四权模型（批准拆分/批准计划/验收/阶段推进永不在 AI 手里）；投递通道（DSH 会话草稿人握发送键）；任务书可编辑脏锁（五 purpose 一致，'plan' 加入同权）；知识注入上限；`approveUnderstand`/`advanceStage`/看板解锁条件零改动。

## D5 合并一轮交付（已拍板）

A（拆分结果文件化+回显）与 B（规划文档两步化）一轮做完——B 的拆分任务书输入/输出段改写与 A 的输出段改写是同一处手术，拆两轮反而两次重写同一文件与测试；风险控制靠里程碑分刀（通道/数据面先行，任务书面与 UI 面随后）与冻结锚回归用例承担。

## 连带记档

- **SowPurpose 扩展**：`'analysis' | 'split' | 'consolidate' | 'dev' | 'review'` 增 `'plan'`（[sow.ts:202](../../src/client/workbench/sow.ts#L202) 等 3 处 union + view/split-section 入口）。注意 'plan' 与 stage key 'plan'（探索规划）同形不同枚举、与 artifact kind 'plan'（WP 实施计划）无关——命名冲突已审议并接受（阶段语境内 'plan' 即探索规划，语义自洽）。
- **SESSION_PURPOSE_VALUES 增 `'split'`**（[types.ts:28](../../src/workbench-host/types.ts#L28)）：拆分投递绑回传会话（bindSplitSession，带任务书头 200 字锚——provenance+watcher 门控语义与 analysis 同构；**不做 shell repair**——文件单通道不需要会话内容寻址）；'plan' 不绑（无回传）。
- **splitProposals 容器**（新 record 字段，optional 字段演进纪律）：`{session{sessionId,boundAt,anchor}, seed{sessionId,contentHash,seededAt}?, workPackages: ProposedWorkPackage[]}`——seed 幂等锚=sessionId+盘上 sha256；**收取门** `!running`（不 mid-run 播种；文件通道armed 时不受 blank 门限——0007 死锁消解口径）。
- **watcher 复制不抽**：view 层 analysis watcher（running/blank/one-shot/retry 族）为 split 复制一份精简版（无 shell repair、无 title 前缀重绑）；**文件卡家族抽通用件**——WorkspaceDocSection（report-section/prd-section/requirement-doc-section 三胞胎 + 本轮 planning-doc 第四份，[requirement-doc-section.tsx 头注](../../src/client/workbench/requirement-doc-section.tsx#L1-L13)预约的触发条件到达）。
- **stale 两臂**：① 规划卡自身——planBaseline.requirementDocHash ≠ 现行 understandBaseline.docHash（双侧在场才比，缺席不误报——第五臂纪律）⇒ 规划卡 warning 徽章「上游基线已变更」；② splitBaseline 增 `planningDocHash`（approveSplit/confirmSplitStillValid 从 planBaseline?.docHash 派生铸入，revoke/reSplit 摘除——requirementDocHash 第五臂逐字同构）⇒ 基线重整理→重新采纳规划→拆分失效的级联诚实链。
- **declare-parse 扩展**：DeclareProposals 增 `workPackages`（row 形 DeclareWorkPackageRow{ref,title,boundary,dependsOn,parallel?,covers}，坏行 skipped 闭枚举理由）；**不进 entries[]**（analysis proposals 同纪律——S5 导入面 wire 逐字节不变）。
- **GET artifacts 面**：kind 增 `planning-doc`（锚 compare vs planBaseline.docHash）/`split-result`（vs splitProposals.seed.contentHash）——文件先行可读（seed 未落也先读）、404 诚实缺失、contentTampered 警示不阻断。
- **词典**：planning.*（title/refresh/missing/loadError/tampered/pathPrefix/noWorkspace/adopt/adoptAck/revoke/adoptedBanner/staleBadge…）+ splitProposal.*（sectionTitle/waiting/missReason 族/adoptSelected/ignore/registeredHint…）+ sow.planButton，五点登记同步；CSS 沿用既有类为主，提议行复用 wpRow 族加提议标识类。
- **测试基线 1080**，预计净增 35-45（实施期落定）；README 双版同步。
