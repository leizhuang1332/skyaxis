# skyaxis — decision 0030：声明收取即翻转（in-dev 自动待验收）

> 日期：2026-10-23
> 背景：用户需求「开发完成后，应该自动更新 WP 状态为待验收」。现状取证：in-dev→built 翻转仅两处——手动按钮 markWorkPackageBuilt（record-actions.ts guard 只认 in-dev）与导入声明时 built 条目折叠（复用同 guard）；声明块被 watcher 收取后 WP 停在 in-dev，必须人工走完「导入声明→抓取→预览→勾选→导入」才翻状态。三个客户端触发臂（watcher sweep／声明卡「重新收取」／视图 mount 补种）全部汇入同一宿主 RPC（seedDevDeclare→applyDevDeclareSeed）——单写点。
> 拍板：用户 2026-10-23 两问两答（D1-A／D2-A 均采推荐档）。

## 白话摘要

dev 会话收工吐出声明块（`claims: built: true` =「我做完了」的自报）→ 宿主收取（种槽）的那一刻，同一笔账本写就把 WP 从「开发中」翻成「待验收」；验收通过/不通过仍由用户手动（P13 天花板不变：declare 回传只能推进到待验收、永不自动推已验收）。「导入声明」职能收窄为上线项/知识候选的人工收录＋盖章，不再承担状态翻转。

## 一、D1-A：翻转落点与条件

**落点=收取写点**（applyDevDeclareSeed fresh 分支，同记录原子折叠）——单点覆盖全部触发路径；槽与状态一笔落盘不撕裂。

**条件=块确实声明了 built**：种子流既有的轻量解析（P2b 取 commits 同一调用）顺带算 `claimsBuilt`（=以当前台账该块能导出 built 条目——claims 形状/作用域/拆分批准全部语义继承自解析器），且只有 in-dev WP 翻转：

| 收取时 WP 状态 | 块带 built 主张 | 块不带（部分交付） |
| --- | --- | --- |
| in-dev | **翻 built（本决策）** | 只种槽（信息收集） |
| plan-approved / accepted / built | 只种槽（三修前半保真——抢跑会话不越生命周期门，翻转仍归导入路径） | 只种槽 |

幂等锚不变：锚命中（同会话+同哈希）恒零写——翻转随该文本的首次 fresh seed 落地或被正确扣留，无重翻路径；返工轮（验收不通过回 in-dev→会话重跑→新哈希 fresh seed）自动再翻（0019 闭环缩短一步）。

## 二、D2-A：翻转后导入面的良性呈现

自动翻转后，同一声明的导入预览中 built 行落 skipped——新增良性原因 `wp-already-built`（「已完成待验收（收取时已自动生效）」），与报错口吻的 `wp-not-in-dev`（拆分未批/真不在开发中）分流。SKIP_REASON_KEY 穷举 Record 与 DECLARE_SKIP_REASONS 守卫数组强制登记到位；仅 built 态的块仍可导入 artifacts/knowledge。

## 三、对既有裁定的修订记档（诚实复盘）

- **刀一验收三修后半句部分推翻**（0016 修订记录 2026-10-17）：「收取是信息收集……导入（markWorkPackageBuilt）才需要 in-dev 门」。0030 起：对 in-dev WP，声明 built 的收取写点本身即翻状态——「收取是信息收集」对 in-dev WP 不再成立；前半句（收取无 in-dev 门、任意非 dropped WP 可收）原样保留。导入折叠的 in-dev guard 保留为竞态防御＋抢跑会话路径。
- **与 0016 显式拒绝清单的边界**：拒绝清单禁「watcher+自动导入（违四权）」。本决策不是自动导入：上线项/知识候选/回执/盖章仍全部人工（导入弹窗勾选不变）；翻转是生命周期推进、终点钉在 P13 天花板（待验收），验收永不动。watcher 触发的收取写原本就是自动写（种子本身），翻转搭同一笔写，不新增写通道。
- **手动兜底全保留**：详情「标记完成待验收」按钮、粘贴通道导入、非 built 主张块的人工导入路径零改动。

## 四、实现面

record-actions.ts `DevDeclareSeedInput` +`claimsBuilt?`（fresh 分支同记录折叠 in-dev→built）；endpoint `seedDevDeclareFlow` 解析算 `claimsBuilt` 穿线＋三修注释后半句改写；declare-parse.ts built 态单列 `wp-already-built`；protocol `DeclareSkipReason`＋`DECLARE_SKIP_REASONS` +新成员；词典 zh/en＋register 登记＋导入弹窗穷举映射。

测试 +3（1234→1237）：record-actions 收取即翻转新用例（同记录翻转／锚回放不重翻／返工新哈希再翻）＋既有锚与守卫用例扩钉（无主张不翻、planned/built 带主张不翻）；endpoint 种子流翻转落账本（armed＋unarmed）＋导入新常态（预览良性 skip＋applied=0 盖章分支全断言）＋抢跑会话臂（plan-approved 收取不翻→start→导入折 built，退役路径保活）；declare-parse built 态良性 skip（artifact/knowledge 照常可导）。tsc 干净。

## 五、不动清单

验收动作（通过/不通过）仍手动（P13 不变式）；手动 markBuilt 按钮/粘贴通道/导入 built 条目折叠（降级兜底与竞态防御）；收面无 in-dev 门（三修前半）；inbox 分组全序（槽 pending 行先于 built 行——共存态先导后验）；看板/声明卡/收件箱渲染（built 态可导、角标注入）；P2b commits 提案与确认；pending 快照尾写；幂等锚；0019 返工链；ADR 0005；词典其余。

## 六、实机验收门

1. dev 会话跑完（≤30s 节流窗内）→ 看板 WP 自动迁「待验收」列＋收件箱出行＋详情状态行。
2. 同声明导入：built 行呈「已完成待验收（收取时已自动生效）」；上线项照常勾选导入；槽翻 imported、回执落盘。
3. 无 built 主张的部分交付块（仅有 artifacts）→ 收取后 WP 留「开发中」不误翻。
4. 返工轮：验收不通过回开发中→会话重跑吐新声明 → 收取后再自动翻「待验收」。
