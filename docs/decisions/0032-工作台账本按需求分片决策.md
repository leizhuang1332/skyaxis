# skyaxis — decision 0032：工作台账本按需求分片（per-requirement record shards）

> 日期：2026-10-23
> 背景：用户三轮裁定——①「要拆分 workbench.yaml，每个需求都是独立的文件」（全机单文件台账随需求单调增长，每操作全量 parse/重写，一条坏行毒全库拒写——R#### 事故实弹先例）；②否决迁移到 `<workspacePath>/.skyaxis/`（鸡生蛋/换绑悬空/生命周期反转/git 污染四道墙，requirements.yaml 拍板不动）；③方案三点全按推荐（D1 分片同居、D2 插件加载时点迁移、D3 镜像导出面不做另立项）。设计全档见 [research 0032](../research/0032-工作台账本按需求分片立项与设计.md)。
> 拍板：用户 2026-10-23「都按你的推荐走」。

## 白话摘要

每个需求一条记录一个文件 `$DSH_HOME/skyaxis/workbench/<requirementId>/record.yaml`——和它已有的计划/评审产物**住同一个目录**，记录与产物生命周期从此完全同构（级联删除的整目录改名一把带走）。一把全库锁变成每需求一把小锁：两个需求并行操作不再互相 409；一条坏记录只坏它自己，其余需求照常。旧 workbench.yaml 在插件加载时一次性拆分归档，宿主域单写者，不需要 0028/0029 那套双通道读机器。取证确认全库不存在任何跨记录原子写（每个写请求本就只带一个需求 id）——单文件只是实现遗留，不是领域需求。

## 一、拆分不扭曲语义的证据（立项依据）

- 每个 mutate 请求本就带 `requirementId + expectedRevision`（wire 锁早已是需求级意图）；
- 所有 id 铸造以记录自身集合为域（WP/C 序号、R#### 均传 `record.xxx`）；**全库无跨记录原子写**；
- 客户端 controller 本就按需求分槽持 revision，未装载槽 0 = 分片缺失的虚拟 revision 0，implicit-create 语义精确对齐（UI 零改动）；
- declare 两段导入「共享 revision 空间、跨写 409 正确」——跨需求 409 是单文件强加的假冲突，拆分后消失。

## 二、设计要点（全档见 research 0032 §2）

1. **分片信封** `{version: 1, revision, record}` + `.bak` 随分片；加载校验 `record.requirementId === 目录名`（分片错位拷贝以 degraded 'schema' 拒载——artifact-path 双层防御同族）。
2. **锁**：每分片独立 revision，写队列按 rid 分道；缺失分片虚拟 0。mutate 面 wire 零改动（`{ok, revision, record}` 同形重释）；detail 面 revision 改为该记录值（record null 时 0）。
3. **list 面改形**：`{ok, true, rows: [{requirementId, revision, record}]}`——降级分片缺席 rows（其收取自动化静默跳过、用户面降级由 detail 409→slot degraded 承载）；degraded 信封只留给「迁移阻塞」整库态。消费面仅两 watcher + 测试。
4. **级联 step ③ 重定义**：「台账滤记录」→「unlink record.yaml + .bak」（幂等）。失败组合矩阵任何一支不劣于旧语义：③败⑤成时记录随目录入 .trash；墓碑改从分片读取内嵌；「降级永不阻塞删除」契约不破。
5. **迁移（D2）**：构造时 + 每入口点自愈 `ensureMigrated()`——可读旧文件→逐记录 force-seed revision 1→改名 `.migrated`（提交点；.bak/.tmp 随迁 best-effort）。**防影铸**：旧文件在场且未改名（不可读、或改名反复失败）→ 整库 blocked，绝不「分片缺失→虚拟 0→铸新记录盖真身」。
6. **孤儿扫描**：record.yaml/record.yaml.bak 入直下文件豁免清单；降级分片目录整体跳过（引用不可读时报孤儿是噪音）；目录在场≠记录在场（record.yaml 在场才算）。

## 四、不动清单

requirements.yaml / repos.yaml / knowledge.yaml 形态零改动（四同构 store 抽共享基类仍是记档后续项）；`.skyaxis/` 七通道零改动；plans/reviews 双通道与 contentHash 锚；批准锁定/尾草稿/版本号语义；级联 ①②③④⑤ 钉死顺序与「降级不阻塞删除」契约本身；幂等锚；declare/review 收取链与 pending 快照尾写；knowledge.yaml 及晋升双写语义（分片锁+全局池锁，非原子本就是记档态）；客户端 store/view/词典；ADR 0005 除本修订表 v3 行外其余条款。

## 五、实机验收门（四条，用户 2026-10-23 通过）

1. 真机升级：workbench.yaml 消失、workbench.yaml.migrated 在、各 `<rid>/record.yaml` 在、板子数据无损；
2. 两个需求并行操作零 409；
3. 删除一个需求 → 墓碑含完整记录、record.yaml 不在活树、.trash 目录完整；
4. 手工毁坏一个分片 → 仅该需求降级、其余照常、.bak 恢复后自动复原。
