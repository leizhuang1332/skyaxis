## 0. 摘要（TL;DR）

- **场景**：拆分批准后，工作包（WP）逐个交给 AI 会话开发。现状 S3 只有「五列看板（纯状态投影）+ WP 详情 Modal（计划版本链/会话绑定/验收历史）+ 会话条四态芯片」三件套——AI 执行本身发生在宿主会话里，工作台在「任务书投递」与「声明块回传」之间是黑盒：无过程视图、无 diff、无计量，中途介入只能跳宿主；dev 会话交付不自动绑定、built 声明要人跑去 S5 手动导入、`commits[]` 是无写入者的死字段。五目标（显性化/状态可见/结果可查/进度可跟踪/人类可介入）只有「状态可见（WP 粒度）」成立（§2.5 差距矩阵）。
- **答案**：**三层一引擎**（§5-§15）。①**摘要层**=看板卡升级为「WP 态 × 会话态」双层实时卡（一句话活动摘要/waiting 角标/完成待读角标/真实时长）；②**过程层**=新增 WP 执行视图（session-digest 尾窗 → 客户端折叠直播 + 真实计量 + 交付自述区），看板与执行视图双形态切换；③**末端**=声明块扩键（交付自述 summary/files/verification/commits）→ `devDeclares` 按 WP 键控待裁容器 → **注册层 watcher** 自动 seed → 用户确认导入（commits 死字段经用户逐条确认激活）；**引擎**=注册层 dev watcher（全局观测会话 idle 翻转沿，人不盯着的需求也能收完成信号）。S3 顶部「需要你」段瘦身为两组异常行（卡哪·存疑 + 等你·待发送）。
- **意义**：五目标全覆盖而盘子可控——底线四刀（P0 侦察 + P1a 收取管道 + P1b 执行视图 + P2a 声明扩键）独立可验收，其余刀全部可砍或后置（§14 砍刀保险清单）。业界验证模式（「等用户」一等态/零假进度/收件箱分组/折叠直播降噪/验证证据门/介入动词梯度/commit↔过程互链）全部**降维到「插件只读投影 + 任务书协议扩键」**形态落地——不动宿主、不破四权；而业界空白（需求级 WP 编排、账本锚定验收链、任务书软协议、跨会话本地持久）恰是 skyaxis 已有资产的延长线（§3.5 差异化机会）。
- **六问映射**（本轮六个关注点 → 章节）：产品形态→§6；功能职责→§7；workflow→§8；用户介入点→§9；AI 执行状态监控与跟踪→§10；准入准出→§11。工程四面：数据模型与协议→§12；宿主依赖与降级→§13；分期→§14；风险→§15。

## 1. 背景与问题定义

### 1.1 执行实施的位置与本轮动机

- ③ 执行实施（含验证——0006 形态拍板②）承接 ② 批准的拆分产物：逐 WP「起草计划 → 批准（硬门②）→ 生成任务书 → 投递 AI 会话 → 声明 built → 验收/返工」。上游三轮演进（0009 任务书精简 / 0010 需求基线 / 0012-0013 拆分两步化与文件通道 / 0015 PRD 勾选退役）把 ①② 收口后，③ 成为流水线上唯一「AI 在场时间长而工作台在场感为零」的阶段。

- 本轮动机（用户 2026-10-16）：把 AI 执行显性化——**状态可见、结果可查、进度可跟踪、人类可介入**。

### 1.2 可行性边界先行

重设计的一切机制受 §2.3 宿主能力包络约束：插件**现用**观测面=sessions.list 订阅（displayTitle/running/blank）/pendingInteractions（waiting 布尔级）/readSession 全量日志按需拉/searchSessions；**现用**操作面=sessions.create/scope/setDraft/open/navigate + 台账写动作族。sendMessage/interrupt/git/事件流增量订阅/台账推送在**现用面为零**（grep 验证，§2.3.3）；但 SDK 类型层存在 `prompt(content,'queue'|'steer')`/`updateQueue`/`cancel()`（设计勘误①，§5.0——类型在场≠运行时已验证）。业界模式凡依赖超包络能力的（三速介入/自动编排/diff 直读/后台实时直播）一律降维为协议通道或列宿主诉求决策点（D10），批复前不进任何默认。

#### 2.2.3 账本事实要点（重设计的事实底座）

1. **触发者归类**：全部 lifecycle 迁移仅用户可触发；AI 唯一间接通道 = declare built 声明被用户勾选导入（导入提交仍是用户点击）。watcher 自动收取只写 analysis/split 两提议容器（`view.tsx:277-394`），seed 只写待裁行，promote 全是用户动作。
2. **`commits[]` 是死字段**：仅创建时置 `[]`（`record-actions.ts:487, 535`），全仓无任何 action/declare/端点写入（grep `commits` 全 src 验证：命中仅 protocol/types 定义、两处置空、UI 计数）；`detail.commitsSection` 词典键**无渲染点**。commit 维度「结果可查」为零。
3. **sessions[] append-only 无解绑**（`protocol.ts:1076`；`record-actions.ts:697-704`；research/0006:415「解绑不删历史」）。
4. **acceptances append-only**，fail 返工固定回 in-dev，不区分「重写计划」与「继续改」。

#### 2.3.4 包络判定（映射五目标）

- 状态可见：原料齐全（状态机 + 四态芯片），差距纯在联动与刷新策略。
- 进度可跟踪：**半套原料**——`readSession` 日志可解析执行痕迹（工具调用/文件写入），但无增量订阅、无结构化进度信号；任何「实时进度」设计要么轮询 readSession、要么新增声明/心跳通道。
- 人类可介入：**半套原料**——waiting 态可感知（pendingInteractions），但应答无入口（须跳宿主）；运行中干预无 API。
- 结果可查：**原料缺**——diff/commit 需新宿主能力（git 读）或工作区文件方案（扫描产物）；readSession 可提取 AI 自述产物清单。
- 显性化：纯 UI 层问题，原料=上述全部。

## 3. 业界调研：执行实施期模式目录（15 产品 / 11 份报告）

**白话摘要**——场景：skyaxis 执行期是「任务书投递→黑盒→声明回传」，要在业界找显性化形态。答案：11 份已核证调研合成后，业界执行期收敛为一个骨架：**计划门进、事件流折叠直播、显式状态机（等人与卡住皆一等态）、diff+commit+会话日志三件套互链可查、介入=排队/转向/暂停/接管梯度、AI 自认完成≠人验收准出**。性价比最高的三件：①WP 执行详情页多区聚合（Qoder 六区，四区数据源 skyaxis 已有）；②声明块扩键成结构化交付自述+验证证据+commit 锚定（协议通道已有，不动宿主）；③chips 状态枚举扩「等待输入/受阻/失败」+「等谁」两态分离。意义：多数模式可插件侧落地；业界空白（需求级 WP 编排、账本锚定验收、跨会话本地持久、任务书软协议）恰是 skyaxis 已有资产可超车处。

### 3.1 六轴模式地图

#### 3.1.1 执行界面形态

- 谱系：①终端单流直播——claude-code CLI（todo 常驻区+subagent 面板+/diff 侧挂面板+PR 徽章）、plandex TUI（per-file chip 流+完成后 review 热键菜单）、amp CLI（2026-08 砍侧栏收敛线程单一形态）；②IDE 内嵌——Kiro（tasks.md 文件本身获得任务执行界面+SPECS 区）、CodeBuddy（三栏：任务列表/过程流/产物-文件-变更-预览常驻区）、Trae（聊天流+终端/预览面板）、通义灵码（工具调用内联 diff、命令前置展示）；③Web 任务页——jules（中央活动流+右侧可拖宽/全屏 diff 编辑器双栏）、devin（对话+计划+机器三层，Changes/PR/Terminal/Tasks tab 族）、copilot（session log 与 PR Overview/Files changed 并列成 tab）、cursor（Agents Window/Web/Slack/iOS 五表面同一后端同构）、codex（transcript+goal 进度行常驻+review pane 五档 scope）；④零自有 UI 寄生宿主——Spec Kit（17+ 宿主聊天窗+repo markdown 工件+handoffs 按钮）、BMAD（命令+plan frontmatter 板列投影）。
- 主流：执行页=「活动流 × diff」双核并排；一份状态多处投影（copilot 全局面板→仓库 tab→issue pill 三层嵌入；cursor 跨设备收件箱；devin Linear/Jira/Slack 镜像）；密度管理靠折叠/分组/降噪（amp Less Noise、copilot 相似工具分组+子代理折叠 HUD、devin 按计划步骤折叠）。
- 最佳实践：jules 双栏（diff 内直渲染截图、stacked 多文件纵堆）；Qoder Quest 六区聚合（状态徽章/Spec/Plan 清单/Activity/Diff/批注）；copilot 直播降噪（每工具专属图标、bash 全透明、文件改动内嵌一键展开 diff、token+时长常驻）；copilot 过程与结果同页（日志与 PR diff 并列）；qoder review→commit→push 收进任务窗口。

#### 3.1.2 状态模型

- 谱系：显式枚举机——copilot 八态（queued/in_progress/completed/failed/idle/waiting_for_user/timed_out/cancelled，REST 官方枚举）、jules 九值（AWAITING_PLAN_APPROVAL 与 AWAITING_USER_FEEDBACK 分离）、openhands 六态（idle/running/waiting_for_confirmation/finished/error/stuck，API 逐字）、Qoder 六态、CodeBuddy 六态（含等待输入）、cursor 双层（agent ACTIVE/IDLE/ARCHIVED × run CREATING/RUNNING→FINISHED/ERROR/CANCELLED/EXPIRED）、claude-code agent view 六态+Projects 六组、devin API 九态（挂起/恢复三段式）、plandex 两层（流状态×产出 pending→applied/rejected）、codex pet 四态角标（Running/Needs input/Ready/Blocked）+Activity 三分类；拼装式无全局表——amp（工作/空闲、orb 运行态、成本、排队态等正交指示器）；文件化——BMAD plan.status 七态映射板列、Kiro tasks.md 两态推进、Spec Kit 命令级状态机（implement→converge）。
- 主流：骨架收敛「排队→执行→（等待人）→终态四分支」；「等人」显式建模；迁移事件驱动、UI 是投影。
- 最佳实践：cursor 双层解耦（资源决策挂 agent、成败细节挂 run，可恢复错误 agent 层仍 IDLE）；jules 等人两态分离（放行机制不同：定时器自动批 vs 通知唤人）；openhands finished 是 advisory（Stop hook 可撤销自认完成，full_state 快照才权威）；卡住是一等态（openhands stuck detector 五模式默认开启、codex Blocked 角标、devin blocked+Waiting 与故障卡住刻意区分）；jules 状态是不可变事件流的折叠投影（官方明言可 reconstruct）；BMAD built≠done（agent 终态止步 built，done 永远人/orchestrator 标）。

#### 3.1.3 进度跟踪

- 主流：**15 产品无一家做百分比/ETA/burn-down**——进度锚定真实事件（todo 翻态、diff 累计、commit 增量、测试结果、裁决轮次）。
- 最佳实践：devin 计划骨架+步骤归组（shell/编辑/浏览器动作全挂计划步骤下，三面呈现+同步工单系统）；cursor 回合收口（end-of-turn summary+Changes「只看本回合改动」）；Kiro Sync Files 对账动词（扫码库补标已完成任务，账追平现实）；jules 终局四元组（Files changed/runtime/LOC/branch+commit msg）；Spec Kit converge 量化自检（Findings 表按 gap-type×severity 分桶计数）。

#### 3.1.4 结果可查性

- 谱系：diff 中心（copilot 日志内一键展开、cursor 词级高亮+嵌入编辑器、jules 堆叠+渲染截图、claude-code /diff 侧挂+按轮视图）；可寻址交付（cursor 自动分支 cursor/…+git.branches[]{repoUrl,branch,prUrl}+autoCreatePR、copilot draft PR 交接、amp Ship 推送+PR 回贴、jules Publish/WIP 中途导出）；commit↔过程互链（copilot commit 内嵌 Agent-Logs-Url trailer+co-author+Verified、amp Amp-Thread-ID trailer+URL 加 .md 直读）；会话档案化（copilot 归档不可删+Chat 自然语言查档、cursor transcript MCP 按 source/status/改动/PR 过滤、jules Activity 不可变+游标增量、amp Markdown/JSON 导出）；快照/回滚（claude-code /rewind 双轨：代码/对话独立恢复+每 prompt 自动检查点、kiro checkpoint：Restore 同时回滚文件与上下文、codex 任务前后 git checkpoint、plandex 每动作一版本+rewind+branch、openhands Branch from here/fork 源不可变）；证据附件（cursor artifacts 截图/视频/日志随 PR「不必 checkout 即可验证」、devin 主动提交截图/录屏 proof of testing+浏览器录像回放、jules media 挂事件）；结构化锚定（BMAD baseline_revision commit 区间+Auto Run Result 五段+deferred findings 机器可读审查输出）；事后分析（devin Session Insights：四指标卡+色彩编码问题时间线+改进提示词一键开新会话+知识双向归因）。
- 主流：结果=「diff+commit+会话日志」三件套互链；交付默认可寻址；产物停在等人审的中间态（draft PR/pending/built）。
- 最佳实践：commit↔会话永久互链（copilot/amp trailer）；BMAD 区间锚定机械圈定每票 diff；plandex 沙盒 pending changes（产物不直写项目文件，diff→reject/apply 收口——15 产品唯一，主流直写+git 兜底）；devin 步骤组 scoped diff（点 +N/-M 打开只含该步骤变更的 diff）。

#### 3.1.5 介入点

- 谱系：①消息梯度——cursor 三速动词（排队 Enter/转向 Send now 在下一工具调用边界送达/取消=终态）+409 占线；amp 三级（默认 steer 当前步边界/显式排队等 turn/Esc Esc 强停，Ship 等内置动作恒排队）；claude-code（执行中输入即排队灰显、Ctrl+Enter 立即、Up 收回重编）；copilot（「当前工具调用完成后生效」）；jules（任意时点 chat 可触发 replan）；codex（instant_interrupt 不等 turn 结束）；②暂停不销毁——devin（stop=睡眠 14 天可恢复、归档连子会话睡眠有警告）、jules（PAUSED 保位）、openhands（pause/resume+goal interrupted/resume）、amp（orb 睡眠零成本数周一条消息唤醒）、copilot（Stop session 保留已推 commit）；③审批/确认——devin 审批卡文化（计划 30 秒输入窗/部署/MCP/插件/子会话批次全有卡+置信度门黄红停）；jules 计划门三模式（人工/定时自动/API 开关+Planning Critic 兜底）；plandex autonomy 五档矩阵+missing-file 全屏三选一；codex 权限三档+auto-review 拒绝三句语义+断路器；openhands 风险分级×阈值（UNKNOWN 默认要确认）；claude-code 权限微介入（批一次/存规则/带评论批准）；④硬接管——devin（stop 后完整 VSCode+恢复时告知 AI 你改了什么）、cursor（远程桌面接管 VM）、copilot（Open in VS Code/Continue in CLI）、kiro/openhands（VS Code tab）、amp（共享 tmux+Desktop 接管）；⑤侧问——claude-code /btw、devin side chat /btw（只读带全上下文）、codex /side、cursor /side；⑥打回——qoder 逐文件 Approve/Request Changes、plandex reject 精确到单文件、Trae 项级重做、claude-code diff 行内评论打包下一条消息、BMAD 分层打回（代码错回计划、计划错因目标错回意图层）；⑦事后——copilot Fix with Copilot 家族（评审评论批量/CI 失败/冲突一键再委派）、spec-kit converge 收敛循环。
- 主流：介入是动词族；「不打断在飞工作」是排队/转向共同约束；梯度从只读到硬接管全覆盖且不必杀会话。
- 最佳实践：三速动词全部定义在系统声明的安全边界上（cursor）；四档梯度不杀会话（devin）；amp「Steer, Don't Queue」默认+CI 事件消息也能 steer；Spec Kit 勾选所有权分面（tasks.md 归执行 agent、checklists 归评审者、「implementation must not silently self-approve」）；qoder 批注位置锚点（Spec/代码/Diff 三处选中打批注直达 AI+自动标已处理）；Spec Kit implement 只读门（checklist 计数表，有未勾选即 STOP 问 yes/no）。

#### 3.1.6 进出门槛

- 谱系：入口触发——issue 指派（copilot 总开 PR、jules 打标签）、Slack/IM（devin/cursor/copilot）、定时与事件自动化（devin Scheduled/Automations、jules Suggested/Scheduled、cursor Automations、amp automations+webhook+orb spawner、codex Scheduled）、API/CLI 全员。计划门——cursor/codex/claude-code Plan Mode（提计划人批才动手）、jules AWAITING_PLAN_APPROVAL、devin 初始计划确认、qoder Spec 确认门、CodeBuddy/Trae 计划/阶段确认门、kiro 三阶段逐段审批、spec-kit --require-tasks、BMAD READY FOR DEVELOPMENT 门；例外：plandex 无计划批准门（硬门只有 context 相关三个）、amp 无计划门（信任=环境隔离+廉价撤销+规则引擎）。准出——copilot draft PR+发起人加 reviewer（三道人审门：独立审批计数/workflow 白名单/内置验证默认开）；独立裁决者（claude-code /goal 小模型每 turn 三裁、openhands judge LLM 审计证据「不能仅靠声称成功」、jules Planning Critic）；可配置收尾（amp Ship：commit→rebase→全量测试→推送→归档，护栏=实质冲突回问/测试仅基线同败可忽略）；收敛循环（spec-kit converge 直至 tasks.md 字节不动）；BMAD built≠done 人标；验证判据（Trae 测试全绿、amp definition of done）。失败/卡住——copilot 59 分钟硬上限+setup 失败降级继续；jules 瞬时错误静默重试；CodeBuddy 测试失败自动反思修复；plandex 失败四选一菜单（重试一次/升全自动/回滚退出/带病通过退出）；codex 断路器（3 连拒或 50 窗 10 拒中断）；BMAD blocked 十一枚举+blocked_at/reason+同票后续派发全停；cursor CI 自动修 10 次封顶+人一出手（推 commit/发消息）就让位。
- 主流：**计划门是标配（形态可配置：每阶段人批↔API 开关）**；完成≠合并/验收，准出权在人；失败显式建模且有低成本重试（unassign/reassign、rerun、retry 按钮）。
- 最佳实践：BMAD「Build Auto never moves a ticket to done」；spec-kit「completion claims are not evidence」（converge 无视勾选重验代码现状）；copilot 准出=交接而非完成；plandex 失败是分支选择不是终态（「升级授权」选项出现在证明需要的时刻）；codex 断路器与 cursor 让位规则（人机互斥显式写死）。

### 3.2 可移植模式目录

按对五目标〔执行显性化/状态可见/结果可查/进度可跟踪/人类可介入〕的贡献降序编号。

- **P1 WP 执行详情页六区聚合**——把黑盒期拆成六个正交可查面。证据：Qoder Quest 六区（状态徽章/Spec/Plan 清单/Activity/Diff/批注）；devin 驾驶舱（对话+计划+机器）。适配：状态区=chips 扩展（P5）；Spec 区=账本 criteria；Plan 区=已批准计划文档（账本已嵌）；Activity 区=宿主事件流折叠（P7/P8 数据）；Diff 区=工作区 git diff（P3 锚定）+声明产物清单；批注区（P14）。四区数据源已有，缺聚合呈现面；面向「离开再回来」设计。成本：中。目标：显性化/可见/可查/进度四项。
- **P2 声明块扩展为结构化交付自述**——会话收尾回传从自由 yaml 升级为固定段落自述。证据：BMAD Auto Run Result 五段（摘要/改动文件/发现分解/已做验证/残留风险）；codex done 强制附 Outcome/Constraints/Verification；jules 终局四元组。适配：declare 冻结契约扩可选键，验收面按段渲染；与 0012 declare 形态同路数。成本：低-中。目标：可查+显性化。
- **P3 baseline commit 区间锚定**——批准计划时记 baseline commit、declare 时记 head，WP 的 diff/文件清单可机械圈定。证据：BMAD baseline_revision..<下票 baseline>。适配：单人本地 git 现成；账本已有 docHash 锚定先例（planBaseline）平移即可。成本：低。目标：可查。
- **P4 验证证据门**——自报完成必须附验证证据（跑了什么命令/什么结果），无证据不能进待验收。证据：copilot 准出=交接（内置验证默认开）+domestic（Trae 测试全绿=完成判据，官方文档唯一写明）；amp「信任不是感觉，是测试套件通过」。适配：declare 扩「验证证据」键+任务书输出约定加一段；验收从「读声明」升级为「先看证据再看 diff」。成本：低。目标：可查+准出。
- **P5 WP 状态枚举扩展（等待输入/受阻/失败）**——把「卡住」建成一等态。证据：codex pet 四态（含 Blocked）；openhands stuck/error 显式终态；CodeBuddy「等待输入」态有明确恢复动作。适配：chips 三态（运行/空闲/待输入）扩枚举，状态进账本、UI 投影；受阻/失败由声明块披露或事件流超时推导。成本：低。目标：可见。
- **P6 等人两态分离**——「待计划批准」与「待澄清输入」是两个态，放行机制不同。证据：jules AWAITING_PLAN_APPROVAL vs AWAITING_USER_FEEDBACK。适配：账本层把 WP 级「等谁」建为两显式态，状态语义从「会话在干嘛」升到「工作包在等谁」。成本：低。目标：可见+介入。
- **P7 一句话活动摘要/live chip**——「正在读 X/正在跑 Y」常驻卡面。证据：openhands live activity chip（当前未完成动作短标签）；claude-code agent view 行摘要（15s 节流+轮末重写）。适配：插件订阅绑定会话事件流，规则提取「动词+对象」起步，后续再上小模型归纳。成本：低-中。目标：显性化。
- **P8 生命周期事件链锚点**——投递→拾取→首个动作发生三锚点，填黑盒前半段。证据：copilot timeline 事件链（👀 已收到→started work 带 View session→完成请求 review）。适配：账本记投递/开跑/首动作迁移事件（事件枚举+推断器在插件侧）。成本：低。目标：显性化+可见。
- **P9 「需要你」收件箱/状态分组看板**——多 WP 并行时按「谁的球在我这」分组聚合。证据：claude-code agent view 六态分组+Projects Overview 六组+tab 标题计数；codex Activity 三分类（unread/running/waiting for your response）+Ctrl+Alt+U 直达。适配：看板五列重组语义分组+跨需求收件箱视图；数据全在插件 store，不依赖宿主。成本：低。目标：可见。
- **P10 计划骨架+步骤归组**——进度是计划树的执行投影，事件挂到步骤下。证据：devin（plan todo 常驻，shell/编辑/浏览器动作全挂计划步骤，Progress/Detailed View/Tasks 三面+同步 Linear/Slack）。适配：已批准计划文档生成时带步骤标记（AI 单写者可控，最低）；卡面「当前步骤 x/y」；事件归组可先时间窗启发式。成本：中。目标：进度+显性化。
- **P11 回合收口+Last-turn diff 边界**——每回合结束出摘要与本回合变更集。证据：cursor end-of-turn summary+Changes「只看本回合改动」；codex review pane Last turn scope。适配：declare 回传天然是回合边界（每次 declare=一个 turn 产出）；「最近一次回传的变更集」审阅面配 P3 锚定。成本：低-中。目标：进度+可查。
- **P12 三速介入动词（排队/转向/取消）**——介入全部定义在安全边界上。证据：cursor（排队=任务边界/转向=下一工具调用边界/取消=终态，409 占线）；amp 三级（steer 默认/排队/强停）；claude-code（排队灰显+立即发送+收回重编）。适配：steering 草稿箱（WP 卡输入框）→投递绑定会话；排队/取消先行，转向依赖宿主注入时机；无 API 则降级复制面。成本：中（依赖宿主消息 API）。目标：介入。
- **P13 勾选所有权分面+built≠done 不变式**——机器可建不可收，制度化。证据：Spec Kit（tasks.md 勾选归执行 agent、checklists 归评审者、禁静默自批）；BMAD（Build Auto never moves to done）。适配：declare 回传只能推进到待验收、永不自动推已验收——把既有手动验收从约定升为账本不变式+词典措辞；与 0015 PRD 勾选退役方向一致。成本：低。目标：介入（制度层）。
- **P14 批注指向性反馈通道**——选中内容打批注直达 AI，位置天然带锚点。证据：qoder（Spec/代码/Diff 三处批注+修改后自动标已处理）；claude-code diff 行内评论随下一条消息打包（带 file:line）。适配：WP 详情页对计划行/diff 行打批注→插件拼装追加任务书→复用 SOW 投递通道；批注锚点记账本。成本：低。目标：介入。
- **P15 stuck detector 插件侧启发式**——卡住可检测而非沉默烧钱。证据：openhands 五模式默认开启（同动作-同观察重复 4+/同错误 3+/独白 3+/乒乓 6+/上下文错误），语义级比对忽略时间戳。适配：对绑定会话事件流滑窗统计，命中即 WP 置「疑似卡住」+提示介入；纯插件侧可做。成本：低-中。目标：可见+介入。
- **P16 checkpoint/rewind**——投递时锚定快照，验收不过可回滚到 WP 起点。证据：claude-code /rewind 双轨（代码/对话独立恢复，每 prompt 自动检查点）；kiro checkpoint（Restore 同滚文件与上下文）；codex 任务前后 git checkpoint；plandex 每动作一版本。适配：结合 planBaseline 哈希锚定先例打 git tag；会话轨不可恢复则降维为「重投任务书」语义（等价重开轮）。成本：中。目标：介入+可查。
- **P17 Sync Files 对账动词**——对照工作区实际状态与账本勾选，不符即诚实披露而非静默改账。证据：Kiro Sync Files（扫码库补标已完成任务+需求变更后重映射）。适配：与账本 stale 双臂/六臂（0009/0012）同构升级为「对账」按钮；对账结果走追加/披露不改写历史。成本：中。目标：进度+账实一致。
- **P18 converge 收敛循环+gap 分类学**——以基线为唯一意图源评估代码现状，「完成声明不是证据」。证据：Spec Kit converge（四类 gap：missing/partial/contradicts/unrequested×四级 severity，每条带 source-ref 与 evidence，append-only，Converged=tasks 字节不动才算干净）。适配：④评审 agent 直接复用此语义——对照需求基线+WP 边界评估现状，findings 块回传契约（0012 冻结）天然承载 gap-type/severity/证据字段。成本：中。目标：可查。
- **P19 独立裁决者预审**——准出前由独立小会话对照 criteria 裁决，缺口回灌。证据：openhands /goal（judge LLM 每轮审计 transcript 权威证据，missing 回灌，轮次上限 capped）；claude-code /goal（小快模型每 turn 三裁并给理由）；jules Planning Critic（自动批准的计划由第二 agent 前置严审）。适配：待验收前插机器预审（judge=另开会话或独立调用查工作区证据），missing 生成补充任务书回灌；缓解④评审负担。成本：中-高。目标：可查+准出。
- **P20 失败分支菜单**——失败是分支选择不是终态。证据：plandex 四选一（重试一次/升全自动/回滚退出/带病通过退出）；BMAD intent gap 补丁保留（卡死尝试存 patch 供人裁定，正确则 git apply 续审）。适配：验证失败给三路：重投修复任务书（复用 SOW 通道+revision 戳先例）/回滚到锚定 commit/人工接管后手动销账；补丁保留与「实物交接优于状态摘要」（0008 拍板）同向。成本：中。目标：介入。
- **P21 Ship 式收尾任务书**——「收尾」按钮=投递固定收尾任务书（跑验证/自检/commit 建议/收尾声明块）。证据：amp Ship（commit→rebase→全量测试→推送→归档，护栏编译进流程；Ship Behavior 三选项目级预配）。适配：与「插件不是执行器」同构——护栏（测试仅基线同败可忽略）编译进任务书措辞+账本校验，不改宿主。成本：中。目标：可查+准出。
- **P22 autonomy 档位化**——审批强度是预置档位不是散装开关。证据：plandex 五档矩阵（none/basic/plus/semi/full 决定全链哪些迁移自动化）；codex 三档一键（三轴正交、UI 收敛）；jules 计划门三模式。适配：每 WP「每验证点停/整 WP 自动+抽检验收」档位写在 WP 或需求级；spec-kit staged implement（大件圈段执行每段验证）可作任务书措辞先行。成本：低。目标：介入。
- **P23 侧问只读会话**——不进历史、不打断主执行的旁路提问。证据：claude-code /btw（可 fork 成后台 subagent）；devin side chat /btw（只读、带该时点前全部上下文、主会话继续跑）。适配：新开轻会话引用同工作区只读提问（宿主多会话能力模拟）；无协议要求。成本：低。目标：介入。
- **P24 通知收束+未读徽标**——终态（尤其出错与完成）即提醒验收。证据：codex Activity Ctrl+Alt+U+Mark all as read；cursor 每回合推送+未读徽标+Live Activities〔Live Activities 上限 8 为官方移动端口径〕。适配：单人本地简化为宿主内徽标+Windows 系统通知。成本：低。目标：可见。
- **P25 Session Insights 事后体检**——WP 收口后统计反哺上游。证据：devin Insights（ACU 用量/用户消息数/尺寸分级/任务分类四指标卡；L/XL 标记不健康劝拆；改进提示词一键开新会话）。适配：token/时长/重试/修正次数本地化统计；「本 WP 执行异常重，建议回拆或回改任务书」回写沉淀阶段；规则统计版先行。成本：中（规则版低）。目标：沉淀（⑤目标外围）。

### 3.3 反向结论（业界普遍不做什么）

1. **无人做百分比/ETA/预估进度**——15 产品 verified 全无；进度=真实事件投影（todo 翻态/diff/commit/测试/裁决）；cursor durationMs 仅终态事后计算。原因：agent 任务时长方差极大，假精度误导等待决策。
2. **趋势是删清单不是加清单**——amp 2026-01 整体移除 todo（官方理由：模型已能自管、写清单费 token 费 UI 空间）；claude-code 2026 新模型默认不带清单工具。给人的密度转向「一句话摘要+回合收口+diff 累计」。启示：todo 回报若做，定位是「对账物」（P17）不是「直播物」。
3. **无人自动合并/自动收票**——AI 终点永远是自认完成+证据+请求人审：copilot 发起人 approve 不计数；BMAD done 永远人标；spec-kit 禁自批；jules「完成≠合入」。原因：验收是责任行为。
4. **主流不做逐动作一律审批弹窗**——已越过该阶段：分级×阈值（openhands）、档位化（plandex/codex）、分类器代人批（claude-code/codex auto-review）、置信度门（devin）。审批强度是产品参数。
5. **主流不做全粒度实时直播给人盯**——折叠/分组/降噪；amp「有耐心盯每步=缰绳太短」；devin Detailed View 定位是 debug 工具非默认视图。直播价值在事后可查不在实时围观。
6. **主流不做沙盒中间层**——plandex pending changes 是 15 产品唯一，其余直写+git 兜底（amp：git 让撤销成本趋零）。skyaxis 非执行器更不可能，降维=锚定+对账（P3/P17）。
7. **终止不销毁**——stop/cancel 之外全部有暂停/睡眠/可恢复态（devin 睡眠 14 天、amp orb 睡数周、jules PAUSED 保位、openhands goal interrupted 可 resume）；取消是显式选择。原因：长任务重启成本高。
8. **状态不自成一源**——真源在事件流/文件/frontmatter，UI 是投影（jules 可 reconstruct、BMAD frontmatter 板列、Kiro tasks.md）；CodeBuddy 曾修「UI 虚假显示执行中」缺陷〔该 release note 条目未经全文核对，仅方向参考〕——状态与真实执行解耦是各家踩过的坑。
9. **无人做需求级执行编排**——编排单位全部是会话/线程/任务/票，需求只是触发源（issue/label）；无「需求基线→WP 依赖闭包→分波多会话→逐 WP 验收」的产品（详见 §5-1）。

### 3.4 与 skyaxis 约束的冲突预警

skyaxis 约束：C1 工作台非执行器（无执行拦截权/无沙盒/无进程控制，能力上限=宿主 API）；C2 四权在用户（提议/登记/批准/验收分离，AI 不得自批）；C3 Non-Goals 不代写用户仓库/不代执行 git 收尾；C4 账本真源+append-only 不改写历史；C5 单人本地（无云/无多人/无计费）；C6 宿主与 wire 演进成本高（历史轮偏好零改动）。

1. **自动触发/自动编排 vs C1+C2**：devin Automations/Scheduled、jules Scheduled/Suggested、cursor Automations、amp webhook/orb spawner、codex Scheduled 全是事件到自动开工会，绕过「用户发起任务书」之权。→ 降维为「建议投递」卡（条件满足时看板提示、人点才算投递）；拒绝无人值守自动执行。
2. **权限代答/自动批准 vs C2**：claude-code auto 分类器、codex auto-review+断路器、jules 定时自动批准+Planner Critic 代审——「AI 代人批」任何形态都撞四权。→ 降维：Critic/judge（P19）只产出「建议+理由」回填看板，批准动作永远人点；jules 报告自评「单人本地定时器价值低，该借的是 Critic 而非定时器」。
3. **auto-commit/push/merge vs C3**：amp Ship 推 trunk、plandex auto-commit、qoder commit/push 收口、copilot merge box。→ 降维为引导级：验收通过后建议 commit message+WP 关联信息，open-in-app（0014）打开工作区由人执行；插件不代跑 git。
4. **CI 自动修复循环 vs C1+C2**：copilot auto-fix、jules CI Fixer、cursor CI 订阅自动 follow-up。→ 降维：只读拉 check 状态挂 WP 卡作准出信号（企业后端 PR/CI 必有，价值真实）+「一键投递修复任务书」；拒绝事件到自动续跑。
5. **运行中消息注入/终止会话 vs C1**：steer/转向/打断全依赖宿主暴露会话消息 API 与时机。→ 降级阶梯：有 API 则 P12 全量；只有普通发送则先落一档；全无则 steering 草稿箱退化为复制面+引导，并在 unverified 项记宿主能力缺口（openhands 报告同款纪律）。
6. **沙盒 pending changes（plandex）vs C1+C3**：AI 直写工作区、插件无沙盒。→ 拒移植硬沙盒；降维=baseline 锚定+diff 对账+checkpoint tag（P3/P16）。
7. **多表面推送/mobile/IM 镜像 vs C5**：cursor iOS、devin Slack/Jira/Teams 镜像、copilot mobile。→ 拒移植；降维：宿主内徽标+Windows 系统通知（P24）。看板卡本身即 devin「工单镜像」的插件自有一亩三分地版（devin 报告 portability 原话）。
8. **计量/配额 vs C5**：devin ACU、jules 任务配额（触顶只禁新不禁旧的降级纪律可取）、copilot credits。→ 降维：宿主事件流若有 usage/token 字段则披露为「消耗可见」；无则不做，不造假计量。
9. **同题并行竞态 vs C4**：jules --parallel 5 路、cursor /best-of-n——账本 WP 状态机为单人单会话绑定设计，多会话竞态需状态机扩展。→ 拒首期（jules 报告自评「不建议首期」）；远期探索。
10. **worktree 磁盘管理 vs 0011 CJK 路径教训+C5**：cursor 装配脚本+机器级配额自动清理。→ 降维：需并行时先跨 repo WP 有限试点；拒绝自动建树自动清理。
11. **风险分级执行前拦截 vs C1**：openhands ConfirmRisky/analyzer 是执行器一手权限，插件拿不到。→ 降维：任务书输出约定要求高危动作前置声明+事后声明块命令清单按等级排序供人复核（把「批什么」变「复核什么」）；若做审批卡须诚实记档为软门（无强制力，靠任务书纪律+事后对账，与 Devin 宿主级强制不同）。

### 3.5 差异化机会（业界空白=skyaxis 可超车处）

1. **需求级 WP 驱动多会话编排**——业界编排单位=会话/任务/票，需求只是触发源；devin Dynamic Workflows 最接近但是 phase/agent 脚本+ACU 视角、无需求锚定；BMAD ticket 树最接近但是纯文件形态、无会话绑定；copilot/jules 单任务单会话。skyaxis 已有 WP dependsOn 依赖闭包+看板+会话绑定，「拆分产物驱动执行编排、就绪 WP 分波开并行 dev 会话」业界无人做（Kiro Run all Tasks 波次并行有依赖分波思想但同仓冲突面大，先跨 repo 试点）。
2. **账本锚定验收链**——业界验收锚定止于 commit/diff/CI（BMAD baseline_revision 最深也只到 commit 区间）；无「需求基线 docHash→planBaseline→声明块→逐条 criteria 勾验→上游 stale 六臂传播」全链追溯。skyaxis 已有 docHash 锚定+criteria 真源+stale 双臂/六臂，补 P3/P4 即闭环。
3. **跨会话状态持久在本地账本**——业界状态持久=云服务端能力（jules Activity 不可变、重启可恢复是服务器侧）；本地单人语境无人有 append-only 账本作执行期事件容器。skyaxis 有 splitProposals 容器先例，可落 WP 级 activity 容器（originator 三源、状态是投影、jules 同构语义）。
4. **任务书软协议**——业界显性化靠宿主 hook/UI 按钮/API；无「markdown 任务书输出约定+结构化声明块回传」的纯协议通路。skyaxis 五段 SOW+declare 冻结契约已有，P2/P4/P11 全走此路——不动宿主达成业界同级显性化，是插件语境独创通路。
5. **评审/开发两权分离制度化**——spec-kit 勾选所有权分面靠模板纪律；skyaxis 可在账本+协议层硬约束（P13：declare 永不推进已验收列）+词典措辞，把纪律变制度。
6. **WP 级「等谁」语义**——jules 等人两态是会话级；skyaxis 可把待计划批准/待澄清/待评审/待验收建为 WP 级账本态（P6），看板即答案，业界无 WP 粒度对应物。
7. **执行期体检反哺上游**——devin Insights「改进提示词一键开新会话」是会话级；skyaxis 可做 WP 级「执行异常重→建议回拆/回改任务书」回写沉淀阶段（P25），闭环到需求与拆分层，业界无对应物。

## 4. 设计原则

- **P1′ 账本真源不动**：WP 七态状态机与四权面零改动；新持久数据只加三类——用户动作审计戳（`wp.startedAt`）、append-only 导入锚（`wp.declarations[]`）、host 铸待裁容器（`record.devDeclares`，按 WP 键控、文本不入容器只持哈希）。
- **P2′ 显性化=只读投影**：执行过程的一切呈现（折叠直播/活动摘要/计量/角标/「等谁」分组）是读时投影，一律不入账本；拉不到就诚实缺席（行隐藏/「截至上次翻转」标注），绝不假装。
- **P3′ 零假进度**（业界反向结论全票，§3.3）：无百分比/ETA/预估/插值进度条；进度只锚真实事件（声明轮次/计划版本/验收轮次/工具调用/真实计量）。零假进度扩展为**零假「等谁」**——不确定态一律落「存疑」并披露推导依据。
- **P4′ 事件驱动不轮询**：完成信号=注册层 watcher 观测 running→idle 翻转沿；过程视图=翻转/开视图/手动触发 digest 按需拉取；无后台常驻轮询（放宽须 D7 档位与门槛数据）。
- **P5′ 降级=最坏现状**：每处新能力配降级路径（§13）——宿主能力缺席/路由改名/老版宿主下回退到既有行为而非阻塞（0014 D3 先例）。
- **P6′ 复用先例不造第二套**：watcher（analysis/split 先例）、declare 两段式导入、待裁容器（splitProposals 同构）、task-graph 事件解析、waiting-tracker、delivery 投递通道全部复用或同构升级；`execution-fold` 与 task-graph 解析栈的每列关系落对账表（P0），杜绝第二套解析纪律与第四套状态词汇。

## 5. 终案设计：三层一引擎（定稿修订版）

> 白话摘要——**场景**：拆分批准后 WP 交给 AI 会话开发，用户要看得见（AI 在干嘛）、跟得住（多 WP 并行时谁的球在我这）、查得了（做成了什么、证据在哪）、插得进手（排队补话/跳转应答）。**答案**：三层一引擎——看板卡升级为「WP 态×会话态」双层实时卡；新增 WP 执行视图作过程层（digest 尾窗→客户端折叠直播+真实计量+交付自述）；末端声明块扩键→devDeclare **按 WP 键控**待裁容器→**注册层 watcher** 自动 seed→用户确认导入（含 commits[] 死字段激活）；S3 顶部「需要你」段**瘦身**为两组异常行（全量分组引擎留作 P4 跨需求版资产）。**意义**：五目标唯一实质全覆盖且盘子压回可落地量级（P0 侦察刀+显式砍刀保险）；三份评审 14 项 graft 全部落位（1 项部分拒绝有实证）；账本状态机零改动、四权零变化、每处新能力有降级路径（最坏=现状）；全部机制复用 watcher/declare/task-graph/waiting-tracker/splitProposals/delivery 先例。定稿轮按三份攻击 findings 修订 13 处（§5 处置表）。

### 5.0 骨架裁决与 graft 处置

**三镜头 best 分歧**：governance=board、feasibility=live、persona=live。**裁决=live 分层骨架**（看板摘要层 / WP 执行视图过程层 / 声明自述末端），理由三条：

1. 2/3 镜头选 live，分歧本质是「返工风险 vs 目标覆盖」的权衡而非红线违规——governance 对 live 的两处扣分（介动词分期前置未决追认、治理暴露面最宽）均可结构性修复：介动词全部移出默认分期（D2 追认门控、默认降 A 档）并在 §12 逐条枚举 wire 账目。
2. governance 自身 graft 清单把 live 核心件（digest/declarations 锚/commits 容器/介动词族）全部拉进 board——骨架选 board 也会长成 live 的形状；不如以 live 分层为骨、board 红线自查与 inbox 分组引擎为肉，暴露面更显式可控。
3. §2.5 最大空白是「执行中的过程可见性」：board 角方案自认不正面呈现执行过程，只有 live 正面击穿；五目标覆盖三镜头评分 live 唯一全达。P3b 置台直播后置（修订 #10）不改变裁决——过程层承重件是执行视图（digest 尾窗+折叠），Tier A 直播是增强件非承重件。

**包络勘误承接**（三镜头独立复核一致，定稿轮二次实证）：
- ① SDK SessionFace 类型在场 `prompt(content,'queue'|'steer')`/`updateQueue`/`cancel()`（session.d.ts:146-171；cancel 头注「Host preserves pending inbox work」背书）。类型在场≠运行时已验证——介动词一律探针+诚实失败+深链降级，且须 D2 追认才立项（默认 A 档=仅深链）。
- ② 「会话内容不可订阅」精确边界=事件窗口仅置台开；task-graph connector 置台订阅先例（connector.ts:195-220）——供 P4 候选 P3b 引用。
- ③ SessionSummary.completed 是 manager-owned live fact（快照序列化不保证携带）。完成信号不依赖该字段——主信号=注册层 watcher 的 running→idle 边沿 seed+devDeclare 容器（账本锚定、跨刷新稳定）；completed/updatedAt 仅到场则用的辅助投影（缺席=不显示）。

## 7. 功能职责

**管**（全部是「读+呈现+转交」，聚合器本色）：投递与绑定的台账；执行过程折叠直播与真实计量（尾窗+客户端折叠）；「需要你」异常分组（两组）与直达+完成信号注册层收取；声明收取预览（dryRun 零写）与用户确认导入（含 commits 确认）；介入动词的用户点击转交（默认仅深链，排队类 D2 追认后才立项）；验收与返工；执行档案（计划版本链/声明历史/验收历史）。

**不管**（「非执行器」再陈述，对§2.4 约束 1/2/3 与冲突预警）：
- 不自动发起/编排/定时触发任何会话（冲突预警 1 全拒）；「点火」组=建议卡，投递=create+setDraft+**用户按发送**（约束 3 人握门禁不动）。
- 不代批代答：devDeclare 只到待裁；导入/忽略/验收/推进全用户点击（约束 1）；judge/预审类只出建议行（P4 独立立项）。

## 11. 准入准出

- **开工准入**：plan-approved 严格链零改（守卫 #3）；新增 advisory 依赖就绪徽章，非门。
- **built 门**：真守卫不变（用户按钮或声明导入逐条复用，竞态 skipped 不整批拒）；验证证据=徽章非闸（D4-A：声明缺 verification 键时验收面出示「无验证证据」，stale 同款「提示权在系统、判断权在用户」）。
- **验收门**：pass/fail+必填理由+append-only 不变；验收面证据区先行；built≠done 已结构性保证（声明只能到 built、验收只能人点）——词典补「完成声明不是证据」措辞（P13 制度层，零新代码）。
- **S3→S4**：advanceStage 零守卫**不动**（约束 8 刻意口径）；唯一新增=按钮旁披露行「N 项未验收」纯提示（D5-A，与 stale 徽章同构）；任何真门=治理变更另立项。

## 15. 风险登记

1. **readSession 长会话性能**：一次全读+尾窗+lastEventCount 缓存（同 count 不重读）+P0 实测门槛先行，未过门槛不放宽频率（D7）；超门槛→执行视图落「最近一次成功折叠+时刻戳」。
2. **事件 schema 是宿主内部契约**：P0 侦察刀前置（真实分布表定列集）+对账表+防御性读取+未知事件跳过计数披露+duck-typing；diff 等字段未证→对应列整列可隐藏（不承诺）。
3. **介动词运行时未验证**：默认 A 档仅深链（现状零增量）；候选立项才探针+首用诚实失败+深链降级；绝不静默假装已发送；D2 未批不动工。
4. **completed 字段语义两面性**（勘误③）：完成信号一律容器/边沿推导，该字段仅到场则用——设计不因 SDK 快照差异而脆断。
5. **直播诱导围观**（amp「缰绳太短」教训）：P3b 后置 P4；digest 默认折叠降噪+摘要优先+「截至上次翻转」标注；价值定位**事后可查**非实时盯梢（反向结论 5）；卡面 live 行一行封顶+条件渲染不占位+15s 节流。
6. **AI 自报失真**（commits/files/evidence 均自报）：全链「未校验」标注+用户确认闸+对账动词位；hash 核验列宿主诉求 D10-③；「完成声明不是证据」入词典。
7. **watcher 误触发/重复 seed**：per-WP 槽+contentHash 幂等锚+RUNNING 关闸+one-shot（先例全套）；注册层对照 30s 节流；revision 竞态 409 自愈。
8. **零假「等谁」**：全序分组判据全可溯真源+不确定落存疑+推导依据披露+全矩阵单测；超窗判据标注客户端时钟非账本；容器前置杜绝「完成已收落存疑」。
9. **三入口动词漂移**（Modal 收取卡/执行视图/收件箱行）：同一 controller 闭包单写者，入口共用不复制（0014 先例）。
10. **治理漂移**：任何「看起来像门」的提示（证据徽章/准出披露/依赖就绪徽章）默认纯展示，D4/D5 拍板前零阻断力；介动词每过一档追认一次。
11. **requirements 页 slot**（若 D6-B）：唯一跨模块回归面——后置独立立项+需求列表测试回归。
12. **收件箱快照滞后**：无推送→时间戳常驻+写动作/焦点自愈+节流共享 demand；永不显示无时刻的状态。
13. **盘子体量与尾部刀挂账**：相对 0012 约 3-5 倍——已由砍刀（tab 计数/P3b/P3a 后置+P1c 瘦身）压回 2 倍以内；砍刀保险清单显式发布，底线四刀（P0+P1a+P1b+P2a）独立可验收，尾部刀挂账不伤主线。
