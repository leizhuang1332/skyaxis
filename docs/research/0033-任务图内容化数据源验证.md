# Research 0033 — 任务图内容化改造：数据源验证

- **日期**：2026-10-27
- **背景**：任务图 v0.4「内容化改造」（拓扑做骨架 + 内容做下钻 + 分层折叠）架构已由用户拍板（见 [ADR 0036](../decisions/0036-任务图内容化改造架构决策.md)），按 research 0002/0003 纪律「没验证到流动的数据不排期」，开工前对六个数据源开放问题逐项取证。
- **验证环境**：本仓库 node_modules（@deepseek-ai/* 0.2.1-rc.3，pnpm store 含 dsh-llm/dsh-subagent/dsh-tool-todo/dsh-tools 传递依赖）+ 宿主源码仓 `c:/Users/lorcan.lei/VSCodeProjects/deepseek-harness`（git describe = `dsh-v0.2.1-rc.3`，与本仓库依赖精确同版）。

## 白话摘要

**场景**：任务图要改造成「能看内容、有层次、可折叠」的图，但设计里六件事依赖宿主到底给不给数据——事件有没有时间戳、assistant 说了什么能不能拿到、工具调用结果和失败原因长什么样、审批问题文案在哪、subagent 是哪次调用派生的能不能查、能不能从图跳回聊天的某条消息。

**答案**：六问五正一负。**时间戳每个事件都有**（Unix epoch ms）；assistant 消息全文、逐 step 的 token 用量都在；工具调用与结果按 callId 严格配对、失败原因人类可读原文在 wire 上；审批事件带问题文案（reason）+ 工具调用关联（callId）+ 结局配对；subagent 派生虽无显式 wire 字段，但派生工具的结果文本字面含 childId，可解析成 fact 级编织边。唯一否定：**宿主没有任何「跳转到聊天某条消息」的 API**。

**意义**：时间维度（原 v0.2 欠账）直接解锁；失败原因/waiting 问题/审批文案全部可承载；subagent 编织可上探 fact 级（带防御降级链）；chat 锚点按 API 缺席定案，架构 E 切片相应收缩。内容化改造没有任何数据源阻塞项。

## 二、验证一：assistant/message —— 全量可用

`@deepseek-ai/dsh-session/lib/types/types.d.ts:331-339`（本仓库 node_modules，0.2.1-rc.3）：

```ts
'assistant/message': {
    turn: number;        // ← turn/step 显式携带，无需环境计数
    step: number;
    message: AssistantMessage;   // content: readonly ContentBlock[]
    stream: AssistantStreamRecord[];  // 紧凑原始流（回放用）
    usage?: TokenUsage;          // ← 逐 step token 记账随行
    interrupted?: true;          // 中断前缀标记
}
```

- `AssistantMessage`（dsh-llm `lib/types/message.d.ts:148-151`）：`{ role:'assistant', id, content, source:{kind:'model', provider, model} }` —— **每条 assistant 消息自带 provider/model**（比 skyaxisAgentMetrics 投影的「会话级最近一次」更细）。
- `ContentBlock` 词表（dsh-llm `lib/types/types.d.ts:44-126`）：`text` / `reasoning`（思考链文本）/ `image` / `file` / `tool-call`（模型请求的工具调用，含 name + arguments 原文）/ `tool-addition` / `tool-removal`。
- `TokenUsage`（dsh-llm `types.d.ts:160-172`）：inputTokens / outputTokens / totalTokens? / cacheReadTokens? / cacheWriteTokens?。
- 附带：`assistant/attempt`（types.d.ts:345-349）——未产出表面消息的失败/重试/取消尝试**也留痕**（内嵌流）；`llm/retry` / `llm/retry-started` 在持久化目录内（known-event-types.js:26-27）。

**结论**：B 切片「assistant 消息节点 + 明细面板」数据全量就绪；step 级耗时与 token 用量、每消息模型路由、思考链全文、失败尝试均可达。

## 三、验证二：tool 配对与错误原因 —— 全量可用

`tool/call`（types.d.ts:355-361）：`{ turn, step, callId, name, arguments }`（arguments 为模型原文 JSON 字符串，未解析）。

`tool/result`（types.d.ts:375-389）：

```ts
{
    turn: number; step: number;
    message: ToolResultMessage;   // content blocks + toolCallId + isError?
    error?: { name: string; code: string; reason?: string };  // ← 失败原因原文
    meta?: JsonValue;             // 工具私有的展示负载
}
```

- 配对：`tool/call.callId` ↔ `tool/result.message.toolCallId`（ToolResultMessage，dsh-llm `message.d.ts:153-160`）——**严格 wire 事实**，turn/step 双双显式。
- `error.reason` 注释明言 "raw user-facing reason"——失败原因不丢的承诺直接兑现；仅当 `isError: true` 才允许出现。
- `meta` 注释点名 `dsh-tool-fs` 把 result-time 上下文 diff 放这里——文件改动明细未来可直接引用（MVP 不依赖，诚实记录）。

**结论**：工具调用节点（名称/参数/结果/失败原因/耗时 call→result time 差）全部 fact 级可达。

## 四、验证三：approval —— 全量可用

`@deepseek-ai/dsh-user-approval` `lib/types/types.d.ts:27-53`（pnpm store）：

```ts
'approval/asked':  { id: ApprovalRequestId; toolName: string; callId?: ToolCallId; reason?: string }
'approval/decided': { id: ApprovalRequestId; outcome: 'allowed-once' | 'rejected' | 'cancelled' | 'unavailable' }
```

- `reason` = asker 的人类可读解释；`callId` = 被审批的那次工具调用（有则严格关联到 §三 的配对链）；`id` 与 decided 严格一对一。
- 两事件均 log-only（无 surfaceOp）但在持久化目录内（known-event-types.js:24-26）——durable 窗口照发。
- waiting 面交叉：waiting-tracker 消费的 `pendingInteractions` 与 approval/asked 同源（GUI 答复者发布），图上的 waiting 节点可下钻到 asked 的 reason 原文。

**结论**：approval 节点从「占位类型」升格为全链事实节点（问题文案 + 关联调用 + 结局）。

## 五、验证四：时间维度 —— 每个事件都有

`SessionEvent` envelope（dsh-session `types.d.ts:490-513`）：

```ts
{ type: K; seq: SessionSeq; time: number /* Unix epoch milliseconds */; data: SessionEventMap[K]; ignorable?: true }
```

`time` 在 envelope 上（types.d.ts:495），**所有**事件类型无一例外。派生量全部 fact 级：

- turn 耗时 = `turn/end.time − turn/start.time`；
- step 耗时 = `step/start`↔`step/end`；
- 工具调用耗时 = `tool/call.time`↔配对 `tool/result.time`；
- 子会话创建时间锚 = `subagent/catalog.childCreatedAt`（catalog.d.ts:21）。

**结论**：v0.1 起拖欠的「时间成本聚合」欠账在数据面全额兑付。C 切片节点耗时徽标、turn 分组时间轴全部可行。

## 六、验证五：subagent 派生上下文 —— 文案级事实，需防御链

wire 显式字段（dsh-subagent `catalog.d.ts:20-42`）：`subagent/catalog = { childId, childCreatedAt, version, mode: 'one-shot'|'continuable'|'unknown'|'external', label? }` —— **不带 callId/turn**，血缘仍靠 list 投影（现 buildSubagentGraph 路径不变）。

但宿主源码给出一条 fact 级通道（deepseek-harness `packages/subagent/tool-subagent/src/index.ts`）：

- :273 `render: (_args, value) => [{ type: 'text', text: `started subagent ${value.subagentId}` }]` —— 派生工具的**模型可见结果文本字面包含 childId**；
- :337 `return { kind: 'activation' as const, subagentId: started.childId }`；
- 派生工具名**可配置**（:366 `config.toolName ?? 'subagent'`）。

编织边的诚实降级链（D 切片实现口径）：

1. `tool/result` 文本匹配 `started subagent <id>` **且** `<id>` ∈ subagentCatalog/list byId → `fact` 级编织边（挂接到该 tool-call 活动节点）；
2. 解析失败/工具名漂移 → 同 turn 内 catalog 事件邻接 → `inferred` 级（虚线呈现）；
3. 两级都失败 → 挂 root（现状语义）。

已知脆弱点记档：匹配依赖宿主 render 文案（跨版本可能变）与可配置工具名——防御解析 + 降级链 + 文本形态回归钉，不硬编码工具名。

附带：派生工具的 `arguments`（JSON 原文）含 `prompt` 与 `description`（tool-subagent `index.ts:230-240`）——**委派的 prompt 全文可作为 delegation 边/子代理节点的下钻内容**（现仅 label 三级回退）。

## 七、验证六：chat 锚点 —— 否定结论

- `UiWorkspace.openSession(target: SessionTarget)`（deepseek-harness `packages/client/ui-workspace/src/client/navigation.ts:44`）；`SessionTarget = SessionId | SubagentAddress`（session-controller `contract/sessions.ts:22`）——**会话级，无消息级锚点**。
- 全 client 包（ui-chat/ui-conversation/ui-workspace 等）grep `revealMessage|jumpTo|scrollIntoView|focusSeq` 零命中；conversation contract 的 seq 字段均为渲染序号用途，无对外 reveal 导出。

**结论**：「从任务图节点跳回聊天对应消息」按 API 缺席定案。E 切片收缩：chat 锚点退役（诚实降级上限 = openSession 切会话 + 切 tab），E 仅剩手工位置持久化与导出候选。若未来宿主提供该能力，另行验证后回补。

## 九、对架构设计的回写（ADR 0036 已吸收）

1. **时间维度入列**：B/C 切片增加耗时徽标（turn/step/tool 三级），全 fact 级派生；
2. **assistant 消息节点携带每消息 provider/model**（dsh-llm source），与会话级 skyaxisAgentMetrics 投影并存（后者保留 root/subagent 现状）；
3. **subagent 编织三级降级链**定案（fact 文本解析 → inferred 邻接 → root 挂接）；
4. **E 切片收缩**：chat 锚点退役；
5. **文档层容忍窗口前缀截断**（hasMore 标注）。
