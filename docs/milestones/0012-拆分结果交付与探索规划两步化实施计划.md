## 刀一 数据面与通道（host 半边先行，纯函数可测）

- **protocol.ts**：`PLANNING_DOC_DIR='.skyaxis/planning'` / `SPLIT_RESULT_DIR='.skyaxis/split'` + `planningDocRelPath`/`splitResultRelPath`（uuid 守卫 + 布局冻结头注，requirementDocRelPath 同款）；GET kind 增 `'planning-doc' | 'split-result'`；mutate union 增六动作 `adoptPlan | revokePlanAdoption | bindSplitSession | seedSplit | adoptSplitProposals | dismissWorkPackageProposal`（逐个手写 guard）；`ProposedWorkPackage` wire 类型 + `PlanBaseline` wire 类型。
- **types.ts（zod 镜像）**：`PlanBaselineSchema{at, docHash, requirementDocHash?}`（子字段 REQUIRED 同 UnderstandBaseline 立场——半填基线会说谎；requirementDocHash optional 系上游无锚时缺席）；record 增 `planAdoptedAt?`/`planBaseline?`/`splitProposals?`（容器：session{sessionId,boundAt,anchor?} + seed{sessionId,contentHash,seededAt}? + workPackages: ProposedWorkPackage[]——**proposed 行无 status**，登记才铸）；`SESSION_PURPOSE_VALUES` 增 `'split'`；`SplitBaselineSchema` 增 `planningDocHash: z.string().min(1).optional()`（0008 D4 第五臂同款 conditional 写入）。
- **artifact-path.ts**：`planningDocPath`/`splitResultPath`（node:path join + uuid 再断言，analysisReportPath:99 双层防御同款）。
- **record-actions.ts**：`adoptPlan`（校验未采纳；铸 planAdoptedAt+planBaseline——docHash 由 flow 传入，动作纯函数不碰盘）/ `revokePlanAdoption`（摘戳即摘基线，键移除不是置 undefined——revokeSplitApproval 形）/ `bindSplitSession`（analysis 容器 bind 同形）/ `adoptSplitProposals{refs[]}`（splitLocked ⇒ 400 locked-split；refs 必须全在容器；按容器序 nextSequenceId 铸 id、dependsOn ref→铸 id 重写、covers 校验存在、recomputeCoveredBy；登记后行从容器移除）/ `dismissWorkPackageProposal{ref}`（手动出口）。
- **endpoint.ts**：`adoptPlanFlow`（读盘 planning-doc：ok ⇒ sha256 入 planBaseline.docHash；unarmed/missing ⇒ 无锚采纳仍成立；too-large ⇒ 413——approveUnderstandFlow 三态逐字同构；含 implicit-create 臂）；`seedSplitFlow`（容器存在且 session 匹配 ⇒ 读 split 文件 ⇒ parseDeclare ⇒ applySplitSeed：sha256 幂等（seed.contentHash 相同 ⇒ no-op）、新 hash ⇒ 替换未登记提议行 + 更新 seed；无文件 ⇒ seedMissing 诚实原因，**不回落会话链**）；GET artifactReadFlow 增两面（文件先行可读、404 诚实缺失、contentTampered vs planBaseline.docHash / splitProposals.seed.contentHash——727/746 面形制）。
- **declare-parse.ts**：`DeclareProposals` 增 `workPackages: readonly DeclareWorkPackageRow[]`；行解析（ref 须 `^WP[1-9]\d*$`、title/boundary/dependsOn(ref 数组)/parallel?/covers(C 数组)）坏行 skipped 闭枚举（bad-shape / bad-ref / unknown-criterion——covers 校验延到登记期对活账本做，解析期只验形状与自引用闭包）；**plain 骨架 declarePlainSkeleton 逐字节不动**。

## 实机验收脚本（8 步）

1. **规划任务书**：S2 [生成规划任务书] → modal 九节形态（必读基线行/无 PRD 组/无 declare 块/无 revision 戳）；可编辑+恢复生效。
2. **规划文档落盘回显**：投递 → 会话写 `.skyaxis/planning/<rid>.md` → S2 规划卡 ready（路径披露行）→ 预览 Modal 全文；篡改后预览出 tampered 警示。
3. **采纳与撤销**：[采纳规划] ack 弹窗（文档在场披露）→ 横幅+planAdoptedAt；[撤销采纳] 摘锚回未采纳态；重复采纳 400。
4. **规划失效臂**：采纳后重新整理基线文档并重定稿 → 规划卡「上游基线已变更」徽章。
5. **拆分任务书新形态**：已采纳规划 → 输入段含必读 `.skyaxis/planning/…` 行；未采纳需求 → 诚实行；输出段为文件交付 + workPackages 教学块。
6. **拆包提议回显**：投递拆分会话 → 写 `.skyaxis/split/<rid>.md`（含机器块）→ 会话空闲后 S2 提议区回显行（含一条坏 covers 行被跳过列出）。
7. **登记与硬门①**：勾选部分提议 [登记选中] → workPackages[] 落账（铸 id/依赖重写）→ 覆盖矩阵更新 → [批准拆分] 原语义走通；locked 后 [登记选中] 禁用+披露。
8. **回归**：dev/review 任务书逐字冻结；analysis/consolidate 零漂移；无工作区需求——规划采纳无锚披露+拆分提示无法自动收取（手动 [＋工作包] 路径仍可用）；徽章/stale 第五臂/看板解锁零感知。

> **实机验收已通过（用户 2026-10-16）**。验收过程驱动三处修正（均已红/绿测试落定并入本轮提交）：
> ① 拆分输入段第三态措辞——「先生成规划任务书」在「已生成未采纳」场景误导（账本不探盘无法区分子场景），改为双覆盖引导「若规划文档已生成，先在工作台采纳它，再重新生成本任务书」；
> ② 拆分结果文档卡补面——人读拆分方案（清单/覆盖矩阵/新发现）此前只有机器抽取的提议行、无文档回显；S2 增第五张文件卡（WorkspaceDocSection ns=splitResult：预览/路径披露/tampered 对照 seed 锚/404 诚实缺失/无工作区诚实提示；splitResult.* 8 键五点登记；卡片不依赖提议收取，文件先行可读与 GET 面同口径）；
> ③ `SplitBaselinePrdSchema.modifiedAt` 去 `.int()`——pre-existing 缺陷（d86de83 起），NTFS mtimeMs 天然带小数，首个带 PRD 清单的实机批准拆分在请求体解析层整包 400；用户原样 payload 红测试复现后放宽（输入/存储面对齐读面 wire guard 的 number 口径），回归锚在 endpoint.test。
