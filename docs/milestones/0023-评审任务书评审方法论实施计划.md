## 刀一范围（全量）

### A. 任务书本体（sow.ts）

1. 新增评审专属七节装配：`reviewGoalBlock`（两产物：验收核验＋质量发现，不做清单与不做裁决边界）、`reviewSnapshotBlock`（标题/描述/阶段＋验收标准逐条＋工作包行下挂 commits 短哈希＋note，零 commits 诚实缺席行，快照头「生成时快照」措辞）、`analysisInputBlock` 复用（`## 输入` 头，名词映射既有）、`knowledgeBlock` 复用（`## 参考知识` 头）、`reviewConstraintsBlock`（严格只读＋不运行代码/测试/构建／不裁决／有据／如实分级〔有把握才报·不确定但高危注明不确定·零发现如实写〕／有限停止）、`REVIEW_WORKFLOW`（通读标准列核验清单→定位改动面〔commits 锚，缺席以边界为界〕→逐条核验三值＋证据→六维排查〔判据内嵌〕→汇总三节报告）、`reviewOutputBlock`（三节模板＋级别判据＋`# skyaxis-review` 骨架〔findings+detail、criteriaChecks〕＋说明＋完成自检）。
2. `buildSow` review 分支独立成族返回（无修订戳）；五块路径回 dev 专属；`requirementBlock`/`outputBlock` 的 review 臂退役。

### B. 协议（protocol.ts）

- `WorkbenchCriteriaCheck` 新接口（ref/result 三值/evidence?）；`ReviewReportEntry.criteriaChecks?`；`ReviewVerdict.detail?`；`SaveReviewVerdictRequest.verdict.detail?`（≤2000）；`ReviewSkipReason` +3；守卫（isReviewVerdict/isReviewReportEntry/save 校验）与 `seededChecks` 响应字段跟随。

### C. 解析（review-parse.ts）

- findings 行 detail 可选（非空保留、超 2000 skip `over-cap`）；`criteriaChecks` 节解析（ref≤64 非空、result 闭枚举、evidence≤2000 可缺席；坏行 skip 三新原因）；结果体 +`checks`。

### D. 宿主（endpoint.ts reviewWriteFlow）

- 播种核验行（以 `record.criteria` id 集过滤未知 ref）；verdict 铸 detail；响应 +`seededChecks`；幂等收敛分支零改动（自然不重播）。

### E. UI（review-section.tsx / controller.ts）

- 报告卡 second tag：核验计数（{s} 满足/{u} 不满足/{v} 无法核验，unmet>0 warning / 全满足 success / 否则 info）；`ReportDetailModal` 顶部核验表（C/结论/证据）；`VerdictFormModal` detail 只读展示＋提交回传；`ReviewImportOutcome` +`seededChecks`＋状态行展示。
- 词典 +7 键四处登记（review.checksTitle/checkSatisfied/checkUnmet/checkNotVerifiable/checksCount/checkEvidence/seededChecks）。

### F. 测试与同步

- sow.test（评审七节正/负钉：commits 锚、零 commits 缺席、六维判据、yaml 骨架、无修订戳、dev 回归）；review-parse.test（detail 三态＋checks 四态）；endpoint.test（播种+过滤+detail+seededChecks+幂等不重播 checks）；review-section.spec（tag/核验表/证据只读+回传存活）；register.spec 键清单 +7；存量钉现场修。
- tsc 干净＋全量绿（基线 1195/80 文件）；README 双版基线同步。
