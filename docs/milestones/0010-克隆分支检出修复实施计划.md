## 实施记档（单工作树交付）

### 刀一 clone.ts（引擎面）

- `#branchPhase(task, exe)`：probe argv `[exe, '-c', 'credential.helper=', '-C', dest, 'show-ref', '--verify', '--quiet', refs/remotes/origin/<branch>]`；spawn 后立即 `task.handle = probeHandle`；`signal.aborted` 先查；`exitCode === 0` → `checkout -B <branch> --track origin/<branch>`，否则 `checkout -b <branch>`；checkout spawn undefined / done reject → cleanupDest + unknown；probe 自身 spawn undefined / reject 同收敛 unknown（不回落 `-b`——静默错误起点比响亮失败更糟）。
- `#drive` 尾部改为委托 `#branchPhase`；模块头/`#drive` 注释/`CloneStatus` 注释同步三段链。
- git 语义依据见决策 0011 D1/D2（本机 git 2.55 实测：show-ref 0/1/128；`-B` 重置当前检出分支合法；`--track` 防 `branch.autoSetupMerge=false`、与 `checkout.guess` 无关）。

### 刀二 clone-registry.test.ts（11→14）

- `trio()`→`quad()`：+probe（默认 exit 0 ⇒ 跟踪臂为默认形态）；happy path 断言 spawn 序 check/clone/**probe(2)**/**checkout(3)** 与两条新 argv；failing-checkout 插 probe；reclone 两处 quad 化。
- **+3 用例**：① probe exit 1 → `spawnCalls[3]` 为 `checkout -b`、done；② abort during probe——probe 悬置、`begin()` 后同步 mkdir dest、abort ⇒ probe.terminate 已调 + 'aborted'，probe 以 SIGTERM settle 后仍 aborted 且 dest 被清；③ probe spawn blow-up（fake 无 script 抛 unexpected spawn）⇒ failed/'unknown' + dest 被清 + spawnCalls 恰 3（无 checkout spawn）。
- 时序纪律：dest mkdir 必须在 `begin()` 返回后**同步**执行——中间任何 await（含 `await import`）都会让 clone continuation 的 cleanup 先于目录存在跑完（②③首跑红过一次，已记档）。

## 实机验收脚本（5 步，已通过——用户 2026-10-15）

1. **跟踪臂（本轮主体）**：关联克隆一个远程已有同名开发分支（含中文分支名，如 `leizhuang/feat-0831-量本利操作成本线上化`）的仓库 → 完成后在 `<workspace>/repos/<目录>` 内：`git rev-parse HEAD` == `git rev-parse origin/<branch>`；`git rev-parse --abbrev-ref @{upstream}` = `origin/<branch>`；`git status` 显示 "up to date with 'origin/<branch>'"；`git branch -vv` 显示 `[origin/<branch>]`。
2. **新支臂**：关联克隆时填一个远程不存在的分支名 → 照旧：HEAD 在新分支、基于默认分支 tip、`@{upstream}` 报 no upstream（0003 场景无回归）。
3. **默认分支名边角**：branch 填仓库默认分支名（master/main）→ done（不再是 bad-branch）、HEAD==origin/<默认>、upstream 在场。
4. **取消**：cloning 或 branching（探测/检出）阶段取消 → aborted、repos/ 下半成品目录被清。
5. **reclone**：已关联仓库重克隆 → 走同一探测臂（远程有同名分支 ⇒ 跟踪检出）；空远程仓库无回归（probe exit 1 → 新支臂照旧）。

> **实机验收已通过（用户 2026-10-15）**——五步全过（含中文分支名跟踪检出）。**0010 克隆分支检出修复轮整体收口（引擎 + 测试 + 记档 + 实机验收），无挂账遗留**；留下一轮候选见文末。克隆建支语义就此落定：远程同名分支 ⇒ 跟踪检出（远程 tip 起点 + upstream），远程无同名分支 ⇒ 本地新支（0003 场景）。
