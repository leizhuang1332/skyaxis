# skyaxis — 每阶段验收标准（权威出处）

> 本文档定义 skyaxis 每个里程碑的验收维度。给出**"达成 / 未达成"的判定框架**，**不写具体指标阈值、不定性能 SLO**（遵循 CLAUDE.md 第 2.1 节边界）。

**锁定来源**：[ADR 0008 — 每阶段验收标准：MVP 4 个验收维度](0008-每阶段验收标准.md)（2026-09-19 接受）。

---

## MVP 阶段 4 个验收维度

| # | 维度 | 一句话定义 | 判定框架 |
| --- | --- | --- | --- |
| 1 | **功能完整性** | MVP 完整 6 个场景全部可用 | 6 个 MVP 场景（A / B / C / D / D1 / D2）在 v0.3 通过条件满足时全部可用。 |
| 2 | **可用性** | 个人开发者可在本地 5 分钟内跑起来 | 新用户按 README 步骤，从 git clone 到看到可视化界面 < 5 分钟；DSH 插件加载无需手工改配置。 |
| 3 | **文档完整性** | 关键决策有 ADR + README 使用文档 | 关键决策全部有 ADR；README 包含安装、使用、配置、自检 4 个最小章节。 |
| 4 | **测试覆盖** | 核心场景有端到端测试 | 6 个 MVP 场景每个至少有 1 个端到端测试（手动或自动化皆可）。 |

## 验收维度在 3 个子阶段的差异化应用

| 维度 | v0.1（核心可视化） | v0.2（依赖关系） | v0.3（归档检索） |
| --- | --- | --- | --- |
| **功能完整性** | A 场景可用；B + C **基础部分**可用 | D1 + D2 必交付；B + C **增强部分**可用 | D 场景可用；B + C **完整**；**6 场景全部可用** |
| **可用性** | 5 分钟跑起来（基础流程） | 5 分钟跑起来（增强流程） | 5 分钟跑起来（完整流程） |
| **文档完整性** | README + ADR 0001-0007 | README 增量 + 子阶段 ADR | README 完整 + 子阶段 ADR |
| **测试覆盖** | A 场景至少 1 个端到端 | D1 + D2 至少 1 个端到端 | 6 场景各至少 1 个端到端 |
