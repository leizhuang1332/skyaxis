## 实机验收脚本（主线四刀后，`dsh web` 本机 zh-CN Win11）

1. **自动绑定**：S3 生成工作包任务书→投递→发送后回 S3——WP 详情绑定行出现该 dev 会话（无需手动 [＋关联]）。
2. **watcher 收取**：会话跑完（末尾吐声明块）——停留本需求：看板卡出「完成待读」角标+Modal 收取卡 pending；切到别的需求再切回来：同样已 seed（注册层 watcher 全局观测）。
3. **双 WP 并行**：两个 WP 各投一会话先后完成——两 pending 槽共存互不覆盖；分别导入互不影响。
4. **返工 re-seed**：验收不通过→同会话补话再跑→新声明（hash 变）→槽重置 pending。
5. **执行视图**：dev 会话执行中打开 WP 执行视图——折叠直播有内容（列集按 P0 表）、计量真实、摘要行在轮换；断网/宿主忙时 missing 诚实行。
6. **waiting 聚合**：会话提问时 S3 等待条出现→点击跳宿主应答。
7. **收件箱两组**：制造「待发送」（投递未发送）与「存疑」（in-dev 无绑定）——两组各出行；正常态段零占位。
8. **声明扩键**：新任务书生成的声明含 summary/files/verification——导入后 built 卡证据行+验收节证据区渲染；旧形态声明照常导入。
9. **准出披露**：留一个未验收 WP 点「完成本阶段→」——旁披露行出现「1 项未验收」，推进不被阻。
10. **回归**：S5 导入声明面照旧可用；analysis/split watcher 照旧；任务书五段与 revision 戳不变；看板拖拽仍禁用。
