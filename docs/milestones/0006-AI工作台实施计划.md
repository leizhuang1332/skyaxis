**硬约束（全程有效）**：
- **诚实口径**（docs/dist/06 指标诚实纪律 + research 0006 §4.4）：无数据源处不渲染计数与动作——徽章计数在数据缺失时隐藏不占位；`[完成本阶段 →]` 等推进按钮在 stage/stageHistory 无处落盘前不渲染（点了没反应的按钮就是假交互）。P1a 已把该口径钉成测试守卫（ai-workbench-tab.spec）。
- **权责模型**：built ≠ done——批准拆分 / 批准计划 / 验收确认 / 阶段推进四权永不在 AI 手里（research 0006 §3）。
- **observe-only**：9 服务白名单无静态守卫，写操作逐个论证（编程启动 session 的三档边界——`sessions.create` / `inputActions.setDraft` / `prompt`——**已定性，见 [research 0007](../research/0007-工作台P0-三验证结果报告.md)**：create=观察外行动无四权冲突 / setDraft=UI 本地写（最低摩擦，slot-props 路线免新 inject）/ prompt=用户身份行动（自动发送越同意线，v2 不采用——投递 v2 = create + setDraft + 用户按下发送）。
- **字段演进纪律**：账本新字段一律 optional/default + 手写 guard 同步放宽（0003「一行旧数据炸整文件」教训）；运行态（session 实时状态）不入账本，读时经 projection。
- **CSS alias-only**：新类只用已实证的 `--dsw-alias-*` token（mockup 的 `--state-warn-bg`/`--state-success-bg` 不在实证清单，不得引入）；几何基线镜像现有 ladder。
- **sticky 几何耦合**：`.stageRail` 的负 margin / top 偏移与 `.body` 的 16px padding 耦合（CSS 注释已钉死），改 `.body` padding 必须同步。

### P5a 实机验收脚本（8 步）

1. **投递端到端**：S3 详情生成 dev 任务书 → 点 [投递到新会话] → 新会话打开（cwd = 需求工作区）、输入框已预填任务书全文 → **用户自己**按发送（工作台全程不代发）。
2. 投递后回 S3 详情把新会话 bind 到工作包（既有关联流不受影响）；剪贴板复制按钮与投递并存，投递失败出「请手动粘贴」警示且可重试。
3. **workspace 知识**：S6 手动新建一条 scope=工作区、path=某需求工作区路径、触发=path value=`src/**` 的知识 → 该需求 S6 可见（另一工作区的需求看不到）；该需求 SOW 勾选池也出现（标签 `[path: src/**]`）；无工作区无仓库的需求两者都不出现。
4. **绝对 glob**：触发 value 写 `C:/<工作区>/repos/**` → 只有该工作区下需求命中。
5. **知识导出**：S6 [导出] → 预览（## 标题 + scope/path/触发 meta + 正文 + 生成戳）→ 复制粘贴核对；行 Menu [导出此条] 同。
6. **计划/报告副本**：S3 详情选已批准版本 → [复制正文]；S4 报告详情 → [复制正文]；粘贴核对。
7. 既有回归：激活流 requirement/global 档照旧、keyword 触发照旧。
8. D6 删除需求后 workspace 行留存（级联不动它——公共资产口径）。

### P5b 实机验收脚本（10 步）

1. **stale 触发**：批准拆分 → 手改工作区 `prds/` 里一份 PRD（或新增/删一份）→ 回 ②探索规划 → 标题行出现「上游已变更」徽章 + gonogo 行「PRD 文件」成因 + [确认仍有效]/[重新拆分] 两按钮。
2. **findings 触发**：不改 PRD，只在 ①需求理解 处置一条发现（记方案解决/不处理）→ 回 ② → 徽章出现，成因写「发现处置」。
3. **确认仍有效**：点它 → 徽章消失；再改一次 PRD → 徽章重现（基线已换到新快照）。
4. **重新拆分（未开工）**：全部 WP 未开工时点 [重新拆分] → ack Modal 列活动包数 → 勾选确认 → 活动 WP 全进底部「已放弃」区、批准戳消失、清单可重新编辑。
5. **重新拆分（已开工禁用）**：把某 WP 推进到开发中 → 回 ② 触发 stale → [重新拆分] 按钮禁用 + 下方披露成因（有工作包已开工）。
6. **评审任务书**：④评审 点 [生成评审任务书] → 预览含 `# skyaxis-review` 骨架与 findings 注释教学、末句「不要替用户下结论」→ 复制/投递到真 session 让 AI 评审收尾。
7. **抓取 + 种子**：④评审 [导入报告] → 选该会话 [抓取] → 整条报告正文（含 fence）填入 → 保存 → done 披露「种子裁决行 N 条」；报告卡计数「发现 N · 待裁决 N · confirmed 0 / rejected 0」；裁决节出现 N 行**「待裁决（AI 提议）」**（outline tone，不是 confirmed 琥珀）。
8. **逐条裁决**：点一行 → 弹窗只有 confirmed/rejected 两个选项（无 proposed）→ 选 rejected 必须填理由 → 行变 `rejected：理由`；选 confirmed + 处置 → 变绿；④徽章 = 待裁决 + confirmed 未处置之和，全裁决处置后消失。
9. **幂等锚不复活 + 无块/坏行**：删一条种子行 → 同内容再导 → 报告不新建且被删行不复活；粘一段无 `# skyaxis-review` 的纯报告 → 照建、种子 0、done 出 blockError 变体文案；粘一段 findings 含 severity 非法/title 超 64 → 好行入库、坏行不入库（种子数少于总行数，账本仍可正常 load）。
10. **模板误命中防线**：对只粘过评审任务书、AI 未输出 `# skyaxis-review` 的会话点 [抓取] → 提示「没有约定块」（不是把任务书骨架当报告导入）。

### 挂账轮实机验收脚本（4 步）

1. **下载（核心悬空点）**：⑤ [导出上线单] → Modal 出现 [下载为文件]（与 [复制到剪贴板] 并存）→ 点击 → 浏览器/webview 触发文件下载，落盘文件名 `release-sheet-<需求id>.md`、内容与预览逐字一致；S6 知识导出同（`knowledge-export-<戳>.md`）。**若 webview 拦截/无反应 → 拍板记档销账或回退（下载按钮仍留注入缝，剪贴板主路不受影响）**。
2. **产物对账**：工作台导轨下方出现「产物对账」按钮 → 打开 Modal → 三面恒显（孤儿/缺失/.trash，当前需求口径计数）；④ 删除一条评审报告（正文留盘成孤儿——P4 裁决⑤）→ Modal 内 [刷新] → 孤儿面 +1（kind 标签「报告」+ reviewId）。
3. **（可选）另两面**：手改产物目录某文件名为不合规名 → 刷新后孤儿面「未识别」行现形；手删某计划版本文件 → 缺失面现形。
4. **回归**：既有复制导出照旧（三态机）；刷新重拉正常；账本不可读时（临时改坏 workbench.yaml）出对账失败警示行可刷新重试。
