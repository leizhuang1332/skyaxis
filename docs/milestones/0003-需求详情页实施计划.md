## 路线决策记录（本次调研核心产出）

六个候选横向对比（main 第二 entry / 面板内子视图 / Modal / 右栏 tab / shell.overlay / 内联展开），结论 **B > A > C**，决定性证据：

- **生态零先例**：DSH 生态注册过 main entry 的只有宿主自己（conversation，ui-conversation/apply.ts:391）与 skyaxis（repos、requirements）。dsh-web-ui 全仓 20+ 插件零 main 注册——"列表→详情"先例（skill-explorer、dsh-market 等）全部走容器内导航（面板内 tab / Modal / settings 分页 / 自建槽位 / createRoot 自造 overlay）。
- **宿主官方心智是 B**：宿主自己的会话树（会话→子会话 lineage）就在 `main.conversation` 单 entry 内实现，不是多 main key。main key = 顶层面板，层级导航在面板内部。
- **A（main 隐形 entry）的后患随页面数复利**：侧栏高亮缺失（activePanelId 严格相等匹配）、"main entry 数 ≠ 侧栏按钮数"漂移、activePanelId 语义超载（宿主未来若加持久化/URL 同步，隐形 key 是边角案例）、rc 阶段宿主升级需专项回归。每加一个带详情的页面，税按比例放大。
- **B 的迁移出口干净**：日后若出现"任何位置直达需求详情"的深链需求（A 的唯一独有收益），迁移面 = register.tsx 加第二 main entry 挂 detail.tsx + openDetail 追加 selectPanel + 返回动作改 selectPanel；detail.tsx / selectedId / controller 动作全部原样复用（约半天）。

### 调研结论（tab 能力盘点，2026-09-26 实证；2026-09-27 二轮补 conversation.view 解剖并修正设计）

| 项 | 结论 |
|---|---|
| primitives 有无 Tabs 组件 | **无**。类型入口全量盘点（`dsh-client-ui-primitives/lib/types/index.d.ts`）：Button / Input / Menu / Modal / Switch / Tag / Pill / StateDot / DisclosureRow / HoverCard / Tooltip / Toast / RiskConfirmation / OnboardingSurface / ConnectionIndicator / JsonTree / Terminal·Read·Diff·Search·Web·Code·Json Block / MarkdownText + 60 图标 + 工具函数——无 Tabs / TabList / Segmented |
| **conversation.view 解剖（宿主官方 tab 模式）** | 三件套，**同样无可复用组件**：① 槽位声明 = list slot / **session scope** / 由 `conversation.session` 的 children 声明（apply.ts:263）；② tab 投影 = 宿主从 entries 投影 `{id, label}`（`resolveSlotLabel` 吃词典 thunk）存 snapshot store，订阅 slot + locale 刷新（apply.ts:140-195）；③ 切换器 UI = `ConversationSessionHeader` **自绘** button（`role=tablist/tab` + `aria-selected`，`tabs.length > 1` 才渲染，**无箭头键盘导航**，ConversationSession.tsx:140-155）；④ 内容 = `renderSlot('conversation.view', props, { only: active.id })` 按活动项挂载；⑤ 选中态 = conversationStore.view 持久化 + 兜底 `chat`，"绝不自动选第一个注册项" |
| 宿主 tab 视觉基线（中央面板） | **ui-conversation 会话页视图 tab**（ConversationRoot.module.css:159-205）：**文字 + 底部 2px 蓝条**式——13px/16 wt500 文字、tertiary 色、strip gap 36 / padding-left 8 / margin-top 10、active 色 `--dsw-alias-state-business-primary`（业务蓝，两主题恒蓝）+ `::after` 2px 底条盖 header 发丝线；**tab 行在 header 内**（76px 构成本就含 tab 行：10 顶 + 30 标题 + 10 margin + 16 tab + 9 底） |
| （对照）右栏 tab 基线 | ui-dockkit 胶囊 chip（28px r12 / `markdown-tag` 填充）——**dockkit 场景专属**，非中央面板基线（2026-09-26 初稿误选，27 日修正） |
| 生态 tab 先例 | skill-explorer 面板内 tab 为**自绘**（`role="tab"` + 自写 css，无组件）；**插件声明自建槽位**有实证先例：preset-center 的 `dsh-workshop.panel`（keyed, root，插件间共享面板壳）——skyaxis 声明 `requirements.detail.view` 同构可行 |
| **路线结论** | **复刻 conversation.view 模式**（非仅自绘注册表）：声明自有 list slot + entries 投影 + `renderSlot({only})` + tablist 照会话页逐字移植——与宿主官方 tab 同构，且获得跨插件开放性。tab 本体仍无组件可 import，复用的是**模式与视觉基线** |

### 设计（B 路线不变；slot 化视图注册，2026-09-27 修订版）

```
RequirementsPage（挂载点不变；宿主半 / 协议继续零改动；register.tsx 仅加槽位声明）
├─ header 详情态：[← 返回] + titleCluster（标题 / 描述）
│                + tab 行（titleCluster 下方，照会话页 tabs 块——底条压发丝线）
│                    ├─ 「概览」overview      ← 占位 seat
│                    └─ 「占位」placeholder   ← 占位 seat
└─ body
    └─ renderSlot('requirements.detail.view', { t, requirement }, { only: activeId })
        └─ 活动 tab 的组件（session 内仅挂载一项，同 conversation.view）
```

- **自有槽位声明**：`'requirements.detail.view': { kind: 'list'; scope: 'root' }`（SlotMap 本地 declare 合并，同 main/panellist 先例；register.spec 的 mountFixture 补声明）。
- **tab 注册 = slot 注册**：apply 时 `ctx.slots.register({ name, id, order, label: () => t(key) }, Component)`——条目是组件而非 render 函数，label 走词典 thunk（宿主 locale 切换自动重解析）。skyaxis 自有的两个占位 tab 在 register.tsx 与主面板同批注册、随 disposer 撤销。
- **消费者在 detail.tsx**：`ctx.slots.entriesOfSlot('requirements.detail.view')` 投影 tabs（+ subscribe 刷新，照 apply.ts:140-195 形状）→ 自绘 tablist（结构/样式/行为照 ConversationSession.tsx:140-155 逐字移植）→ `renderSlot(..., { only: activeId })` 挂载活动项。**加功能 tab = 加一个 slot 注册项**，detail.tsx 不随 tab 变；**其他插件未来也可注册进该槽位**（跨插件开放，slot 机制本意）。
- **tab 行位置**：header 内 titleCluster 下方（会话页同位）——strip 常驻问题自然消解（header 本就 flex:none），header 高度自适应（tab 行 ~26px，短记录仍近 76px 基线）；缺失态不渲染 tab 行。
- **tab 态**：组件内 `useState`（详情会话生命周期，进新需求重置）；不做持久化。**默认选中策略对齐宿主**：不自动选第一个注册项——无有效选中时回落首 tab 并显式置为选中（与宿主"persisted → chat fallback"的差异在无 chat 等价物，文档记录）。
- **a11y 对齐宿主**：`role=tablist/tab` + `aria-selected`，**无箭头键盘导航**（宿主未做，同构优先；后续要加是 detail.tsx 内十行的事）。
- **占位内容**：notice 卡（P1 缺失态同形态，CSS 类合并为 `detailNotice`）+ 词典"功能规划中，此页预留。"
- **词典 +3 key**：`detail.tab.overview`（概览 / Overview）、`detail.tab.placeholder`（占位 / Placeholder）、`detail.tab.seat`（功能规划中，此页预留。/ A planned feature will land here.）

### 调研结论（2026-09-27 四路并行）

**路 1 · DSH 工作区机制**（dsh-workspace / dsh-api-workspace-controller 0.1.5-rc.2 源码级）：

| 项 | 结论 |
|---|---|
| workspace 本体 | uuid + 已存在目录的 canonical path（realpath）；唯一性法则是 path 字符串相等；持久化在宿主 domain KV（`ctx.storageDomain`），非自有文件 |
| 绑定 API | host 侧 `ctx.workspaceRegistry.create(path, title?)`——同 canonical path **幂等返回已有实体**；会话落位 = session.create 传 `workspaceId`（attach 时校验 cwd 一致）；无"切换/激活"全局态 |
| 元数据机制 | **没有**（durable schema zod $strip 剥多余字段）→ "需求↔工作区"绑定关系必须 skyaxis 自存（requirements.yaml sidecar，与 0002 拍板一致） |
| 关键约束 | 目录必须已存在（create 校验 isDirectory → skyaxis 需自 mkdir）；workspace 删除不删磁盘、重加同目录 = 新 uuid → **引用存 path 而非 id**（`resolveByPath` 可找回） |
| 现成通道 | controller 附带 `ctx.remote.directoryPicker`：`pick()`（OS 原生选目录）/ `list(path)`（目录浏览+面包屑）/ `createDirectory`——"设置工作区"交互直接复用，不必自造目录树；`@deepseek-ai/dsh-api-workspace-controller` **已在 skyaxis client inject 列表**（package.json dsh.client.inject），接线成本低 |
| 降级 | `ctx.inject(['workspaceRegistry'], …)` 可选依赖；无 session 持久化后端的组合中服务不激活（静默，与 skyaxis 现有 optional-dependency 风格一致） |

**路 2 · 需求元信息存储**（skyaxis 现有代码）：
- 推荐**直接扩展 `RequirementRecord` 字段集**，不建新文件、不升 version——正是 0002 预留的演进路径（version 字段 + 向后兼容读）。
- **坑**：zod schema 新字段必须 `.default()`，否则旧 requirements.yaml 整文件 degraded（写入门全关）；手写 guard `isRequirementRecord` 同步放宽。
- 关联仓库 = repoId 引用 + **读时容错 join**（详情页另拉 repos list 按 id join，命不中显示"已移除的仓库"）；repos-pool 零改动（保持"独立文件互不持有状态"边界，0002 风险登记）。
- 新 tab = register.tsx 一个 slot 注册项 + 词典四处同步；detail.tsx / view.tsx 零改动（P2 骨架开放性的兑现）。

**路 3 · git 实现方案**（DSH 生态本地核查 + 开源五方案对比）：
- **首选：手写 `ctx.subprocess.spawn` 跑 git CLI，零新依赖**。理由：① [validator.ts](../../../src/repos-pool-host/validator.ts) 已有 `resolveExecutable('git')` + spawn contract（`GIT_TERMINAL_PROMPT=0` / `credential.helper=` / 超时 AbortSignal）+ 认证/网络错误分类完整先例，clone 是同模式再加一步；② **唯一保留 DSH 托管语义**的路线（进程组终止 / disposal 连带清理 / env 擦洗 / Windows job object——第三方库全绕过 subprocess seam，clone 中途关面板会留孤儿 git 进程）；③ 系统 git 原生覆盖 ssh/scp（仓库池白名单含 ssh，硬约束）、LFS、子模块；④ 进度 = `git clone --progress` stderr 增量读（collect `readFrom(offset)` 或 pipe 流），解析十几行代码。
- **否决**：isomorphic-git（**不支持 ssh URL，一票否决**；LFS/子模块均不支持）；nodegit（稳定版停在 2020、Node 22 无预编译二进制）；dugite（postinstall 下载百 MB 级二进制，不适合 npm 插件分发；无进度 API）。
- **条件备选**：simple-git（活跃度最好，周下载 1384 万，4.0.2）——仅当后续 status/diff/commit 的 porcelain 解析维护失控时引入，引入时需在其 config/plugins 里复刻 spawn contract。
- 后续 git 需求（status/commit/push）同路线：一次 spawn + `--porcelain=v2`（机器可读、locale 无关）。

**路 4 · DSH UI 体系**（primitives 全量盘点 + 宿主先例）：
- **无现成组件**（实证）：Tabs/Select/Table/Progress bar/上传控件/目录树均无——下拉用 `Menu`、状态用 `Tag`、进行中用 `StateDot state="ongoing"`（自带追逐动画）、上传自绘隐藏 `input[type=file]` + `IconPaperclipOutline16`。
- **原位编辑无组件，自绘双先例组合**：QueueDock 行内编辑状态机（editing 态三元切换、Esc 取消 / Enter 提交 / IME composition 守卫 / 行外消失清 editing）+ `.editor` 样式契约（border-l4 r6 bg-base，focus 变 `--dsw-alias-state-business-primary`）；路径类编辑可用 DirectoryBrowser"容器画框"变体（边框由外层画，编辑期间保持点亮，防跳动）。
- token 纪律不变：只消费 `--dsw-alias-*`；间距/圆角 px 字面量（卡片 r12 / 组件 r8 / gap 4 的倍数）；z-index 惯例值（Modal 1000 / portal 1100）。
- **上传通道**：skyaxis client↔host 现只有 JSON；`HostConnectionFetch` 契约原生支持 `requestBody:'streaming'` → 自注册流式路由（octet-stream），照宿主 file-upload 包 http-route 形状，无 multipart 必要。
- MD 渲染：`MarkdownText` 现成（PRD 预览用）。

### 概念模型（账本与磁盘分离——DSH workspace 同哲学）

```
requirements.yaml（skyaxis 账本，单文件单乐观锁域不变）
  RequirementRecord 扩展三组字段（全部 .default() 向后兼容，version 不动）：
    workspacePath: string          // '' = 未绑定；存 canonical path 而非 workspaceId
                                   //（workspace 删除后重加同目录 = 新 uuid，path 才稳定）
    linkedRepos: { repoId: string; branch: string }[]   // 意图声明；clone 运行态不入账本
    prdDocs: { id; name; path; updatedAt }[]            // 清单引用，不存文档内容

<workspacePath>/（磁盘投影；DSH 对 workspace 内部布局零约定，repos//prds/ 为 skyaxis 自有约定）
  repos/<repo-name>/   // clone 目标；repo-name 取仓库池登记名 sanitize
  prds/<file>          // PRD 落盘；按需创建
```

- **绑定动作**（host）：路径校验（绝对路径）→ 按需 `mkdir -p` → `realpath` → `ctx.workspaceRegistry.create(path)`（幂等）→ workspacePath 入 yaml。需求自此与会话体系打通：session.create 传该 workspace 的 id 即落位于此（本期只留口，不做"从需求发起会话"）。
- **clone 动作**（host）：**任务票据模式**——POST 发起（返回 taskId；同 repoId 进行中防重）→ `git clone --progress <url> repos/<name>` → stderr 增量解析进度 → `git checkout -b <branch>` → GET 轮询任务状态（进行中百分比 / 成功 / 分类失败：auth / network / git-missing / other——分类器复用 classifyLsRemote 形状）。
- **PRD 动作**（host）：上传 = streaming 路由收字节流 → 落盘 `prds/`；创建 = 端点收 name + 内容写 `.md`；重名拒绝。清单读时校验（文件缺失显示"已缺失"Tag）。
- **删除哲学**：需求删除 / 解绑 / 移除关联**一律不删磁盘**（对齐 DSH workspace 删除语义）；产物留在原地。
