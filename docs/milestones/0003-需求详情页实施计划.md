# 需求详情页实施计划

> 日期：2026-09-26
> 依据：需求管理 P1-P3 全阶段闭环（[milestone 0002](0002-需求管理实施计划.md)）+ 本次路线调研（DSH 0.1.5-rc.2 main/AppFrame 源码级复核 + 生态插件槽位分布实测：deepseek-harness 主仓、dsh-web-ui 集合仓 20+ 插件、dsh-plugin、dsh-z-workbench）

## 总体形状（先立边界）

```

            controller.ts  +openDetail(id)（附带 refresh）/ closeDetail()（照 openCreate/closeForm 形状）

            view.module.css +detail 样式（alias-only 口径不变；tagId 已按路径唯一，无撞名风险）
```

## 路线决策记录（本次调研核心产出）

六个候选横向对比（main 第二 entry / 面板内子视图 / Modal / 右栏 tab / shell.overlay / 内联展开），结论 **B > A > C**，决定性证据：

- **生态零先例**：DSH 生态注册过 main entry 的只有宿主自己（conversation，ui-conversation/apply.ts:391）与 skyaxis（repos、requirements）。dsh-web-ui 全仓 20+ 插件零 main 注册——"列表→详情"先例（skill-explorer、dsh-market 等）全部走容器内导航（面板内 tab / Modal / settings 分页 / 自建槽位 / createRoot 自造 overlay）。
- **宿主官方心智是 B**：宿主自己的会话树（会话→子会话 lineage）就在 `main.conversation` 单 entry 内实现，不是多 main key。main key = 顶层面板，层级导航在面板内部。
- **A（main 隐形 entry）的后患随页面数复利**：侧栏高亮缺失（activePanelId 严格相等匹配）、"main entry 数 ≠ 侧栏按钮数"漂移、activePanelId 语义超载（宿主未来若加持久化/URL 同步，隐形 key 是边角案例）、rc 阶段宿主升级需专项回归。每加一个带详情的页面，税按比例放大。
- **B 的迁移出口干净**：日后若出现"任何位置直达需求详情"的深链需求（A 的唯一独有收益），迁移面 = register.tsx 加第二 main entry 挂 detail.tsx + openDetail 追加 selectPanel + 返回动作改 selectPanel；detail.tsx / selectedId / controller 动作全部原样复用（约半天）。

## P1 导航骨架（进得去、回得来）

- [ ] store/controller：`selectedId` 字段 + `openDetail`/`closeDetail` 动作（含 openDetail 附带 refresh、竞态序号守卫沿用）。
- [ ] detail.tsx 最小版：返回按钮 + 按 selectedId 渲染标题/描述（presentation-only，props：t / requirement / onBack）。
- [ ] list.tsx：行主体 button 化（li 内平级结构，不与行尾菜单嵌套）+ `onOpen` prop。
- [ ] view.tsx：body 区条件渲染接线（只切内容区，filterBar/banner/Modal 留在 page 层）。
- [ ] 词典：`detail.*` 最小 key（返回 aria 等，zh/en）。
- [ ] 测试：store selectedId 流转（open→close→再开另一条）+ view 条件渲染切换与返回触发 + **register.spec 零改动**（挂载契约零变本身即 B 路线的验证点）。
- [ ] **验收（实机目测）**：① 点卡片进详情、返回按钮回列表、再进另一条；② 侧栏高亮全程保持；③ 行尾菜单（编辑/删除）与表单流零回归；④ 键盘可达（Tab 聚焦行、Enter 进入）；⑤ 仓库池/task-graph 零回归。

## P2 详情页成型（只读展示完整化）

- [ ] 完整字段展示：标题、描述（多行 pre-wrap）、createdAt / updatedAt（格式对齐 DSH 惯例）。
- [ ] 缺失态：selectedId 对应记录不在 store（外部删除/坏文件降级）→ "已不存在"空态 + 返回引导；focus 刷新回流自动覆盖。
- [ ] Esc 返回落地（editing 关闭守卫）。
- [ ] 状态保留专项：返回后筛选词/滚动位置不丢；**详情态下切面板再切回 → 落在详情态**（store 常驻注册闭包，keyed entry 卸载重建后 selectedId 仍在——与 A 路线"切回落列表"的行为差异点，验收时按此口径确认）。
- [ ] 词典扩全（缺失态文案、字段标签）；面包屑式页头（"需求管理 / {标题}"）实现期目测定夺。
- [ ] 测试：缺失态渲染、Esc 守卫（Modal 打开时不关详情）、词典双语对齐。
- [ ] **验收（实机目测）**：① 双开标签删除一条 → 详情态切回标签 → 该详情落缺失态；② 返回列表后筛选词仍在、滚动位置基本保留；③ 编辑 Modal 打开时按 Esc 只关 Modal；④ 亮暗/语言/主题跟随。

## P3 操作收口（详情页成为操作入口）

- [ ] 详情页操作入口：编辑（`openEdit`，Modal 表单在 page 层弹出，保存成功后详情内容随 store 更新）/ 删除（复用 pendingRemove 确认流）。
- [ ] 删除联动：确认删除成功后，若 `selectedId` 即被删项 → 自动 `closeDetail` 回列表。
- [ ] 测试：详情页编辑回流（保存后字段更新）、删除自动返回。
- [ ] **实机终验清单**：① 列表→详情→编辑→保存→详情内容已更新→返回；② 列表→详情→删除→确认→自动回列表；③ 外部删除→详情缺失态→返回列表条目同步消失；④ 多面板往返零回归；⑤ 刷新回会话页（宿主已知限制，activePanelId 不持久化，与列表页一致）；⑥ 仓库池/task-graph/需求管理三面板全链路零回归——**P3 收口，详情页全阶段闭环**。

## 风险登记（方向级）

| 风险 | 缓解 |
|---|---|
| 行主体 button 化与行内 Menu 的 DOM/交互冲突（button 嵌套禁令、点击冒泡） | li 内平级结构 + P1 实机专项（验收 ③④） |

| 0.1.5-rc.2 → 后续版本契约漂移 | 本路线**零宿主新依赖**（不用 layout/selectPanel/新槽位），升级面为现有已验证面；沿用 0001/0002 升级 diff 口径 |
| 深链需求未来出现 | A 出口已固化于路线决策记录（迁移面约半天，组件与状态层全复用） |
