# 需求管理（requirements）实施计划

> 日期：2026-09-24
> 依据：仓库池全阶段闭环（[milestone 0001](0001-仓库池实施计划.md) + [research 0004](../research/0004-仓库池调研-DSH宿主能力评估与方向规划.md) / [0005](../research/0005-仓库池P0-PoC结果报告.md) 的实证结论）+ 本次源码调研（仓库池全链路复核 + DSH 0.1.5-rc.2 Slot 机制源码级确认）
> 定位：大方向与步骤清单，不含实现细节；每阶段末给出验收口径。架构总形：完全对齐仓库池的双面插件范式（宿主半 = 存储 + 端点，浏览器半 = UI），本功能是其**去校验器简化版**——无任何未实证宿主能力，**不设 P0 PoC 阶段**。

## 总体形状（先立边界）

```
浏览器半  src/client/requirements/{register, view, list, requirement-form, store, controller, fetcher, dictionary}
宿主半    src/requirements-host/{requirements-file, types, endpoint}  +  src/index.ts 追加挂载
共享协议  src/requirements-shared/protocol.ts（零依赖 wire 类型 + 手写 type guards + 路由常量）
数据      $DSH_HOME/skyaxis/requirements.yaml（独立于 repos.yaml 的自管文件，独立 store 实例）
通道      /api/skyaxis/requirements 端点族（GET list + POST save/remove；无 validate）
面板      main key === sidebar.panellist id === 'requirements'，order=110（仓库池 100 之后）
词典      skyaxis.requirements 命名空间（zh/en 双语，panel.title = 需求管理 / Requirements）
```

硬约束（全程有效，沿用仓库池口径）：`panellist id === main key`；不注册 `main.conversation`；CSS 只用 `--dsw-alias-*`（禁字面色/static 色/dark 选择器/组件库）；`dsh-client-ui-layout` 未装，`'main'` 的 SlotMap 合并声明在本插件内自行声明（同仓库池做法）。

## 与仓库池的差异（减法清单）

- **删除**：URL 语法校验器、git ls-remote 可达性探测、`subprocess` 可选 inject、validate 端点、RiskConfirmation 勾选放行流、整套 URL 合法性错误码族。
- **保留**：revision 乐观锁与冲突自愈、坏文件降级拒写 + `.bak` 提示、删除二次确认、窗口聚焦自动刷新、加载骨架屏、CSS Modules alias-only、SlotCore 契约测试范式。
- **简化**：表单流从「本地校验 → 探测 → 四分支」退化为「本地校验（标题必填）→ 直接保存」。

无 PoC 论证：仓库池 P0 已实证的四个环节——端点回环（PoC-2）、yaml 自管文件回环（PoC-3）、ui-primitives 接入（PoC-4）、组件测试样板（PoC-5）——需求管理全部原样复用，无新宿主能力需求。

| 项 | 拍板 |

## P2 数据层与 CRUD（核心功能）

- [ ] 共享协议：`src/requirements-shared/protocol.ts`（RequirementRecord 最小字段集 + revision 信封 + 三条路由常量 + 手写 type guards，浏览器 bundle 零依赖）。
- [ ] 宿主半 requirements.yaml 模块：`src/requirements-host/requirements-file.ts`（repos-file 范式整套移植：zod 读边界、原子写+备份+EPERM 退避、写互斥队列、坏文件降级拒写）+ `types.ts`（schema 与共享协议编译期对齐断言）。
- [ ] 宿主半端点族：`src/requirements-host/endpoint.ts`（GET list + POST save/remove；错误码 400/404/409/500；save 服务端强制必填+revision）+ `src/index.ts` 追加 `ctx.inject(['connection'], ...)` 挂载（无 subprocess）。
- [ ] 浏览器半 CRUD 流：`src/client/requirements/{fetcher, store, controller, list, requirement-form, view}` + 词典扩至 CRUD 全量 key（page/view/form/error/delete 前缀）；表单流=本地校验→直接保存；冲突/404 自动刷新自愈。
- [ ] 自动化门：typecheck + 单测（requirements-file 读写矩阵含并发双 save 恰一成一败、端点直构矩阵、fetcher guards、store 状态机/refresh 竞态守卫、表单组件分支）+ build 产物断言。
- [ ] **验收（实机目测）**：① 增删改查全链路持久化（重启宿主后 list 仍在，`$DSH_HOME/skyaxis/requirements.yaml` 可目视）；② 双开页写冲突 → conflict banner + 自动刷新；③ 手改坏 requirements.yaml → 插件正常加载 + 降级 banner（含 .bak 提示）+ 写被拒；④ repos.yaml 与 requirements.yaml 并存互不影响；⑤ 亮暗/语言切换、仓库池/task-graph 零回归。

## 风险登记（方向级）

| 风险 | 缓解 |
|---|---|
| panellist 第二占用者的多面板行为（宽窄两态、切换、回落） | list slot 多 entry 是官方机制（sidebar shell 快照全部注册项，order 定序）；P1 实机专项验收 |
| requirements.yaml 与 repos.yaml 同目录并存 | 独立文件 + 独立 store 实例，互不持有状态；P2 验收项 ④ |
| 0.1.5-rc.2 → 后续版本契约漂移 | 沿用 0001 风险登记口径：升级引擎版本时 diff slot 契约/静态模块表/token 清单 |
| 字段集后续扩展（状态/优先级/仓库关联） | 协议层 `version` 字段 + 向后兼容读（zod schema 演进）；本期最小集不动 |
