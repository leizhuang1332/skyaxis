## 实施记档（单工作树交付）

### 刀一 客户端两调用点

- [workspace-tab.tsx](../../src/client/requirements/workspace-tab.tsx) `openDirectory`：`openWorkspacePath({ path })`（无 action）；注释记档 reveal 的 UTF-8 百分号 URL 在 zh-CN Windows 解析不了 CJK 路径回退默认目录、plain open 与 GUI open-in-app explorer 同宿主开窗函数（指向决策 0012）。
- [repos-section.tsx](../../src/client/requirements/repos-section.tsx) `revealDir`→`openRepoDir`：同样去 action；注释记档 repo 目录居于 CJK 工作区名之下必然触发同缺陷；`onOpen` 回调同步更名调用。
- 根因与 A/B/C 实证表、GBK 旁证见决策 0012 D1（本机 2026-10-15 探针）。

### 刀二 workspace-tab.spec.tsx

- 断言 `toHaveBeenCalledWith({ path: '/old/path' })`——**无 action 键即回归锁**（多出的 `action:'reveal'` 翻红）；注释指向决策 0012。
- 用例名 'reveal button rides…'→'open button rides…'；文件头注释 reveal→open。
- repos-section.spec 无 opener 载荷断言，零改动通过。

### 刀三 记档

decisions/0012、本计划、[issue 草稿](../issues/issue-dsh-native-command-explorer-windowshide.md) 补第二节（revealNativePath 的 CJK file-URL 缺陷：症状/根因/A-B-C 复现表/上游修法=explorer 分支传裸 Win32 路径）。README 双版 1080 不变、零改动（README 未描述打开行为细节）。

## 实机验收脚本（3 步，已通过——用户 2026-10-15）

1. **工作区打开（本轮主体）**：需求详情页 → 工作区 tab → 「打开」→ Explorer 打开**工作区目录本身**（中文路径，如 `IdeaProjects\集运附件回传`），不再落桌面/文档；窗口内容 = 工作区目录（非父目录选中形态）。
2. **repos 行打开**：已克隆仓库行「打开」→ 打开 `<工作区>\repos\<目录>` 本身。
3. **与参照一致**：dsh GUI 头部 open-in-app explorer 按钮（同一工作区目录）→ 两者打开同一目录、行为一致；opener 能力不在时（`canOpenWorkspacePath` false）按钮仍不出现。

> **实机验收已通过（用户 2026-10-15）**——三步全过。**0011 打开按钮行为修复轮整体收口（客户端两调用点 + 回归锁 + 记档 + 实机验收），无挂账遗留**。「打开」语义就此落定：plain open（与宿主 open-in-app explorer 同一开窗函数，开目录本身），reveal 形态退役——其 CJK 缺陷已记入 issue 草稿 2 走上游。
