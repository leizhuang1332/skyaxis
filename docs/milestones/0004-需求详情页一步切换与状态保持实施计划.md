# 需求详情页一步切换与状态保持实施计划

> 日期：2026-09-27
> 依据：用户两项体验反馈（①切换需求需两步：先返回列表再点卡片；②详情页切走 panel 再切回，tab 重置为概览，期望"走时什么样回来什么样"）+ 本次源码级根因调研（DSH 0.1.5-rc.2 keyed main slot 渲染语义实测：dsh-client-ui-renderer `client.js` keyed 分支 `find(e => e.options.key === entryKey)` —— 同一时刻只渲染激活 entry，非激活 entry 整体从 React 树消失，无 keep-alive）
> 定位：大方向与步骤清单，不含实现细节；每阶段末给出验收口径。全部改动收敛在浏览器半 `src/client/requirements/` 内部；宿主半、共享协议、DSH 包全部零改动。

## 根因与路线决策记录（本次调研核心产出）

### 症状二根因（tab 重置）——证据链

1. 宿主切 panel 机制：sidebar 行点击 → `ctx.layout.selectPanel(id)` → 宿主 layout controller 执行 `renderSlot('main', {}, { entryKey: id })`（register.tsx 头注明示的派发契约）。
2. keyed slot 渲染语义（dsh-client-ui-renderer `client.js` keyed 分支）：按 entryKey `find` 后只渲染命中的那一个 entry——**切 panel = 旧 entry 卸载**，无 keep-alive / display:none 多 panel 共存机制（宿主 sidebar 的 panelInfo 亦只是单值 activePanelId）。
3. 因此切到"仓库池"时 `RequirementsPage` 卸载，`view.tsx` 的 `useState<string | null>(null)` tabId 随组件销毁；切回时重挂，null 回落 `detailTabs[0]`（概览）。
4. 而 `selectedId` 存于 RequirementsStore（注册闭包创建、随 apply disposer 销毁，插件常驻 → 跨 panel 存活），所以详情页本身还在——与用户观察完全吻合。
5. 同病状态：列表筛选词 `filter` 亦为组件 useState，panel 往返同样丢失（列表↔详情的页面内切换不丢——组件未卸载）。

**结论**：宿主不会为插件保活组件，但把视图状态放组件外（store）即可——store 生命周期 = 插件生命周期。这正是宿主自己的范式（会话状态在 session projection store，不在组件里），也延续 store.ts 既有设计意图（"selectedId is a page-level view state … a future main-slot entry can reuse it verbatim"）。

### 症状一路线对比（一步切换需求）

| 路线 | 评估 | 结论 |
|---|---|---|
| **A. 详情头部"需求切换器"下拉菜单** | 单步随机访问；DSH `Menu` 原语现成（owner-controlled open / portal / autoFocus 箭头导航 / selectedId 勾选 / footer 钉底 / items 区滚动），项目内 4 处同构用法（requirements 卡片菜单、PRD 菜单、repos 菜单、repos-pool 卡片菜单）；改动集中 | **选定** |
| B. master-detail 双栏（列表常驻左列） | 与"列表/详情二态"现有模型冲突；页面重排 + tab 条归属重设计；宿主主区单列范式不同构 | 弃 |
| C. 上一/下一需求按钮 | 仅顺序切换，随机访问差；需求非有序浏览场景 | 弃 |
| D. 面包屑（"需求管理 / {标题}"） | 本质仍是返回列表，两步未消解 | 弃 |

两症状协同：P1 把"换需求重置 tab"收口进 controller 的 `openDetail`，P2 切换器落选即走同一动作，两特性不打架。**实施顺序：先 P1 后 P2。**

## 已拍板项（2026-09-27 用户认可设计后落盘）

| 项 | 拍板 |
|---|---|
| 症状二修法 | 视图状态 store 化：`detailTabId` / `listFilter` 迁入 RequirementsStore，controller 动作驱动 |
| "换需求重置 tab"语义 | **保留**（host parity，避免落进新需求未绑定的工作区空态；现有测试 `view.spec:entering another requirement resets the tab selection` 继续成立） |
| "panel 往返"语义 | tab + 筛选词均保持（"走时什么样回来什么样"的一致贯彻） |
| 不保活范围 | tab 内部瞬态（workspace status/pathDraft/PRD 预览等拉取型态）、`pendingRemove` 确认框——回来重新拉取/重开，属合理边界 |
| 症状一路线 | A：详情头部切换器 Menu 下拉 |
| 切换后 tab 落点 | 概览（走 `openDetail` 既有重置语义） |
| 切换器可见性 | 需求数 ≤ 1 时隐藏（无对象可切，不留死按钮）；`state.busy` 时禁用（与列表卡片 disabled 规则对齐） |
| 切换器菜单独有态 | 菜单开合为组件局部 useState（纯瞬态，不进 store） |
| per-requirement tab 记忆 | 不做（Map\<id, tabId\> 备选留档；单一 activeTabId + 换需求重置已覆盖主场景） |
