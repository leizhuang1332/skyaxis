## 实机验收脚本（7 步，已通过——用户 2026-10-15）

1. **整理端到端**：有裁决内容的需求 → S1 [生成整理任务书] → 预览（全量素材：发现带 detail 与方案全文、已答澄清全文、知识注入、十节文档模板 + `.skyaxis/requirements/<rid>.md` 绝对路径）→ 投递 → AI 会话把融合文档写入该路径。
2. **卡片与定稿锚**：S1 基线文档卡片出现（`requirements/<前8>.md` + 全路径）→ 点击预览正文 → [定稿需求理解] → ack Modal 出「检测到需求基线文档——定稿将锚定其当前内容」→ 确认 → 查 `workbench.yaml` 的 `understandBaseline.docHash` 落账。
3. **篡改与重整理**：手改基线文档 → 卡片预览出篡改警示；[生成整理任务书] 重跑 → AI 覆盖写 → 重新定稿 → docHash 换锚。
4. **软门**：无文档需求（或删掉文件）定稿 → ack Modal「尚无需求基线文档」披露行，确认键照常可用。
5. **S2 必读行**：已定稿带锚需求 → ② 拆分任务书输入段首行「必读 .skyaxis/requirements/…（唯一需求真源）」；未定稿需求无此行。
6. **stale 第五臂**：批准拆分（带锚态）→ 重新整理 + 重新定稿 → S2 stale 成因含「需求基线文档已变更」；[确认仍有效] 重锚消失。
7. **回归**：analysis/split/dev/review 四任务书逐字不变；摘要导出照旧；0007 的四臂 stale 与定稿/撤销/变化提示行为不变；S5 导入声明零感知。

> **实机验收已通过（用户 2026-10-15）**——七步全过。**0008 需求基线文档轮整体收口（切片一至四 + 实机验收），无挂账遗留**；留下一轮候选见文末。需求理解的最终形态就此落定：融合文档（唯一需求真源）+ 定稿盖章锚定 + 下游实物交接。
