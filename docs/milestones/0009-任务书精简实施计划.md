## 实施记档（单工作树交付，切片哈希随提交补记）

### 刀一 sow.ts（纯函数面）

- `analysisInputBlock`：analysis 文档行与 consolidate loop 同形（全部 `- 必读 prds/<name>（KB）`，焦点/指针/按需分级行退役）；split 整段跳过 PRD 清单（含「列表未可得」行），基线行三态——docHash 在场 ⇒ 0008 必读行逐字不变；定稿无锚 / 未定稿 ⇒ 两条新诚实行（以需求描述为唯一需求依据）；工作区未绑定早退行 purpose 中性化。
- `splitSnapshotBlock` 瘦身：保留 标题/描述/当前阶段/定稿状态行/现有工作包；标准清单、发现处置三组、已答澄清、待裁决提议退役（真源在基线文档）；record null 降级行同步。
- split 文案对齐：工作流第 1 步「通读需求基线文档」；约束「有据」与输出报告结构的依据括注切到 `基线文档 FR/C 编号`。
- `buildSow` 三 AI 分支不拼 `revisionStamp`（函数保留，dev/review 用途不变）；`requirementBlock` split 死臂清理；`prdSections`/`prdDocumentName` 注释收窄 dev/review。

### 刀二 sow-modal（呈现面）

- 左侧 PRD 组（select + 章节勾选）仅 dev/review 渲染；consolidate 提示组（sow.prdGroupConsolidate/prdAllHint）退役。

## 实机验收脚本（待用户）

1. **分析任务书**：S1 [生成分析任务书] → modal 无左侧「PRD 重点章节」组（仅知识组）→ 编辑区为可改 textarea；输入段全部 `必读 prds/…` 行、无「重点章节」；结尾无「生成于 revision …」行。
2. **编辑与恢复**：直接改任务书文本 → [复制到剪贴板] 得到改后全文 / 投递同理；footer 出 [恢复生成内容] → 点击回生成内容、按钮消失；编辑后勾/退知识条目不覆盖所改文本，恢复后同步最新勾选。
3. **拆分·带锚**：已定稿（有基线文档）需求 → ② 拆分任务书：快照无标准/发现/澄清（标题/描述/阶段/定稿行/工作包）；输入段首行「必读 .skyaxis/requirements/…（唯一需求真源）」、无任何 prds/ 行；modal 不拉 PRD（网络面可观察）。
4. **拆分·未定稿**：未定稿需求 → 输入段「（需求理解未定稿——尚无锚定的需求基线文档…）」诚实行；pre-0008 定稿老记录（定稿无锚）→「已定稿但未锚定」行。
5. **整理任务书**：S1 [生成整理任务书] → 无左侧提示组；输入段全必读清单 + 基线文件路径段照旧；无戳尾行。
6. **回归（冻结锚）**：dev / review 任务书与 0008 逐字一致（左侧 PRD 组照旧、`生成于 revision …` 戳在场）；知识命中/上限/投递 v2 行为不变；摘要导出、S1 卡片、ack 文档态探测零感知。
