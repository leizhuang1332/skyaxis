## 实施记档（单工作树交付）

### 刀一 控制器 `src/client/requirements/open-in-app-controller.ts`

- 四常量：apps/open/icon 三路由 + `OPEN_IN_APP_CHOICE_KEY = 'dsh.open-in-app.choice'`（头注记 D1 字符串取舍与 D2 键共享耦合）；icon 前缀导出（组件 img src 用）。
- `SnapshotFace<T>`（结构化 uSES 读面）+ `OpenInAppFace`；`createOpenInAppController(fetcher = fetch)` 注入口供测试假件（dsh 同构）。
- `load()` 用 `loading ??= run()` 每生命一次并发共享；失败/坏形一律发布 `[]`（已应答的「无能力」而非悬置）。
- choice store 带 `persist: { name }` —— 与 dsh 会话头按钮同一条 localStorage 记忆。

### 刀二 组件 `open-in-app-button.tsx` + `open-in-app.module.css`

- `APP_LABEL_KEY` 34 键 const 映射 + `labelKeyOf` 查表（「只渲染能命名的 id」过滤器）。
- `AppIcon`：`/open-in-app/icon/<id>` img，onError 进模块级 `failedIcons` 后渲染方框 glyph（404 每页一次）。
- busy 250ms 延迟 / error 2s 褪去 / `inFlight` 防抖——照抄 dsh 节奏；unmount 清双定时器。
- 渲染阶梯见决策 D3：`apps === null` → null；空可命名表或空 path → `props.fallback`；否则 Menu（`align:'end'`/`dense`/`selection:'fill'`/selectedId=current）+ 分体 anchor。
- CSS：`CAgGvG_*` 规则语义重表达（28px 胶囊/main+chevron 分隔线/hover 填充/error inset ring），全 `--dsw-alias-*` token；实施时抓出一处笔误 `--dsh-` 前缀，红眼修正。

### 刀三 接线

- [workspace-tab.tsx](../../src/client/requirements/workspace-tab.tsx)：`WorkspaceTabBody`/`createWorkspaceTabSeat` props 增 `openInApp`；按钮位替换为 `OpenInAppButton` 包原 plain 按钮作 fallback（canOpen 门控、openDirectory、0011 注释全部原样保留）。

## 实机验收脚本（5 步，`dsh web` 本机 zh-CN Win11）

1. 需求详情 → 工作区 tab：分体按钮渲染，主按钮 = Explorer 图标（首次默认 = 菜单首项），无 plain「打开」。
2. chevron → 菜单列出本机已装应用（VS Code/Cursor/Windows Terminal 等），图标正常（404→通用方框）。
3. 选 VS Code → VS Code 打开工作区目录（含 CJK 路径名直开）；再开 dsh 会话头按钮 → 主按钮同显 VS Code（choice 共享验证）。
4. 主按钮单击 → 记忆应用直开；构造失败（目录已删后点击）→ 2 秒 error 红态。
5. 降级臂：devtools 拦掉 `/open-in-app/apps`（offline 刷新）→ 回退 plain「打开」按钮，行为 = 0011 现状（开 Explorer，CJK 正常）。
